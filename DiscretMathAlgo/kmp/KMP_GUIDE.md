# КМП и КМП реального времени: методичка по самостоятельной реализации

В этом документе разбираются два способа искать образец в тексте:

1. **Обычный алгоритм Кнута — Морриса — Пратта (КМП)**: префикс-функция и переходы по границам.
2. **КМП реального времени на таблице переходов**: конечный автомат, обрабатывающий каждый символ текста за гарантированное постоянное число операций.

Цель — понять алгоритмы настолько, чтобы написать их самостоятельно. Основные разделы содержат формулы, трассировки, инварианты, этапы разработки и тестовые примеры. По отдельному запросу в разделе 17 добавлен разбор варианта КМП с Z-препроцессингом и ссылка на готовый пример на C++.

> Термин «КМП реального времени» в учебных курсах может обозначать разные усовершенствования КМП. Здесь выбран конкретный вариант: заранее вычисленная таблица переходов автомата. Его гарантия реального времени относится к обработке символов **после** подготовки таблицы. Предобработка имеет собственную стоимость и не обязана выполняться за постоянное время на символ образца.

## 1. Постановка задачи и обозначения

Даны текст `T` длины `n` и образец `P` длины `m`. Нужно найти все позиции, с которых начинается вхождение `P` в `T`.

Используем индексацию с нуля:

- `T[i]` — символ текста с индексом `i`;
- `P[j]` — символ образца с индексом `j`;
- `P[0:k)` — первые `k` символов образца; правая граница не включается;
- `q` — количество уже совпавших символов образца, а не индекс последнего совпавшего символа;
- `Σ` — алфавит, `σ = |Σ|` — количество его символов.

Например, для текста `ababa` и образца `aba` ответ — позиции `0` и `2`. Вхождения перекрываются: общий символ принадлежит обоим вхождениям.

Если полное совпадение закончилось на индексе текста `i`, то его начало:

`i - m + 1`.

### 1.1. Что решить до реализации

Заранее зафиксируй контракт:

1. Нужно первое вхождение или все?
2. Нужны ли перекрывающиеся вхождения? В этой методичке — да.
3. Что считается символом: байт, кодовая точка Unicode или другой элемент последовательности?
4. Что делать с пустым образцом?
5. Нужно ли искать в потоке, разбитом на порции?

Удобная математическая договорённость: пустой образец встречается на всех `n + 1` границах текста, включая конец. Можно вместо этого запретить пустой образец, но поведение должно быть явно определено.

Все дальнейшие формулы поиска предполагают `m > 0`. Пустой образец обрабатывается отдельно, до обращения к его символам.

## 2. Почему обычный перебор повторяет работу

Наивный поиск прикладывает образец к каждой возможной позиции текста. После несовпадения он сдвигает начало на один символ и сравнивает заново.

На тексте из большого числа `a` и образце вида `aaaaab` почти каждая попытка долго совпадает и только потом завершается неудачей. Уже проверенные символы проверяются снова. В худшем случае получается `O(nm)` операций.

КМП сохраняет информацию о совпавшем фрагменте. При несовпадении он выясняет, какая его часть уже подходит в качестве начала нового совпадения.

Принципиальная идея:

> Индекс текста движется только вперёд. При неудаче меняется длина подходящего префикса образца, а не позиция чтения текста.

## 3. Префиксы, суффиксы и границы строки

**Префикс** — начало строки. **Суффикс** — её конец.

**Собственная граница** строки — её префикс, который одновременно является суффиксом, но не совпадает со всей строкой. В этой методичке под границей далее понимается именно собственная граница; пустую строку учитываем как границу длины `0`.

Для строки `abacaba`:

- префикс `a` совпадает с суффиксом `a`, длина `1`;
- префикс `aba` совпадает с суффиксом `aba`, длина `3`;
- вся строка `abacaba` длины `7` не является собственной границей.

Самая длинная граница имеет длину `3`.

Почему границы важны: если уже совпало `abacaba`, то окончание `aba` можно использовать как начало следующей попытки. Повторно читать эти три символа текста не нужно.

Префикс и суффикс могут пересекаться по позициям. Например, у `aaa` граница `aa` имеет длину `2`: начало занимает позиции `0, 1`, конец — позиции `1, 2`. Запрещена только граница, равная всей рассматриваемой строке.

## 4. Префикс-функция

### 4.1. Определение

`π[i]` — длина самой длинной собственной границы строки `P[0:i+1)`.

Читай это так: **«Возьми строку от начала до позиции `i` включительно. Найди самое длинное одинаковое начало и окончание, не используя всю эту строку целиком. Запиши их длину»**.

Например, при `i = 4` в `abacaba` рассматривается только `abaca`. Символы `b` и `a` справа от этой позиции ещё не участвуют в вычислении. Значение `π[4]` описывает `abaca`, а не весь образец и не отдельный символ `P[4]`.

Формально:

`π[i] = max { k : 0 ≤ k ≤ i и P[0:k) = P[i-k+1:i+1) }`.

Следствия:

- массив `π` имеет длину `m`;
- `π[0] = 0`;
- всегда `0 ≤ π[i] ≤ i`;
- значение — длина, а не позиция;
- `π[i]` относится ко всему префиксу, заканчивающемуся в `i`.

### 4.2. Сначала найдём границы вручную

Возьмём `P = abacaba`.

Для всей строки сравним начала и окончания каждой допустимой положительной длины:

| Длина | Начало | Окончание | Совпали? |
|---:|:---|:---|:---|
| 1 | a | a | Да |
| 2 | ab | ba | Нет |
| 3 | aba | aba | Да |
| 4 | abac | caba | Нет |
| 5 | abaca | acaba | Нет |
| 6 | abacab | bacaba | Нет |

Самая длинная граница — `aba`, её длина `3`, поэтому `π[6] = 3`. Длину `7` не проверяем: это вся строка, а нам нужна собственная граница.

Таким перебором удобно понимать определение и проверять короткие ответы. Быстрый алгоритм не сравнивает все эти фрагменты заново.

Теперь проделаем то же самое для каждого префикса:

| `i` | `P[i]` | Рассматриваемая строка | Самая длинная граница | `π[i]` |
|---:|:---:|:---|:---|---:|
| 0 | a | a | пустая | 0 |
| 1 | b | ab | пустая | 0 |
| 2 | a | aba | a | 1 |
| 3 | c | abac | пустая | 0 |
| 4 | a | abaca | a | 1 |
| 5 | b | abacab | ab | 2 |
| 6 | a | abacaba | aba | 3 |

Итого: `π = [0, 0, 1, 0, 1, 2, 3]`.

Обрати внимание на две позиции:

- Для `aba` ответ `1`, хотя первые и последние три символа совпадают: три символа составляют всю текущую строку и запрещены определением.
- Для `abac` ответ `0`: каждый непустой префикс начинается с `a`, но ни один подходящий суффикс с тем же содержимым не получается. В частности, первый и последний символы различаются, а более длинные пары также не совпадают.

### 4.3. Как получить следующее значение

Предположим, что уже вычислены значения до `i - 1`. Самая длинная граница предыдущего префикса имеет длину `π[i - 1]`. Назовём текущую длину кандидата `k`.

Новая граница может быть длиннее старой максимум на один символ. Если у новой границы удалить последний символ, останется граница предыдущего префикса. Поэтому сначала пробуем продлить самую длинную уже известную границу.

Сначала пробуем продлить именно эту границу: сравниваем новый символ `P[i]` с `P[k]`.

- Если они равны, граница продлевается на один символ: новое значение равно `k + 1`.
- Если они не равны, текущая граница не продлевается. Нужно проверить более короткую границу.
- Если кандидатов положительной длины больше нет, сравниваем с `P[0]`: совпадение даёт `1`, несовпадение — `0`.

**Почему сравнение с `P[k]`, а не с `P[k - 1]`?** Длина `k` означает, что символы с индексами `0…k - 1` уже совпали. Следующий символ имеет индекс `k`.

Например, для `abacab` уже известна граница `ab` длины `2`. При добавлении последнего `a` из `abacaba` проверяем `P[2] = a`. Совпадение превращает границу `ab` в `aba`, поэтому получаем длину `3`.

Визуально это две одинаковые части, к которым приписывается один и тот же символ:

```text
До добавления:  [ab]ac[ab]       граница ab, длина 2
После:         [aba]c[aba]      граница aba, длина 3
```

Квадратные скобки только выделяют сравниваемые фрагменты, в исходную строку они не входят.

### 4.4. Почему откат именно `k = π[k - 1]`

До нового сравнения у нас совпадали префикс образца длины `k` и суффикс уже рассмотренной строки.

Более короткая подходящая граница должна быть одновременно префиксом и суффиксом этого совпавшего фрагмента. Поэтому следующий кандидат — самая длинная граница строки `P[0:k)`, то есть `π[k - 1]`.

Это не произвольное сокращение. Так перечисляются все потенциально подходящие границы в порядке убывания длины:

`k → π[k - 1] → π[π[k - 1] - 1] → … → 0`.

Каждый положительный переход строго уменьшает длину. Отрицательных индексов в этой схеме не требуется: при `k = 0` откат заканчивается.

Раздели в голове два действия:

- `i` выбирает новый символ исходной строки и при откатах остаётся на месте;
- `k` выбирает, какую длину уже совпавшего начала мы пытаемся продолжить этим символом.

Откат не удаляет символы строки и не вычисляет предыдущие значения заново. Он использует готовый ответ для более короткого фрагмента.

Если `k = 3`, совпавшая часть — `aba`. Её самая длинная собственная граница — `a`, поэтому следующим кандидатом будет `π[2] = 1`, а не длина `2`: у `aba` начало `ab` не совпадает с окончанием `ba`.

### 4.5. Пошаговое вычисление всего массива для `abacaba`

**Позиция `0`, строка `a`.** Собственной непустой границы нет: единственный символ является всей строкой. Сразу записываем `π[0] = 0`.

**Позиция `1`, новый символ `b`, строка `ab`.** Начинаем с `k = π[0] = 0`. Продлевать непустую границу нечего, но можно начать границу длины `1`. Сравниваем `P[0] = a` с `P[1] = b`: не равны. Записываем `π[1] = 0`.

**Позиция `2`, новый символ `a`, строка `aba`.** Берём `k = π[1] = 0`. Сравниваем `P[0] = a` и `P[2] = a`: равны. Получаем `k + 1 = 1`, значит `π[2] = 1`. Найденная граница — `a`.

**Позиция `3`, новый символ `c`, строка `abac`.** Берём `k = π[2] = 1`. До добавления `c` совпадали начало и конец `a` строки `aba`.

1. Чтобы граница `a` превратилась в `ab`, новый символ должен совпасть с `P[1] = b`.
2. Пришёл `c`, поэтому продление невозможно.
3. Переходим к границе уже совпавшей строки `a`: `k = π[0] = 0`.
4. Теперь проверяем, может ли тот же `c` образовать границу длины `1`: сравниваем с `P[0] = a`.
5. Совпадения нет. Записываем `π[3] = 0`.

Здесь важно: после отката мы всё ещё обрабатываем `c` на позиции `3`.

**Позиция `4`, новый символ `a`, строка `abaca`.** Берём `k = π[3] = 0`. Символы `P[0]` и `P[4]` равны `a`. Записываем `π[4] = 1`: начало и окончание — `a`.

**Позиция `5`, новый символ `b`, строка `abacab`.** Берём `k = π[4] = 1`. Ожидаемый символ `P[1] = b` совпадает с новым `P[5] = b`. Граница `a` продлевается до `ab`. Записываем `π[5] = 2`.

**Позиция `6`, новый символ `a`, строка `abacaba`.** Берём `k = π[5] = 2`. Ожидаемый `P[2] = a` совпадает с `P[6] = a`. Граница `ab` продлевается до `aba`. Записываем `π[6] = 3`.

Сводная трассировка вычислений:

| `i` | Новый символ | Начальное `k` | Сравнения и откаты | Итог `π[i]` |
|---:|:---:|---:|:---|---:|
| 0 | a | — | начальное значение | 0 |
| 1 | b | 0 | `a ≠ b`, оставляем 0 | 0 |
| 2 | a | 0 | `a = a`, увеличиваем | 1 |
| 3 | c | 1 | `b ≠ c`, откат `1 → 0`; `a ≠ c` | 0 |
| 4 | a | 0 | `a = a`, увеличиваем | 1 |
| 5 | b | 1 | `b = b`, увеличиваем | 2 |
| 6 | a | 2 | `a = a`, увеличиваем | 3 |

В самом `abacaba` нет позиции с несколькими последовательными откатами. Чтобы увидеть такую ситуацию на тех же символах, мысленно допиши ещё один `c`: получится `abacabac`. Перед новым символом граница имеет длину `3`, но ожидаемый `P[3] = c` как раз совпадёт, и она продлится до `4`.

А если дописать `b`, получится `abacabab`: при состоянии `3` ожидается `c`, поэтому будет откат `3 → π[2] = 1`, затем `b` успешно продлит `a` до `ab`. Новое значение равно `2`.

Если дописать `a`, получится `abacabaa`: ожидаемый `c` не совпадает с `a`, затем ожидаемый `b` тоже не совпадает. Получится цепочка `3 → 1 → 0`, после чего сравнение с `P[0] = a` даст границу длины `1`. Это пример нескольких откатов на одном символе.

### 4.6. Почему построение линейное

Хотя внутри обработки позиции возможны повторные откаты, общая работа равна `O(m)`.

Длина кандидата увеличивается максимум на единицу при переходе к следующей позиции, то есть суммарно не более `m - 1` раз. Каждый откат уменьшает её хотя бы на единицу. Длина не может стать отрицательной, поэтому суммарное число уменьшений также `O(m)`.

Дополнительно на каждой позиции выполняется постоянное число проверок вне откатов. Итого время `O(m)`, память под массив `O(m)`.

Не нужно оценивать каждый внутренний цикл независимо как `O(m)` и затем перемножать границы: здесь важна суммарная оценка изменения одного и того же состояния.

## 5. Обычный КМП: поиск по префикс-функции

### 5.1. Смысл состояния

Во время поиска состояние `q` хранит длину совпавшего префикса образца. После обработки очередного символа, **до возможного сброса после полного совпадения**, это длина самого длинного префикса `P`, который является суффиксом прочитанного текста.

Например, `q = 3` для образца `abacaba` означает: прочитанный текст заканчивается на `aba`. Следующим ожидается `P[3] = c`.

Перед обработкой следующего символа обычная реализация поддерживает `0 ≤ q < m`: полное совпадение регистрируется сразу, затем состояние переводится на границу образца.

### 5.2. Как обработать очередной символ текста

Пусть текущий символ — `c`.

1. Проверяешь, может ли он продолжить совпавший префикс: сравниваешь с `P[q]`.
2. При несовпадении и положительном `q` переходишь к длине `π[q - 1]`.
3. Продолжаешь проверять **тот же самый** символ `c` на более коротких состояниях.
4. Если найдено совпадение с ожидаемым символом, увеличиваешь длину на один.
5. Если даже из состояния `0` символ не подходит, состояние остаётся `0`.
6. Если длина стала `m`, найдено вхождение, заканчивающееся на текущей позиции.

Символ текста считается обработанным после завершения всех необходимых откатов и возможного продвижения. Во время откатов к следующему символу переходить нельзя.

### 5.3. Действия после полного совпадения

При `q = m`:

- сообщи позицию `i - m + 1`;
- если ищешь все вхождения, сохрани длину `π[m - 1]` как состояние для дальнейшего поиска;
- если нужно только первое вхождение, можно закончить поиск.

Почему не всегда `0`? Окончание найденного образца может одновременно быть началом следующего.

Пример: `P = aaa`, `T = aaaaa`.

После первого совпадения сохраняется состояние `2`, поскольку `π[2] = 2`. Каждый следующий символ `a` завершает новое вхождение. Ответ: `0, 1, 2`.

Если каждый раз сбрасывать состояние в ноль, перекрывающиеся вхождения потеряются.

### 5.4. Трассировка поиска

Образец `abacaba`, текст `ababacaba`, префикс-функция `[0, 0, 1, 0, 1, 2, 3]`.

| `i` | Символ | `q` до обработки | Действия | `q` после обработки, до сброса |
|---:|:---:|---:|:---|---:|
| 0 | a | 0 | совпало с `P[0]` | 1 |
| 1 | b | 1 | совпало с `P[1]` | 2 |
| 2 | a | 2 | совпало с `P[2]` | 3 |
| 3 | b | 3 | `b ≠ c`; откат `3 → π[2] = 1`; затем `b = P[1]` | 2 |
| 4 | a | 2 | совпало с `P[2]` | 3 |
| 5 | c | 3 | совпало с `P[3]` | 4 |
| 6 | a | 4 | совпало с `P[4]` | 5 |
| 7 | b | 5 | совпало с `P[5]` | 6 |
| 8 | a | 6 | совпало с `P[6]`; найдено вхождение | 7 |

Начало вхождения: `8 - 7 + 1 = 2`. После регистрации состояние для продолжения равно `π[6] = 3`.

Заметь: на позиции `3` один и тот же `b` сначала не подошёл состоянию `3`, затем подошёл состоянию `1`. Символ не был потерян и не был прочитан заново из текста.

### 5.5. Почему поиск корректен

Достаточно понимать три утверждения.

**Совпадение продлевает правильный суффикс.** Если текст уже заканчивается на `P[0:q)` и следующий символ равен `P[q]`, текст теперь заканчивается на `P[0:q+1)`.

**Откаты не пропускают возможное продолжение.** При несовпадении более короткий подходящий префикс должен быть границей уже совпавшего фрагмента. Цепочка префикс-функции перечисляет такие границы от самой длинной к коротким.

**Полная длина означает вхождение.** Если после обработки символа длина равна `m`, последние `m` символов текста совпадают с образцом. Сохранение самой длинной собственной границы после выдачи ответа оставляет все возможности для следующего вхождения.

### 5.6. Сложность

- Предобработка образца: `O(m)`.
- Обработка всего текста: `O(n)`.
- Общее время без учёта хранения результата: `O(m + n)`.
- Вспомогательная память: `O(m)`.
- Хранение `z` позиций ответа добавляет `O(z)` памяти; выдача ответов требует `O(z)` операций.

Линейность поиска доказывается так же, как линейность префикс-функции: успешные продолжения увеличивают состояние максимум на единицу за символ, откаты уменьшают его. Их суммарное число линейно.

Однако один конкретный символ может вызвать `Θ(m)` откатов. Поэтому постоянная стоимость одного символа у обычного КМП — **амортизированная**, а не гарантированная в худшем случае.

## 6. Что означает «реальное время»

Рассмотрим образец `aaaaab`. После пяти символов `a` состояние равно `5`. Если далее приходит `c`, обычный КМП перебирает состояния:

`5 → 4 → 3 → 2 → 1 → 0`.

Для образца `a`, повторённого `m - 1` раз, с завершающим `b`, такая обработка одного `c` занимает `Θ(m)` времени.

**Реальное время в алгоритмическом смысле** здесь означает: после предобработки каждый очередной символ обрабатывается за `O(1)` операций в худшем случае, независимо от `m` и предыдущего текста.

Это сильнее общей линейности. Но это не обещание конкретного числа микросекунд: задержки операционной системы, выделение памяти, ввод-вывод и работа обработчика результата лежат вне этой оценки.

Идея ускорения: заранее вычислить, куда приведёт вся цепочка откатов для каждой пары «состояние, входной символ».

## 7. Автомат КМП

### 7.1. Состояния

Создадим состояния `0, 1, …, m`.

Состояние `q` означает: самый длинный префикс образца, являющийся суффиксом прочитанного текста, имеет длину `q`.

- `0`: непустого совпавшего префикса нет;
- `q`, где `0 < q < m`: частичное совпадение;
- `m`: прямо сейчас закончилось полное вхождение.

В этом варианте состояние `m` сохраняется до следующего символа. Поэтому у него тоже должна быть строка переходов.

### 7.2. Функция переходов

Обозначим через `δ(q, c)` состояние после символа `c`.

Точное определение:

`δ(q, c) = max { k : 0 ≤ k ≤ m и P[0:k) — суффикс строки P[0:q) + c }`.

Знак `+` означает приписывание символа к строке.

Почему достаточно знать `q`, а не весь текст? Если какой-то префикс образца может совпасть с окончанием текста после добавления `c`, то без своего последнего символа он уже совпадал с окончанием предыдущего текста. Это окончание содержится в максимальном совпавшем префиксе длины `q`. Значит, вся нужная информация есть в состоянии.

### 7.3. Формулы построения таблицы

Для начального состояния:

- `δ(0, c) = 1`, если `c = P[0]`;
- `δ(0, c) = 0` в остальных случаях.

Для `1 ≤ q < m`:

- `δ(q, c) = q + 1`, если `c = P[q]`;
- иначе `δ(q, c) = δ(π[q - 1], c)`.

Для полного состояния:

- `δ(m, c) = δ(π[m - 1], c)`.

Последняя формула нужна потому, что `P[m]` не существует. После полного совпадения возможное продолжение ищется через собственную границу всего образца.

### 7.4. Почему строки можно строить по порядку

Для положительного `q` всегда `π[q - 1] < q`.

Следовательно, когда строится строка `q`, вся строка состояния `π[q - 1]` уже готова. Для каждой ячейки достаточно одного сравнения и, при необходимости, одного обращения к ранее вычисленной таблице.

Практический порядок работы:

1. Вычислить префикс-функцию.
2. Выделить таблицу для `(m + 1) × σ` переходов.
3. Заполнить строку состояния `0`.
4. Последовательно заполнить состояния от `1` до `m - 1`.
5. Заполнить строку `m` через строку `π[m - 1]`.

**Не вычисляй каждую ячейку отдельным проходом по цепочке откатов.** Тогда одна ячейка может потребовать `O(m)`, и общая оценка `O(mσ)` уже не следует. Именно повторное использование готовых переходов делает заполнение каждой ячейки постоянным по времени.

### 7.5. Пример полной таблицы

Пусть `P = aba`, алфавит состоит из `a`, `b` и `c`. Префикс-функция: `[0, 0, 1]`.

| Состояние `q` | Совпавший префикс | На `a` | На `b` | На `c` |
|---:|:---|---:|---:|---:|
| 0 | пустой | 1 | 0 | 0 |
| 1 | a | 1 | 2 | 0 |
| 2 | ab | 3 | 0 | 0 |
| 3 | aba | 1 | 2 | 0 |

Разбор неочевидных переходов:

- `δ(1, a) = 1`: строка `aa` заканчивается на `a`, но не на `ab`.
- `δ(2, b) = 0`: у `abb` нет непустого суффикса, являющегося префиксом `aba`.
- `δ(3, b) = 2`: после `abab` конец `ab` уже является началом следующего вхождения.
- `δ(3, a) = 1`: у `abaa` подходящий максимальный суффикс — `a`.

### 7.6. Поиск по таблице

При обработке символа нужно:

1. Определить его столбец алфавита.
2. Заменить состояние значением соответствующей ячейки таблицы.
3. Если новое состояние равно `m`, зарегистрировать вхождение.

Здесь нет цикла откатов по образцу. Для каждого входного символа выполняется один переход.

Трассировка для `P = aba`, `T = ababa`:

| Индекс | Символ | Старое состояние | Новое состояние | Результат |
|---:|:---:|---:|---:|:---|
| 0 | a | 0 | 1 | — |
| 1 | b | 1 | 2 | — |
| 2 | a | 2 | 3 | вхождение с позиции 0 |
| 3 | b | 3 | 2 | — |
| 4 | a | 2 | 3 | вхождение с позиции 2 |

### 7.7. Две допустимые договорённости о полном совпадении

Есть два корректных устройства поиска:

| Вариант | После обнаружения `m` | Нужна строка `m`? |
|:---|:---|:---|
| Полный автомат этой методички | Сохранить `m`, следующий символ обработать из него | Да |
| Автомат со сбросом после ответа | Сразу заменить состояние на `π[m - 1]` | Нет |

Выбери одну договорённость и придерживайся её в описании состояния и обработке ответа. В первом варианте состояние буквально равно максимальной длине совпавшего суффикса после каждого символа. Во втором после выдачи ответа хранится длина собственной границы для будущего продолжения.

## 8. Алфавит, память и настоящая гарантия `O(1)`

### 8.1. Маленький фиксированный алфавит

Для латинских строчных букв можно выделить `26` столбцов, для всех байтов — `256`. Символ непосредственно преобразуется в номер столбца за постоянное время.

При таком представлении:

- префикс-функция: `O(m)`;
- таблица: `O(mσ)` времени и памяти;
- поиск: `O(n)` времени;
- каждый переход: `O(1)` в худшем случае;
- состояние текущего поиска поверх готовой таблицы: `O(1)` памяти.

Если `σ` — фиксированная константа, предобработку асимптотически называют линейной по `m`, но множитель может быть большим.

Например, при `m = 100 000`, `σ = 256` и четырёх байтах на состояние таблица занимает `100 001 × 256 × 4 = 102 401 024` байта, примерно `97,7 MiB`. Это без накладных расходов контейнеров, образца и префикс-функции.

### 8.2. Большой алфавит

Для Unicode таблица на все возможные значения часто невыгодна. Один из подходов — оставить столбцы только для различных символов образца.

Если символ вообще отсутствует в образце, после него состояние всегда `0`: непустой префикс образца не может заканчиваться таким символом.

Но возникает отдельная задача: как быстро определить столбец входного символа?

- Прямой массив индексов даёт гарантированное `O(1)`, если диапазон и память это допускают.
- Хеш-таблица обычно даёт ожидаемое `O(1)`, но сама по себе не доказывает гарантированное постоянное время в худшем случае.
- Сбалансированное дерево даёт `O(log σ)`.
- Бинарный поиск по отсортированным символам также даёт `O(log σ)`.

Поэтому утверждение «КМП реального времени» требует указать не только таблицу переходов, но и способ отображения символа в столбец.

Для первой учебной реализации проще выбрать небольшой явный алфавит или байты.

### 8.3. Байты и Unicode

Если искать в UTF-8 как в последовательности байтов, алгоритм будет возвращать байтовые позиции. Для точного поиска одинаковых байтовых последовательностей это корректно, но позиции не равны номерам видимых букв.

Если нужны позиции в кодовых точках, сначала следует работать с последовательностью кодовых точек. Видимый пользователю знак может состоять из нескольких кодовых точек, поэтому даже этот индекс не всегда равен номеру визуального символа.

КМП сам по себе не выполняет нормализацию Unicode и не игнорирует регистр. Эти правила относятся к подготовке последовательностей; при преобразовании длин может понадобиться отдельное отображение позиций обратно в исходный текст.

## 9. Сравнение двух вариантов

| Свойство | Обычный КМП | Автомат КМП реального времени |
|:---|:---|:---|
| Подготовка | `O(m)` | `O(m + mσ)` |
| Вспомогательная память | `O(m)` | `O(mσ)` |
| Поиск по всему тексту | `O(n)` | `O(n)` |
| Худший случай на один символ | `O(m)` | `O(1)` при прямом доступе к столбцу |
| Основной механизм | Цепочка границ при несовпадении | Готовый переход |
| Зависимость памяти от алфавита | Нет | Есть |
| Потоковая обработка | Да | Да |

Для фиксированного непустого образца число вхождений не превышает `n`, поэтому выдача всех позиций сохраняет линейную общую оценку. Однако динамическое расширение массива ответов или медленный callback могут нарушить практическую гарантию постоянной задержки на один символ. Для строгого ограничения задержки отдельно продумывают выдачу результата и выделение памяти.

Обычный КМП удобен, когда важны компактность и простой поиск по произвольной последовательности. Полная таблица полезна, когда алфавит небольшой, образец используется многократно или требуется ограничить количество операций на обработку каждого символа.

Обычный КМП также можно подготовить через Z-функцию образца: `P → Z → π → поиск КМП`. Это вариант предобработки с теми же оценками `O(m + n)` времени и `O(m)` вспомогательной памяти. Его построение, преимущества и пример на C++ разобраны в разделе 17.

## 10. Как организовать самостоятельную реализацию

### Шаг 1. Зафиксировать типы и контракт

Запиши выбранные правила: вид символов, нумерация позиций, поведение при пустом образце, все или первое вхождение, допустимый алфавит.

Определи типы для длин и индексов. При беззнаковых индексах особенно внимательно относись к `k - 1`: выражение допустимо только при `k > 0`. Формула начала вхождения применяется только после достижения полной длины.

### Шаг 2. Отдельно сделать префикс-функцию

Её единственный вход — образец, результат — массив его длины. Текст для этого этапа не нужен.

Перед написанием выпиши словами:

- что означает текущее значение кандидата;
- какой символ ожидается для продления;
- куда переходить при несовпадении;
- когда откаты прекращаются;
- какое значение записывается на текущей позиции.

Сначала проверь вручную короткие случаи из раздела тестирования. Не переходи к поиску, пока массивы не совпадают с ожидаемыми.

### Шаг 3. Сделать обычный поиск

Логически раздели подготовку образца и обработку текста. Для повторного поиска одного образца префикс-функцию не нужно строить заново.

В отладочной трассировке полезны четыре поля: индекс текста, текущий символ, цепочка состояний, найденная позиция.

Критическая проверка: после несовпадения должен продолжать обрабатываться текущий символ, а после полного совпадения должно сохраняться возможное перекрытие.

### Шаг 4. Сделать построение автомата

Используй уже проверенную префикс-функцию. Отдельно реши, как хранится таблица: плоский массив или массив строк.

Для плоского массива ячейке состояния `q` и столбца `a` соответствует смещение `q × σ + a`. Проверь, что размер таблицы и умножение помещаются в выбранный тип.

На маленьком образце `aba` выведи всю таблицу и сравни её с таблицей выше. Это позволяет отделить ошибки построения от ошибок поиска.

### Шаг 5. Сделать поиск по таблице

Во время поиска нужны текущее состояние, общий номер прочитанного символа и готовая таблица. Префикс-функция при выбранном варианте с состоянием `m` в самом поисковом переходе не требуется.

Проверь, что после каждого символа выполняется один табличный переход и проверка полного совпадения. Цепочка откатов должна остаться только в предобработке префикс-функции, а не в обработке текста.

### Шаг 6. Сравнить результаты

Оба алгоритма обязаны выдавать одинаковый упорядоченный список позиций при одинаковом контракте.

Для маленьких примеров полезен независимый эталон: вручную либо простым перебором проверить каждое возможное начало. Сравнение только двух версий КМП слабее: обе могут зависеть от одной ошибочной префикс-функции.

## 11. Потоковый поиск

Оба варианта умеют работать с текстом, который приходит порциями. Хранить весь текст не требуется.

Между порциями сохраняются:

- текущее состояние;
- общее число обработанных символов;
- подготовленные данные образца.

Пример: `P = abcab`, первая порция текста — `xxab`, вторая — `cabyy`. Совпадение начинается в позиции `2` и пересекает границу порций. Сброс состояния при получении второй порции его уничтожит.

Если после обработки очередного символа всего прочитано `r` символов, начало обнаруженного вхождения равно `r - m`. Это та же формула, что `i - m + 1`, поскольку `r = i + 1`.

Если поступают байты UTF-8, а алгоритм работает с кодовыми точками, декодер тоже должен сохранять состояние: граница порций может разрезать кодировку одного символа.

Для нового независимого текста состояние и счётчик сбрасывают, а подготовку того же образца можно использовать повторно.

## 12. Типичные ошибки и их симптомы

| Ошибка | Почему неверно | Как проявляется |
|:---|:---|:---|
| Использовать `π[q]` вместо `π[q - 1]` при откате | Для длины `q` последний индекс равен `q - 1` | Неверные переходы, иногда отсутствие уменьшения состояния |
| Уменьшать состояние только на один | Это не переход к следующей допустимой границе | Потеря линейной оценки; без проверки границ возможны ложные состояния |
| Сделать один откат вместо цепочки | Следующая граница тоже может не продолжаться | Пропущенные вхождения |
| Прочитать следующий символ сразу после несовпадения | Текущий ещё может продолжить короткий префикс | Пропуски после частичного совпадения |
| Сбрасывать в ноль после каждого ответа | Теряется подходящий суффикс | Пропуски перекрывающихся вхождений |
| Читать `P[q]` при `q = m` | Такого элемента нет | Выход за границы |
| Забыть строку `m` у полного автомата | Следующий переход после ответа не определён | Ошибка после первого вхождения |
| Оставить переход по неизвестному символу без обработки | Столбца может не существовать | Выход за границы или неверное состояние |
| Строить таблицу заново на каждой порции текста | Подготовка относится к образцу | Лишняя работа, потеря преимущества потока |
| Сбрасывать состояние на границе порций | Порции не являются границами поиска | Пропуски вхождений между порциями |

Отдельная ловушка для C++ при выборе байтового алфавита: обычный `char` может быть знаковым. Перед использованием байта как индекса нужно получить его неотрицательное значение в диапазоне `0…255`.

## 13. Набор проверочных примеров

### 13.1. Префикс-функция

|:---|:---|:---|

| `aabaaab` | `[0, 1, 0, 1, 2, 2, 3]` | откат с последующим успешным продлением |

### 13.2. Поиск

Все позиции ниже отсчитываются от нуля.

| Текст | Образец | Ожидаемые позиции | Назначение |
|:---|:---|:---|:---|
| пустой | `a` | `[]` | пустой текст |
| `ab` | `abc` | `[]` | образец длиннее текста |
| `abc` | `abc` | `[0]` | полное равенство |
| `xabcy` | `abc` | `[1]` | вхождение внутри |
| `xyz` | `abc` | `[]` | вхождений нет |
| `ababa` | `aba` | `[0, 2]` | перекрытие |
| `aaaaa` | `aaa` | `[0, 1, 2]` | много перекрытий |
| `ababacaba` | `abacaba` | `[2]` | откат внутри поиска |
| `abcabc` | `abc` | `[0, 3]` | соседние вхождения |
| `baaa` | `a` | `[1, 2, 3]` | образец длины один |
| `ab#aba` | `aba` | `[3]` | символ вне алфавита образца |

При договорённости о пустом образце как о совпадении на каждой границе:

- пустой текст и пустой образец дают `[0]`;
- текст `abc` и пустой образец дают `[0, 1, 2, 3]`.

### 13.3. Проверки свойств

Для префикс-функции:

- каждое значение находится между `0` и индексом позиции;
- указанный префикс действительно совпадает с суффиксом;
- более длинной собственной границы нет;
- `π[i] ≤ π[i - 1] + 1` при `i > 0`.

Последнее свойство полезно для диагностики, но одного его недостаточно, чтобы доказать правильность массива.

Для автомата:

- каждый переход лежит в диапазоне `0…m`;
- для `q < m` переход по `P[q]` ведёт в `q + 1`;
- строка `m` совпадает со строкой `π[m - 1]`;
- на маленьких примерах каждая ячейка соответствует определению максимального подходящего суффикса.

Для поиска:

- каждая выданная позиция допустима и действительно начинает образец;
- позиции возрастают и не повторяются;
- список совпадает с независимым перебором;
- разбиение одного текста на разные порции не меняет ответ.

### 13.4. Проверка различия по задержке

Возьми длинный образец из многих `a` с последним `b`. Подай текст из такого же количества `a`, затем `c`.

Посчитай число откатов обычного КМП на последнем символе и число переходов готового автомата. У обычного КМП будет длинная цепочка, у автомата — один переход. Этот опыт показывает отличие худшей задержки на символ, даже если оба алгоритма быстро обрабатывают текст в целом.

## 15. Рекомендуемый порядок изучения

Сначала вручную найди границы нескольких строк. Затем вычисли префикс-функцию `abacaba` и объясни каждый переход. Для нескольких откатов допиши к ней `a` и разбери последний символ в `abacabaa`. После этого проследи обычный поиск образца `abacaba` в `ababacaba` и обработку перекрытий в `aaaaa` для образца `aaa`.

Когда смысл состояния станет понятен, построй таблицу для `aba` по алфавиту `{a, b, c}`. Сравни каждый переход с тем, что сделал бы обычный КМП. Только затем переходи к самостоятельному коду: сначала префикс-функция, потом обычный поиск, затем таблица и поиск по ней.

Критерий готовности — способность без кода объяснить состояние после любого обработанного символа и обосновать каждый переход. Именно это связывает формулы, корректность и будущую реализацию.

## 16. Как КМП сделан в `DA-samples/4`

Этот раздел разбирает существующие учебные исходники. Новая реализация не добавляется.

### 16.1. Какие файлы за что отвечают

| Файл | Назначение |
|:---|:---|
| `prefix.hpp` | Линейная префикс-функция через откаты по границам |
| `prefix2.hpp` | Перебор длин границы с ограничением предыдущим значением плюс один; сравнение фрагментов посимвольное |
| `prefix3.hpp` | Прямой перебор всех допустимых длин с посимвольной проверкой |
| `kmp.hpp` | Обычный КМП, использующий именно `prefix.hpp` |
| `kmp.cpp` | Генерация случайных примеров и проверка результата |
| `check_substr.hpp` | Независимый наивный поиск для сравнения списков позиций |
| `z.hpp`, `z.cpp`, `z_substr.hpp`, `z_substr.cpp` | Отдельная тема: Z-функция и поиск через неё |

Все три заголовка `prefix*.hpp` определяют функцию с одинаковым именем `calc_prefix`. Это альтернативные реализации для изучения, а не три заголовка для одновременного подключения в один файл.

В `prefix2.hpp` ограничение длины использует свойство `π[i] ≤ π[i - 1] + 1`, но границы всё ещё проверяются перебором. Линейное время `prefix.hpp` обеспечивается именно переходами к уже известным границам, а не только этим ограничением. Простой верхний предел времени для обоих переборных вариантов — `O(m³)`; для `prefix3.hpp` он достигается, например, на одинаковых символах.

### 16.2. Соответствие обозначений

| В исходнике | В методичке | Смысл |
|:---|:---|:---|
| `src_pattern` | `P` | Исходный образец |
| `pattern` | `P + '$'` | Образец с завершающим служебным символом |
| `prefix` | `π` для расширенного образца | Префикс-функция |
| `prev_prefix` | Состояние перед обработкой символа | Длина совпавшего префикса |
| `j` | Рабочее `q` | Состояние, изменяемое при откатах и продолжении |
| `indexes` | Список ответа | Начала найденных вхождений |

`calc_prefix` в `prefix.hpp` устроена так же, как описано в разделе 4: для очередной позиции берётся предыдущая длина границы, при несовпадении она заменяется на `prefix[j - 1]`, при совпадении увеличивается на один.

### 16.3. Главное отличие: завершающий `$`

В `kmp.hpp` длина `m` запоминается **до** добавления служебного символа. Затем создаётся расширенный образец `src_pattern + '$'`, и префикс-функция вычисляется для него.

Поэтому:

- найденное вхождение по-прежнему определяется условием `j == m`;
- `pattern[m]` существует и равен `$`;
- после выдачи ответа `j` сразу не сбрасывается: его сохраняют в `prev_prefix`;
- на следующем символе текста обычный цикл несовпадений сам выполняет нужный откат.

Предполагается, что `$` — зарезервированный символ вне входного алфавита. В частности, он не должен встречаться в тексте. Тогда при состоянии `m` следующий символ обязательно отличается от `pattern[m]`, и первый откат переводит состояние в `prefix[m - 1]` — ровно туда, куда обычная версия переводит его сразу после ответа.

Это **отложенный откат после полного совпадения**. Он не меняет принцип КМП и не превращает алгоритм в вариант реального времени.

Значения префикс-функции на исходных `m` позициях не меняются от приписывания символа справа. При соблюдении ограничения на `$` дополнительное значение `prefix[m]` поиску не требуется.

### 16.4. Как сохраняется перекрытие

Возьмём образец `aba` и текст `ababa`. Расширенный образец — `aba$`.

1. После чтения `aba` состояние `j = 3 = m`, выдаётся позиция `0`.
2. В `prev_prefix` сохраняется `3`.
3. Приходит `b`. Он сравнивается с `pattern[3]`, то есть с `$`.
4. Символы различаются, выполняется откат к `prefix[2] = 1`.
5. Тот же `b` сравнивается с `pattern[1] = b`, состояние становится `2`.
6. Следующий `a` доводит состояние до `3`, выдаётся позиция `2`.

Таким образом, перекрытия учитываются, хотя явного сброса после добавления позиции в ответ нет.

### 16.5. Что учитывать в этой учебной реализации

**Ограничение на `$` не проверяется.** Если он встречается в тексте после полного совпадения, состояние может вырасти до `m + 1`, нарушая предполагаемый диапазон. Для произвольных строк, в том числе содержащих нулевые байты, дальнейшая обработка может привести к выходу за границы. Эту версию следует читать с условием о зарезервированном служебном символе. Вариант с явным откатом после ответа не требует такого ограничения алфавита.

**Пустой образец отдельно не поддержан.** Условие регистрации проверяется только внутри прохода по тексту, поэтому все `n + 1` границ по договорённости этой методички функция не выдаёт. При пустом тексте она возвращает пустой список. Это отдельный случай, который нужно определить в контракте своей будущей реализации.

**Случайная проверка имеет узкую область.** В `kmp.cpp` выполняются 100 испытаний, строки имеют длины от 3 до 100 и состоят из байтов со значениями 67–69 — букв `C`, `D`, `E`. Более длинная строка выбирается текстом. Сравнивается весь список позиций с независимым перебором, что полезно, но пустые строки, служебный символ, образец длиннее текста и целевые случаи перекрытия требуют отдельных примеров. Проверяющая функция также не рассчитана на пустой образец: выражение `i + m - 1` использует беззнаковую арифметику.

### 16.6. Где здесь КМП реального времени

В этой папке реализации КМП реального времени нет: в `kmp.hpp` на каждый символ текста может выполняться несколько итераций `while`. Нет таблицы переходов по паре «состояние, символ».

Для изучения по этим исходникам порядок такой: разобрать `prefix.hpp`, затем смысл `prev_prefix` и `j` в `kmp.hpp`, затем роль `$` после полного совпадения. После этого таблицу из раздела 7 можно понимать как заранее вычисленный результат того самого цикла откатов для каждого состояния и символа.

## 17. КМП через основную процедуру препроцессинга — Z-функцию

### 17.1. Как Z-функция участвует именно в КМП

КМП нужны сведения о границах образца для переходов при несовпадении. Получить их можно не только прямым вычислением префикс-функции, но и через Z-функцию.

В этом разделе выбран конкретный вариант:

`образец → его Z-функция → префикс-функция → обычный поиск КМП`.

Здесь Z-функция вычисляется **только для образца**. Текст не приписывается к нему. Во время поиска используется состояние совпадения и откаты по границам — как в разделе 5.

В разных курсах из Z-функции получают и другие таблицы сдвигов, включая уточнённые таблицы, учитывающие символ после границы. Здесь строится обычная `π`, поэтому формулы и гарантии дальнейшего поиска точно совпадают с уже разобранным КМП. Это не утверждение, что любая лекционная таблица препроцессинга буквально равна `π`.

### 17.2. Что хранит Z-функция

`Z[i]` — длина самого длинного совпадения между началом строки и фрагментом, начинающимся в позиции `i`.

Иначе говоря, `P[0:Z[i]) = P[i:i+Z[i])`. Символы в обоих фрагментах читаются слева направо. Переворота нет.

Договоримся, что `Z[0] = 0`: совпадение строки с самой собой нам не требуется.

Для `abacaba`:

| Позиция `i` | Символ | Строка от `i` до конца | Совпавшее начало | `Z[i]` |
|---:|:---:|:---|:---|---:|
| 0 | a | abacaba | значение по договорённости | 0 |
| 1 | b | bacaba | пустое | 0 |
| 2 | a | acaba | a | 1 |
| 3 | c | caba | пустое | 0 |
| 4 | a | aba | aba | 3 |
| 5 | b | ba | пустое | 0 |
| 6 | a | a | a | 1 |

Итого `Z = [0, 0, 1, 0, 3, 0, 1]`.

Разница с `π`: Z-функция привязана к **началу** совпадающего фрагмента, а префикс-функция — к **концу** префикса, для которого ищется граница.

### 17.3. Как вычислить Z за линейное время

Поддерживай окно `[L, R)`: фрагмент строки в этом окне совпадает с началом строки, а правая граница `R` — самая дальняя из найденных. Правая граница исключена.

При обработке позиции `i`:

1. Если `i ≥ R`, готовой информации о совпадении нет: начинай длину с нуля.
2. Если `i < R`, позиция находится внутри окна. Ей соответствует позиция `i - L` в начале строки. Можно сразу перенести длину `min(Z[i - L], R - i)`.
3. После этого сравнивай следующие символы и продлевай совпадение, пока символы равны и правая позиция находится в строке.
4. Если новый конец `i + Z[i]` дальше прежнего `R`, обнови окно: начало `i`, конец `i + Z[i]`.

Почему нельзя без ограничения копировать `Z[i - L]`: за границей `R` равенство ещё не установлено. Например, на позиции `6` строки `abacaba` из окна `[4, 7)` можно взять только один символ, даже если другая строка в аналогичной ситуации имела бы более длинное совпадение.

На `abacaba` основные окна такие: после позиции `2` известно окно `[2, 3)`, после позиции `4` — `[4, 7)`. Позиции `5` и `6` используют сведения из второго окна.

Линейность следует из того, что новые успешные сравнения за известным окном двигают его правую границу только вправо, суммарно не более `m` раз. Если скопированное значение заканчивается строго внутри окна, следующее сравнение уже обнаруживает несовпадение. Неуспешных завершающих сравнений — не более одного на позицию.

### 17.4. Как из одного Z-значения получить границы

Пусть `Z[i] = L` и `i > 0`. Тогда для каждой длины `k` от `1` до `L` выполняется:

`P[0:k) = P[i:i+k)`.

Правый фрагмент заканчивается в позиции `e = i + k - 1`. Значит, он является суффиксом префикса `P[0:e+1)`. Следовательно, длина `k` — кандидат на значение `π[e]`.

Например, `Z[4] = 3` в `abacaba` даёт сразу три кандидата:

| Длина совпадения `k` | Конечная позиция `e` | Префикс строки до `e` | Его граница |
|---:|---:|:---|:---|
| 1 | 4 | abaca | a |
| 2 | 5 | abacab | ab |
| 3 | 6 | abacaba | aba |

Для каждой конечной позиции нужно оставить максимальную возможную длину, а не просто любое найденное совпадение.

### 17.5. Линейное преобразование Z в π

Сначала все значения будущей `π` равны нулю. Затем рассматривай начала Z-совпадений `i` **по возрастанию**, начиная с `1`.

Для каждого положительного `Z[i]`:

1. Начни с самой большой длины `k = Z[i]`.
2. Определи конечную позицию `e = i + k - 1`.
3. Если `π[e]` ещё нулевая, запиши туда `k` и переходи к длине `k - 1`.
4. Если `π[e]` уже положительная, прекрати обработку этого Z-совпадения целиком.
5. Длина `0` завершает обработку без обращения по индексу `i - 1`.

**Почему первое присваивание максимально?** Для фиксированного конца `e` длина кандидата равна `e - i + 1`. Чем раньше начало `i`, тем больше длина. Мы перебираем начала слева направо, поэтому первый записанный кандидат — самый длинный.

**Почему на заполненной позиции можно остановиться?** Предыдущее совпадение началось раньше и уже покрывает эту конечную позицию. Его более короткие части покрывают также оставшиеся позиции текущего совпадения слева. Если предыдущая обработка сама остановилась, эти позиции уже покрыты ещё более ранним совпадением. Повторная обработка не улучшит ни один ответ.

**Почему время `O(m)`, хотя есть вложенный проход?** Каждое успешное присваивание заполняет ранее нулевую ячейку, и таких ячеек всего `m - 1`. Для каждого начала возможна максимум одна проверка, завершающаяся остановкой на заполненной ячейке. Суммарно работа линейная.

Если убрать остановку и каждый раз проходить по всей длине `Z[i]`, на строке из одинаковых символов преобразование станет квадратичным.

### 17.6. Преобразование для `abacaba` по шагам

Начальное состояние: `π = [0, 0, 0, 0, 0, 0, 0]`.

| Начало `i` | `Z[i]` | Действия | Массив после обработки |
|---:|---:|:---|:---|
| 1 | 0 | нет совпадения | `[0, 0, 0, 0, 0, 0, 0]` |
| 2 | 1 | `π[2] = 1` | `[0, 0, 1, 0, 0, 0, 0]` |
| 3 | 0 | нет совпадения | `[0, 0, 1, 0, 0, 0, 0]` |
| 4 | 3 | `π[6] = 3`, затем `π[5] = 2`, затем `π[4] = 1` | `[0, 0, 1, 0, 1, 2, 3]` |
| 5 | 0 | нет совпадения | `[0, 0, 1, 0, 1, 2, 3]` |
| 6 | 1 | `π[6]` уже равна `3`, останавливаемся | `[0, 0, 1, 0, 1, 2, 3]` |

В последней строке нельзя заменить `π[6]` на `1`: у всего образца есть граница `a`, но более длинная `aba` уже найдена.

### 17.7. Поиск после препроцессинга

После получения `π = [0, 0, 1, 0, 1, 2, 3]` выполняется обычный КМП из раздела 5. Поиск не зависит от того, каким способом получена корректная префикс-функция.

Для `T = ababacaba` и `P = abacaba` на позиции текста `3` будет несовпадение `b` с ожидаемым `c`, откат `3 → π[2] = 1`, а затем продолжение тем же `b`. Полное вхождение начнётся в позиции `2`.

Полные оценки:

- Z-функция образца: `O(m)` времени и памяти;
- преобразование в π: `O(m)` времени и памяти;
- поиск: `O(n)` времени;
- итого: `O(m + n)` времени и `O(m)` вспомогательной памяти, не считая ответов.

Это обычный КМП с альтернативной подготовкой. Длинная цепочка откатов на одном символе всё ещё возможна. Для реального времени можно дополнительно построить автомат из раздела 7 по полученной `π`.

### 17.8. Плюсы и ограничения

Преимущества такого варианта:

- **Одна основная процедура препроцессинга.** Уже написанную и проверенную Z-функцию можно использовать для подготовки КМП и других задач на совпадения префиксов.
- **Наглядная связь двух массивов.** Z описывает начала совпадений, а π — границы на их концах. Преобразование объясняет, как одна информация получается из другой.
- **Сохраняется линейная сложность.** Не приходится платить квадратичным временем за промежуточное представление.
- **Подготовка зависит только от образца.** Один результат можно использовать для нескольких текстов и потоков.
- **Не требуется разделитель.** В этом варианте нет склейки образца и текста, поэтому можно искать строки с любыми байтами, включая `$` и нулевой байт.
- **Можно независимо проверять подготовку.** На небольших строках результат преобразования должен совпадать с прямым вычислением π из раздела 4.

Отсутствие разделителя и возможность потокового поиска есть также у обычного КМП с явным сбросом после ответа; это не уникальное преимущество Z-препроцессинга. По сравнению с прямым построением π добавляются промежуточный массив и дополнительный проход. Асимптотика сохраняется, но автоматического выигрыша в скорости нет.

### 17.9. Реализация на C++17

Готовый учебный пример находится в [kmp_z.hpp](kmp_z.hpp). Основные функции находятся в пространстве имён `kmp_z`:

| Функция | Вход | Результат |
|:---|:---|:---|
| `z_function` | Образец | Z-функция с `Z[0] = 0` |
| `prefix_from_z` | Корректная Z-функция | Префикс-функция |
| `find_all` | Текст и образец | Все начала вхождений с нуля |

Пример вызова после подключения заголовка:

```cpp
const auto positions = kmp_z::find_all("ababacaba", "abacaba");
// positions содержит {2}.
```

Реализация работает по байтам, поддерживает перекрытия и пустой образец. Для пустого образца выдаются все границы текста. После каждого полного совпадения выполняется явный откат, поэтому служебный символ не нужен.

В Z-функции используется полуинтервал `[left, right)`. В `DA-samples/4/z.hpp` окно имеет включённую правую границу. Обе договорённости допустимы, но нельзя переносить формулы между ними без изменения проверок и выражения длины окна.

Для проверки преобразования особенно полезны `abacaba`, `abacabaa`, строка из одинаковых символов и строка без повторов. Для поиска дополнительно проверь перекрытия, пустые строки, образец длиннее текста и символ `$` в данных.

### 17.10. Реализация КМП реального времени без класса

В `kmp_z.hpp` функция `kmp_realtime(text, pattern)` самостоятельно готовит таблицу и обрабатывает весь текст. Класс и отдельный метод обработки символа не требуются. Подготовка идёт по цепочке `P → Z → π → таблица переходов`; таблица `sp′` здесь не используется.

Таблица `go` содержит строки для состояний `0…m`. Строка `0` заполнена нулями, кроме перехода по первому символу образца в состояние `1`. Каждая следующая строка копирует строку состояния `π[q - 1]`. Для `q < m` переход по ожидаемому символу `P[q]` заменяется на `q + 1`. Строка `m` остаётся копией строки границы и обеспечивает перекрытия.

После подготовки поиск выполняется одним циклом по тексту. В нём состояние обновляется единственным обращением к таблице:

```cpp
matched = go[matched][static_cast<unsigned char>(text[i])];
```

Если новое состояние равно длине образца, сохраняется начало вхождения. Цикла откатов в поиске нет.

Пример вызова:

```cpp
const auto positions = kmp_z::kmp_realtime("ababacaba", "abacaba");
// positions содержит {2}.
```

Алфавит включает все значения `unsigned char`, на обычной платформе — 256. Преобразование к `unsigned char` защищает от отрицательного индекса для байта с установленным старшим битом. Пустой образец обрабатывается отдельно: функция выдаёт все `n + 1` границ текста.

Подготовка требует `O(mσ)` времени, таблица — `O((m + 1)σ)` памяти. После подготовки один переход занимает гарантированное `O(1)`. Сохранение ответа в `vector` иногда выделяет память, поэтому ограничение задержки относится к переходу автомата.

По сравнению с обычным `find_all` преимущество — ограниченное число операций на один байт после подготовки. Цена — большая таблица: при 64-битном `size_t` одно состояние занимает примерно 2 KiB для 256 переходов. Каждый вызов функции строит таблицу заново.
