Лекция 1. Язык, компиляция, инструменты и типы

1.1. Что такое C++ и зачем он нужен+

C++ — компилируемый мультипарадигменный язык: поддерживает процедурный стиль, ООП, обобщённое и функциональное программирование. Объектно-ориентированное программирование связывает состояние (поля объекта) и поведение (методы), контролирует доступ и позволяет моделировать отношения между типами. C++ добавляет к этому управление временем жизни объектов, шаблоны, перегрузку, стандартные контейнеры и RAII.

Важные стандарты: C++11 (auto, nullptr, move, лямбды); C++14 (улучшения constexpr); C++17 (if constexpr, structured bindings, std::optional); C++20 (concepts, ranges, <=>, std::span, std::numbers, consteval). Если на контрольной разрешён C++20, не нужно ограничиваться синтаксисом C++11.

1.2. Структура программы+
#include <iostream>            // объявление std::cout

int main() {                   // точка входа
    std::cout << "Hello!\n";  // печать
    return 0;                  // успешное завершение
}

#include обрабатывается препроцессором; std:: — квалификация имени в пространстве имён; main возвращает int, а отсутствие явного return в конце main равнозначно return 0. Допустима также форма int main(int argc, char* argv[]): argc — число аргументов, argv — их C-строки.

Объявление сообщает компилятору о существовании сущности: int sum(int, int);. Определение создаёт её реализацию: int sum(int a, int b) { return a + b; }. Для переменных extern int count; обычно только объявляет, а int count = 0; определяет.

1.3. Как исходный код становится программой+

Препроцессор обрабатывает исходные файлы и заголовки, формируя единицу трансляции. Компилятор создаёт объектный файл. Компоновщик объединяет его с другими объектными файлами и библиотеками в исполняемый файл, который затем загружается и запускается.

  1. Препроцессор раскрывает #include, макросы и условную компиляцию (g++ -E main.cpp -o main.i).
  2. Компилятор анализирует синтаксис и типы и генерирует объектный файл (g++ -std=c++20 -c main.cpp -o main.o).
  3. Компоновщик связывает определения функций между объектными файлами (g++ main.o utils.o -o app).
  4. Загрузчик ОС размещает программу в памяти и запускает её.

Если написать void f(); int main(){f();} без определения f, компиляция отдельного файла может пройти, а компоновка выдаст undefined reference. Если не закрыта скобка, это ошибка компиляции. Если обращение идёт за пределы массива — программа может собраться, но при выполнении возникает undefined behavior (UB).

ODR — One Definition Rule

В каждой единице трансляции нельзя иметь два определения одного и того же определяемого объекта. Для обычной функции с внешней связью программа должна иметь одно определение; специальные правила разрешают идентичные определения inline-функций, шаблонов и типов в разных единицах трансляции.

// math.hpp
#pragma once
int add(int a, int b);             // объявление
inline int square(int x) { return x*x; } // допустимо в заголовке

// math.cpp
#include "math.hpp"
int add(int a, int b) { return a+b; } // определение

Ловушка: определение обычной не-inline функции в .hpp, включённом в два .cpp, часто приводит к multiple definition. #pragma once защищает только от повторного включения заголовка в одну единицу трансляции; оно не устраняет нарушение ODR между разными .cpp.

1.4. make, CMake, Google Test и отладка+

make использует правила вида цель: зависимости, затем команду с отступом табуляцией. При изменении зависимости пересобирает нужные цели.

app: main.o math.o
    g++ main.o math.o -o app

main.o: main.cpp math.hpp
    g++ -std=c++20 -Wall -Wextra -c main.cpp -o main.o

CMake описывает проект на более высоком уровне:

cmake_minimum_required(VERSION 3.16)
project(OOP LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(app main.cpp math.cpp)
target_compile_options(app PRIVATE -Wall -Wextra -Wpedantic)

cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/app

Debug обычно содержит -g -O0; Release оптимизирует. Для поиска ошибок полезны gdb ./build/app, команды break main, run, next, step, print x, backtrace. В Google Test тест выглядит так:

#include <gtest/gtest.h>
TEST(Math, Add) {
    EXPECT_EQ(5, add(2, 3));
    ASSERT_EQ(0, add(-1, 1));
}

EXPECT_* фиксирует неудачу и продолжает тест, ASSERT_* прерывает текущую тестовую функцию. Наличие Google Test требует отдельной настройки зависимостей/сборки.

1.6. Инициализация — крайне важная тема+

Инициализация задаёт начальное состояние при создании объекта. Присваивание меняет уже существующий объект. Сначала найдите в строке объявление нового объекта: знак = сам по себе не означает вызов оператора присваивания.

int a = 5; // создаём a: инициализация
int b{a};  // создаём b: инициализация
b = 9;     // b уже существует: присваивание

1.6.1. Формы записи: что именно они означают

Запись Название Для локального int Особенность для классов
T x; Default-initialization Значение не задано Вызывается подходящий конструктор без аргументов
T x = value; Copy-initialization Начальное значение из value Не использует explicit-конструктор для такого преобразования
T x(value); Direct-initialization Начальное значение из value Может использовать explicit-конструктор
T x{value}; Direct-list-initialization Запрет narrowing Агрегатная инициализация либо выбор конструктора
T x = {value}; Copy-list-initialization Запрет narrowing Ошибка, если выбран explicit-конструктор
int x{}; Пустая list-initialization, затем value-initialization Ноль Для произвольного T поведение зависит от типа и конструкторов

Название copy-initialization не гарантирует фактическое копирование. Например, std::string s = "hi"; конструирует строку из C-строки, а T x = T{}; при подходящих условиях C++17+ создаёт объект сразу на месте без copy/move.

1.6.2. Когда получается ноль, а когда значение не задано

int global;                 // статическое хранение: 0
int main() {
    int a;                  // автоматический int: неопределённое значение
    int b{};                // 0
    static int c;           // статическое хранение: 0
    int* p = new int;       // выделенный int: неопределённое значение
    int* q = new int{};     // 0
    // Не читаем a и *p до присваивания!
    delete p;
    delete q;
}

Для этих int чтение неопределённого значения в C++20 приводит к UB. Само объявление int a; и последующее присваивание a = 10; допустимы. Не следует объяснять это как «всегда случайное число»: определённого результата стандарт не обещает.

Правило для запоминания: локальный скаляр без инициализатора не получает автоматически ноль. Объекты со статическим хранением проходят статическую инициализацию; в примере global и c нулевые. Классы нужно анализировать отдельно: std::string name; создаёт корректную пустую строку через конструктор.

1.6.3. Фигурные скобки и narrowing

int a = 3.14;             // 3: дробная часть отбрасывается
int b(3.14);              // 3
// int c{3.14};           // ошибка компиляции
// int d = {3.14};        // тоже ошибка
unsigned char e{42};      // допустимо: константа представима
int n = 42;
// unsigned char f{n};    // ошибка: n не константное выражение,
                         // а int не весь представим в unsigned char
constexpr int k = 42;
unsigned char g{k};       // допустимо

Сужение проверяется по правилам языка, а не только по текущему значению переменной. Поэтому n и k дают разный результат. Приведение static_cast может явно разрешить преобразование, но само по себе не проверяет диапазон.

1.6.4. Почему () и {} не взаимозаменяемы

#include <vector>
std::vector<int> a(3, 7); // три элемента: 7, 7, 7
std::vector<int> b{3, 7}; // два элемента: 3, 7
std::vector<int> c(3);    // три нуля
std::vector<int> d{3};    // один элемент со значением 3

Для такого класса непустой список в {} сначала рассматривает конструкторы с std::initializer_list. Это причина различий. В a(3, 7) выбран конструктор «количество, значение», в b{3, 7} — список элементов. Скобки выбирают не стиль оформления, а семантику.

Не смешивайте список инициализации членов конструктора (: x_(x)) и тип std::initializer_list: это разные понятия.

1.6.5. Класс и explicit: какой конструктор доступен

struct Count {
    explicit Count(int) {}
};
void use(Count) {}

int main() {
    Count a(5);           // direct: допустимо
    Count b{5};           // direct-list: допустимо
    // Count c = 5;       // ошибка: неявное преобразование запрещено
    // Count d = {5};     // ошибка: выбран explicit-конструктор
    // use(5);            // ошибка
    use(Count{5});        // явно создаём Count
}

explicit защищает от непреднамеренного превращения числа в объект. Подробнее конструкторы и специальные методы изучаются в лекции 6; здесь важно различать формы инициализации.

1.6.6. Пустые скобки и most vexing parse

#include <string>
std::string a;       // объект: пустая строка
std::string b{};     // объект: пустая строка
std::string c();     // объявление функции c, возвращающей string!

T x(); в таком объявлении не создаёт объект. Чтобы создать объект без аргументов и избежать этой неоднозначности, используйте T x{};.

1.6.7. Массивы и агрегаты

int a[4]{1, 2};    // 1, 2, 0, 0
int b[4]{};        // четыре нуля

struct Point {
    int x;
    int y = 9;
};
Point p{2, 3};     // x=2, y=3
Point q{2};        // x=2, y=9: инициализатор поля
Point r{};         // x=0, y=9
Point t;           // x не задан, y=9; не читайте t.x
Point u{.x = 4};   // C++20: x=4, y=9

Point здесь агрегат: у него нет пользовательски объявленных конструкторов и других признаков, исключающих агрегатность. struct сам по себе не гарантирует, что тип является агрегатом. Для designated initializers C++20 имена полей должны следовать порядку их объявления; нельзя произвольно переставить .y перед .x.

1.6.8. auto, const и ссылки

#include <initializer_list>
const int x = 10;
auto a = x;            // int: верхний const убран
auto& b = x;           // const int&: ссылка на x
const auto& c = x;     // const int&
auto d{1};             // int
auto e = {1};          // std::initializer_list<int>
// auto f{1, 2};       // ошибка вывода типа
int n = 3;
int& ref = n;          // ref обозначает n
// int& bad = 3;       // неконстантная lvalue-ссылка не связывается с 3
const int& ok = 3;     // допустимо, время жизни временного продлено

auto — вывод типа, а не динамическая типизация. auto a = x создаёт независимую копию значения; auto& b = x связывает ссылку. Для данного x: decltype(x) — const int, decltype((x)) — const int&.

1.6.9. const и constexpr не равны

int read();
const int a = read();      // неизменяемое значение, получаемое при выполнении
constexpr int b = 5 * 5;   // инициализатор обязан быть константным выражением
// constexpr int c = read(); // ошибка: read не constexpr

const ограничивает изменение объекта. constexpr у такой переменной требует константного выражения в инициализаторе и также делает объект константным. Для функции constexpr означает возможность вычисления на этапе компиляции при подходящих аргументах и контексте, а не обязательное compile-time исполнение каждого вызова.

1.6.10. Осторожно: {} не обнуляет любой класс

struct A { int x; };             // агрегат
struct B { int x; B() {} };      // пользовательский конструктор не задаёт x
struct C { int x{}; C() {} };    // поле имеет свой инициализатор

A a{}; // x=0
B b{}; // x не задан! Тело B() не инициализирует int
C c{}; // x=0

Запоминать «{} всегда всё обнуляет» неверно. Нужно определить, агрегат ли это, какой конструктор вызывается и как инициализируются его поля. Для полей скалярных типов полезно задавать default member initializer: int x{};.

1.6.11. Инициализация полей и присваивание в теле

#include <string>
#include <utility>
class Person {
    const int id_;
    std::string name_;
public:
    Person(int id, std::string name)
        : id_(id), name_(std::move(name)) {} // поля создаются сразу
};

До входа в тело конструктора базы и поля уже инициализированы. const-поле и ссылочное поле нужно инициализировать, им нельзя «назначить начальное значение потом» обычным присваиванием. Порядок полей задаётся их объявлением в классе. Подробный порядок, включая базы, — в лекциях 6 и 8.

1.7. namespace и конфликт имён+

Лекция 2. Операторы, ввод-вывод, ветвления и циклы

2.1. Арифметика и преобразования+
int a = 17, b = 5;
// a+b = 22; a-b = 12; a*b = 85
// a/b = 3;  a%b = 2
// -17 / 5 = -3; -17 % 5 = -2
// 17 / 5.0 = 3.4

При делении двух целых результат целый, усечение идёт к нулю. % работает с целочисленными типами. Деление целого на ноль — UB. Переполнение знакового целого — UB; беззнаковое переполняется по модулю 2^N. Перед вычислением применяются integer promotions и usual arithmetic conversions. Например, int + double даёт double; при сравнении отрицательного int с unsigned можно неожиданно получить огромное положительное беззнаковое значение.

int a = -1;
unsigned b = 1;
// a < b обычно false: a преобразуется в unsigned

Важно: не пытайтесь «предсказать число» при UB. Корректный ответ на контрольной: поведение не определено, а не «скорее всего напечатает ...».

2.2. Побитовые операции+

Для a = 0b1100 (12) и b = 0b1010 (10):

Выражение Двоичный результат Десятичный результат Смысл
a & b 1000 8 Оба бита равны 1
a &#124; b 1110 14 Хотя бы один бит равен 1
a ^ b 0110 6 Биты различаются
a << 1 11000 24 Сдвиг влево
a >> 1 0110 6 Сдвиг вправо

~a инвертирует все биты типа после promotions, а не только четыре показанных бита. Для битовых масок обычно выбирают unsigned:

constexpr unsigned READ = 1u << 0;
constexpr unsigned WRITE = 1u << 1;
unsigned flags = READ | WRITE;
bool canRead = (flags & READ) != 0;
flags &= ~WRITE;  // снять флаг
flags |= WRITE;   // поставить флаг
flags ^= READ;    // переключить флаг

Сдвиг на отрицательное число бит или на число, не меньше ширины продвинутого левого операнда, — UB. Для отрицательных signed-значений и переполнения особенно осторожно применяйте сдвиги; C++20 уточнил некоторые правила сдвигов относительно старых стандартов. Для ясной побитовой арифметики используйте unsigned.

2.3. Логические операции и short-circuit+

&& — логическое И, || — логическое ИЛИ, ! — отрицание. Результат — bool. Короткое вычисление: в A && B правая часть не выполняется, если A ложно; в A || B — если A истинно.

int* p = nullptr;
if (p != nullptr && *p > 0) { /* безопасная проверка */ }

& и | не являются заменой && и ||: они побитовые и не обеспечивают short-circuit. При сравнении double обычно учитывают абсолютную/относительную погрешность:

#include <cmath>
bool near(double a, double b) {
    return std::abs(a-b) <= 1e-9 * std::max({1.0, std::abs(a), std::abs(b)});
}

Для этого примера требуется также #include <algorithm>. Порог подбирают под задачу; numeric_limits<double>::epsilon() сам по себе не является универсальным допуском.

2.4. Приоритет, ассоциативность, ++/--+
int a = 5;
int b = ++a;  // a=6, b=6: сначала изменить
int c = a++;  // c=6, a=7: сначала вернуть старое значение

Приоритет определяет группировку, но не всегда порядок вычисления. *p++ означает *(p++), а не (*p)++. a = b = 3 группируется как a = (b = 3). Не пишите выражения с несколькими конфликтующими изменениями одного объекта: i++ + ++i имеет UB из-за неупорядоченных побочных эффектов. В C++20 правила порядка вычислений уточнены, но это выражение по-прежнему некорректно.

2.5. Составные операторы и numeric_limits+

x += y семантически близок к x = x + y, но левый операнд вычисляется один раз. Аналогично -=, *=, /=, %=, &=, |=, ^=, <<=, >>=.

#include <limits>
int maxInt = std::numeric_limits<int>::max();
double eps = std::numeric_limits<double>::epsilon();
double low = std::numeric_limits<double>::lowest();
double minPosNormal = std::numeric_limits<double>::min();

Для double min() — наименьшее положительное нормализованное число, не самое отрицательное. lowest() — наименьшее конечное. NaN != NaN истинно, проверяйте std::isnan(x).

2.6. Математические функции <cmath>+

std::abs, std::sqrt, std::pow, std::ceil, std::floor, std::round, std::sin, std::cos, std::log, std::log10, std::log2. Тригонометрия принимает радианы. В C++20 число π доступно как std::numbers::pi из <numbers>:

#include <cmath>
#include <numbers>
double x = std::sin(std::numbers::pi / 2.0); // около 1

M_PI и M_E — распространённые, но не стандартные макросы C++20. std::pow(x, 2) часто проще заменить на x*x, когда нужна именно вторая степень.

2.7. Ввод и вывод+
#include <iostream>
#include <iomanip>
#include <string>
#include <limits>

int age{};
if (!(std::cin >> age)) {
    std::cin.clear(); // сбросить флаг ошибки
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}
std::string name;
std::getline(std::cin >> std::ws, name); // пропустить ведущие пробельные символы
std::cout << std::fixed << std::setprecision(2) << 3.14159 << '\n';

operator>> для строки читает до пробельного символа; getline — до разделителя (обычно \n). После cin >> age в буфере остаётся перевод строки; используйте ignore(..., '\n'), если хотите прочитать всю следующую строку, включая возможные начальные пробелы. std::ws удаляет все ведущие пробельные символы, что иногда нежелательно. std::setw(n) действует на следующее поле, std::fixed, std::hex, std::boolalpha сохраняют состояние потока до изменения. std::endl печатает перевод строки и принудительно сбрасывает буфер; обычно достаточно '\n'.

2.8. if, switch и область видимости+
if (int score = 85; score >= 90) {
    std::cout << "A";
} else if (score >= 75) {
    std::cout << "B";
} else {
    std::cout << "C";
}
// score здесь уже недоступен

В switch выполняется переход к подходящему case, затем выполнение продолжается до break, return или конца switch. [[fallthrough]]; документирует намеренный переход к следующему case.

switch (x) {
    case 1: std::cout << "one"; break;
    case 2: std::cout << "two"; [[fallthrough]];
    case 3: std::cout << "three"; break;
    default: std::cout << "other";
}

switch требует целочисленного или перечислимого управляющего типа (с учётом допустимых преобразований), не std::string.

2.9. Циклы и управление потоком+
for (int i = 0; i < 3; ++i) { std::cout << i; } // 012
int n = 0;
while (n < 3) ++n;     // проверка до тела
do { --n; } while (n > 0); // тело хотя бы один раз

break выходит из ближайшего цикла или switch, continue переходит к следующей итерации ближайшего цикла. В for после continue выполняется выражение обновления. Range-based for:

std::vector<int> v{1, 2, 3};
for (int x : v) x *= 2;   // изменяется копия
for (int& x : v) x *= 2;  // изменяются элементы: 2,4,6
2.10. Преобразования типов+

Неявные: promotion (char → int), usual arithmetic conversions, преобразование к bool. Явные: static_cast<int>(3.9) → 3 (усечение к нулю). C-style cast (T)x менее прозрачен, чем именованные C++-приведения. static_cast не выполняет произвольную проверку диапазона: преобразование вещественного числа в целое вне представимого диапазона — UB.

Контрольный вопрос: что выведет std::cout << (5 / 2 * 2.0);? Ответ: 4, потому что 5/2 вычисляется как целое 2, затем 2*2.0 → 4.0.

2.11. Разбор: значение выражения и побочный эффект+

В строке int old = x++; есть два результата: в old попадает старое значение, а x увеличивается. Не определяйте порядок вычисления только по приоритету операторов: приоритет задаёт группировку выражения.

#include <iostream>
int main() {
    int x = 3;
    int old = x++;
    int now = ++x;
    std::cout << old << ' ' << now << ' ' << x; // 3 5 5
}

У встроенных && и || правый операнд вычисляется только при необходимости: p != nullptr && *p > 0 не разыменует нулевой указатель. У перегруженных операторов && и || такой короткой схемы нет. Для контрольной безопаснее разбивать изменения одного объекта на отдельные строки и затем считать результат.

Это иллюстрация типичной ОС, не гарантия стандарта C++: стандарт задаёт длительности хранения, а не обязательные физические сегменты или направления роста. int local; обычно размещается в стеке; static int x; имеет статическую длительность хранения; new int создаёт объект с динамической длительностью хранения. Сам указатель на выделенный объект может лежать в стеке, а объект — в динамической памяти.

int global = 10;
void f() {
    int local = 20;
    int* p = new int(40);
    delete p;
}
3.2. Адрес и разыменование+
int x = 42;
int* p = &x; // p хранит адрес x
*p = 100;   // меняем объект x
// x == 100

Если p = &x, указатель p хранит адрес объекта x, а выражение *p обозначает сам x. Например, при x == 100 чтение *p даёт 100.

&x — адрес объекта; *p — доступ к объекту, на который указывает p. * в объявлении (int* p) и в выражении (*p) выполняет разные роли. nullptr — типобезопасный нулевой указатель. Разыменование nullptr — UB.

3.3. Арифметика указателей и массивы+
int a[]{10, 20, 30, 40};
int* p = a;         // указывает на a[0]
int x = *(p + 2);   // 30
int y = p[3];       // 40

Для массива int a[4]{10, 20, 30, 40} при условных адресе начала 1000 и sizeof(int) == 4:

Элемент Указатель Условный адрес Значение
a[0] p 1000 10
a[1] p + 1 1004 20
a[2] p + 2 1008 30
a[3] p + 3 1012 40

Здесь p = a; адреса приведены только для иллюстрации.

p + n сдвигается на n элементов, не на n байт. Допустимы адреса элементов одного массива и адрес «на один за концом» (a + 4), но разыменовывать последний нельзя. a[2] == *(a+2) == 2[a] (последнее синтаксически допустимо, но не рекомендуется). Разность указателей внутри массива имеет тип std::ptrdiff_t.

Тонкость: массив не является указателем. Во многих выражениях a преобразуется в указатель на первый элемент (array-to-pointer decay), но sizeof(a) измеряет весь массив, &a имеет тип int (*)[4], а a не переназначается. В параметре void f(int a[]) тип фактически корректируется до int* и размер массива теряется. В C++20 удобны std::span<int> и std::array<int, N>.

3.4. Четыре сочетания const+
int x = 1, y = 2;
int* p1 = &x;              // меняем адрес и *p1
const int* p2 = &x;        // p2 можно перенаправить; *p2 менять нельзя
int* const p3 = &x;        // p3 нельзя перенаправить; *p3 менять можно
const int* const p4 = &x;  // нельзя ни перенаправить, ни менять через p4
Объявление Изменить *p через этот указатель? Присвоить p = &y?
int* p да да
const int* p нет да
int* const p да нет
const int* const p нет нет

const int* p не делает исходный объект обязательно константным: если x не const, его можно изменить другим способом. nullptr имеет тип std::nullptr_t; предпочитайте его NULL и 0 при работе с указателями и перегрузками. const-указатель (int* const) обязательно инициализируется.

3.5. new/delete и владение памятью+
int* p = new int(42);
delete p;                   // один объект
p = nullptr;               // лишь этот указатель обнулён

int* a = new int[5]{};     // массив из пяти нулей
delete[] a;                 // строго delete[]

new int без инициализатора оставляет значение неинициализированным; new int{} инициализирует нулём. new по умолчанию при неудаче бросает std::bad_alloc. delete nullptr; безопасен. new[] нельзя парно освобождать обычным delete и наоборот: это UB. Современная альтернатива:

std::vector<int> v(5);                // массив переменной длины
std::unique_ptr<int> p = std::make_unique<int>(42);

delete p; p = nullptr; защищает только от повторного удаления через p; копии адреса в других указателях остаются висячими.

3.7. Санитайзеры+
g++ -std=c++20 -g -O1 -fno-omit-frame-pointer \
    -fsanitize=address,undefined main.cpp -o app
./app

ASan обнаруживает многие выходы за границы, use-after-free, double-free; обнаружение утечек зависит от доступности/настройки LeakSanitizer. UBSan диагностирует ряд нарушений правил языка (например, некоторые переполнения и недопустимые преобразования). Ни один санитайзер не доказывает отсутствие всех ошибок. Для разработки полезны также -Wall -Wextra -Wpedantic.

3.8. Ссылки и алиасы+
int x = 10;
int& r = x;          // r — другое имя x
r = 20;             // x == 20
const int& cr = 42; // временный int живёт столько, сколько cr
// int& wrong = 42; // ошибка компиляции

Обычная ссылка должна быть инициализирована и не может быть переназначена: r = y присваивает значение объекту x, а не привязывает ссылку к y. В корректной программе ссылка должна обозначать действующий объект; при этом висячие ссылки возможны, если объект уже уничтожен. const T& может связываться с временным объектом, иногда продлевая его время жизни; правила продления зависят от контекста, и не всякая передача временного через ссылку продлевает жизнь.

Передача параметров: f(T) — копия/перемещение, f(T&) — изменение исходного объекта, f(const T&) — чтение без копии и связывание с временными, f(T*) — допускается nullptr и явная семантика адреса.

3.9. Категории значений: lvalue, prvalue, xvalue+
Категория Входит в группы Примеры
lvalue glvalue x, *p
xvalue glvalue и rvalue std::move(x)
prvalue rvalue 42, x + 1

Это категории выражений, а не типы переменных. lvalue: x, *p, a[0], ++x для встроенного int. prvalue: 42, x+1, std::string{}, &x. xvalue: std::move(x), static_cast<T&&>(x). std::move ничего не перемещает само по себе — это приведение к rvalue-ссылке; реальное перемещение делает соответствующий конструктор/оператор. Именованная переменная типа T&& при использовании по имени является lvalue.

std::string s = "hello";
std::string t = std::move(s); // может вызвать move-конструктор
// s остаётся корректным, но его содержимое после move не определено заранее
3.10. Именованные приведения+
  • static_cast<T>(x) — проверяемые на этапе компиляции допустимые преобразования, но не гарантия отсутствия потери данных.
  • const_cast<T>(x) — изменение cv-квалификации; попытка изменить изначально const объект через снятый const — UB.
  • dynamic_cast<T>(x) — проверяемое во время выполнения приведение в полиморфной иерархии (для указателя неудача → nullptr, для ссылки — std::bad_cast).
  • reinterpret_cast<T>(x) — низкоуровневая интерпретация представления; не делает доступ к произвольному объекту безопасным.

Задание: int a[3]{1,2,3}; int* p=a+3; — создание p допустимо; *p — UB. p-a равно 3.

3.11. Разбор: объект, ссылка, указатель и время жизни+

Ссылка не владеет объектом и не продлевает жизнь произвольного объекта автоматически. Её корректность зависит от того, существует ли объект, к которому она привязана.

#include <iostream>
int main() {
    int x = 7;
    int copy = x;
    int& alias = x;
    int* ptr = &x;
    alias = 9;
    std::cout << x << ' ' << copy << ' ' << *ptr; // 9 7 9
}

copy — отдельный объект, alias — другое имя x, ptr — отдельный объект-указатель, который хранит адрес x. delete ptr здесь недопустим: x не создан через new. При разборе всегда отдельно отвечайте: кто владеет ресурсом, кто лишь обращается к нему и когда заканчивается его время жизни.

Лекция 4. Функции и разрешение перегрузки

4.1. Объявление, определение, сигнатура+
int sum(int a, int b);                 // объявление
int sum(int a, int b) { return a+b; } // определение

Имя и типы параметров участвуют в перегрузке. Нельзя перегружать только по возвращаемому типу:

int f(int);
// double f(int); // конфликт

При объявлении функции можно не указывать имена параметров, но в определении они нужны, если используются в теле.

4.2. Способы передачи аргументов+
void byValue(int x) { ++x; }   // копия
void byRef(int& x) { ++x; }    // изменяет исходный объект
void byConstRef(const std::string& s) { std::cout << s; }
void byPointer(int* p) { if (p) ++*p; }

Выбирайте по значению для маленьких скаляров, const T& для больших объектов без необходимости копирования, T& для обязательного изменяемого объекта, T* если допустимо отсутствие объекта. Для передачи владения подходят std::unique_ptr и другие явные интерфейсы владения. Нельзя возвращать ссылку/указатель на локальный объект с автоматическим хранением.

4.3. Перегрузка функций+
void print(int);
void print(double);
void print(const std::string&);
print(3);     // int
print(3.14);  // double

Компилятор: (1) находит кандидатов; (2) отбирает жизнеспособные; (3) сравнивает последовательности преобразований; (4) выбирает лучшую или сообщает неоднозначность. Упрощённая иерархия: точное совпадение > promotion > conversion > пользовательское преобразование. Но полный алгоритм сложнее, учитывает ссылки, шаблоны, квалификаторы и другие правила.

void f(long);
void f(double);
// f(1); // неоднозначно: int -> long и int -> double — conversions

Тонкость: const для параметра по значению не образует новую перегрузку: void f(int) и void f(const int) — одна сигнатура функции. Для ссылок void f(int&) и void f(const int&) — разные перегрузки.

4.4. Разрешение перегрузки: const, ссылки, временные+
void show(int&);       // изменяемое lvalue
void show(const int&); // const lvalue и rvalue
void show(int&&);      // rvalue

int x = 1;
show(x);            // int&
show(std::move(x)); // int&&
show(42);           // int&&
const int y = 2;
show(y);            // const int&

Для объекта класса перегрузки f() &, f() const&, f() && могут различать категорию и константность объекта. Результат разрешения определяется типами и категориями выражений, а не только текстом аргумента.

4.5. Аргументы по умолчанию+
void log(std::string msg, int level = 1);
log("start"); // эквивалентно log("start", 1)

Аргументы по умолчанию задаются обычно в объявлении, а не повторяются в определении. После первого параметра с умолчанием следующие параметры в той же области объявления должны иметь умолчания (с учётом ранее видимых объявлений). Умолчания не входят в тип функции и могут приводить к неоднозначности:

void f(int);
void f(int, int = 0);
// f(1); // неоднозначно
4.6. inline, constexpr, consteval+

inline позволяет иметь идентичное определение функции в нескольких единицах трансляции (например, в заголовке), но не гарантирует встраивания машинного кода. constexpr разрешает вычисление при компиляции, когда выполнены условия constant evaluation; функцию можно вызвать и во время выполнения. consteval (C++20) требует, чтобы вызов был пригоден для вычисления в константном выражении.

constexpr int sq(int x) { return x*x; }
constexpr int a = sq(4); // compile-time: 16
int n; std::cin >> n;
int b = sq(n);           // runtime допустим
consteval int cube(int x) { return x*x*x; }
constexpr int c = cube(3);
// int d = cube(n); // ошибка
4.7. RVO, NRVO, возврат по значению+
std::string make() {
    return std::string("hello"); // гарантированное устранение копии в C++17+
}
std::string make2() {
    std::string s = "hello";
    return s; // NRVO разрешён, но не гарантирован
}

RVO / guaranteed copy elision: для подходящих prvalue возвращаемый объект конструируется сразу в месте назначения; наличие копирующего/move-конструктора может быть не нужно, хотя деструктор должен быть доступен и не удалён. NRVO: возврат именованной локальной переменной, оптимизация обычно применяется, но не гарантируется. Если NRVO не выполнен, язык предусматривает правила попытки перемещения из подходящей локальной переменной.

Ошибка: return std::move(s); в make2() часто мешает NRVO. Не добавляйте std::move к каждому return автоматически.

4.8. Указатели на функции, std::function, лямбды+
int add(int a, int b) { return a+b; }
int (*pf)(int,int) = &add;
int x = pf(2,3); // 5

std::function<int(int,int)> op = add;
auto twice = [](int x) { return 2*x; };

Указатель на функцию хранит адрес обычной функции с подходящей сигнатурой. std::function (заголовок <functional>) — типостёртая оболочка для вызываемых объектов, часто с дополнительными затратами. Лямбда [&] захватывает используемые переменные по ссылке, [=] — по значению, [x] — конкретную переменную по значению. Захват по ссылке опасен, если лямбда живёт дольше захваченной локальной переменной.

4.9. Рекурсия+
int factorial(int n) {
    if (n < 0) throw std::invalid_argument("negative");
    if (n <= 1) return 1;         // базовый случай
    return n * factorial(n-1);   // рекурсивный шаг
}

У рекурсии должны быть базовый случай и движение к нему. Каждый вызов обычно добавляет кадр стека; слишком глубокая рекурсия может исчерпать стек. factorial на int быстро переполняется, даже если сама рекурсия логически правильна. Для больших n используйте другой тип/алгоритм и проверяйте диапазон.

4.10. ADL — Argument-Dependent Lookup+
namespace Geometry {
    struct Point { int x; };
    void draw(const Point&) { std::cout << "point\n"; }
}
int main() {
    Geometry::Point p{1};
    draw(p); // ADL найдёт Geometry::draw
}

Кроме обычного поиска имён, компилятор ищет подходящие свободные функции в пространствах имён, ассоциированных с типами аргументов. Поэтому operator<<, swap и свободные операторы часто определяют в пространстве имён своего типа. ADL не является универсальным поиском всех функций по всему проекту.

4.11. Разбор: как выбирать способ передачи параметра+

Передача по значению создаёт отдельный параметр. Передача по ссылке позволяет обратиться к исходному объекту; const T& запрещает его обычное изменение через эту ссылку.

#include <iostream>
#include <string>
void rename(std::string& s) { s = "new"; }
std::size_t length(const std::string& s) { return s.size(); }
int main() {
    std::string name = "old";
    rename(name);
    std::cout << name << ' ' << length(name); // new 3
}

Для небольшого int обычно подходит значение; для чтения большой строки — const std::string&; для изменения аргумента — std::string&. Само наличие const T& не делает объект владельцем ресурса и не разрешает сохранить ссылку на временный аргумент для использования после окончания его времени жизни.

Лекция 5. Классы и инкапсуляция

5.1. struct vs class+

Единственные языковые различия: для struct доступ по умолчанию public и наследование по умолчанию public; для class оба по умолчанию private. Оба могут иметь конструкторы, деструкторы, виртуальные методы, шаблоны и перегрузки.

struct Point { int x, y; }; // public
class Counter { int value_; }; // private
5.2. Поля и методы: внутри и снаружи+
class Rectangle {
    double width_ = 1.0;
    double height_ = 1.0;
public:
    double area() const;           // объявление
    void resize(double w, double h) { width_ = w; height_ = h; }
};
double Rectangle::area() const { return width_ * height_; }

Поля принадлежат конкретному объекту (кроме static). Методы получают неявный параметр объекта; определение вне класса требует ClassName::. В C++20 неявный объект традиционно доступен через this.

5.3. public, protected, private+
  • public: доступен клиентскому коду.
  • protected: доступен самому классу, друзьям и определённым образом производным классам.
  • private: доступен методам и друзьям своего класса, но не напрямую наследникам.

Инкапсуляция — не просто «сделать всё private», а защитить инварианты: например, ширина прямоугольника не должна становиться отрицательной.

class Account {
    int balance_ = 0;
public:
    explicit Account(int initial) : balance_(initial) {
        if (initial < 0) throw std::invalid_argument("negative");
    }
    int balance() const { return balance_; }
    void deposit(int amount) {
        if (amount <= 0) throw std::invalid_argument("amount");
        balance_ += amount; // в реальном коде ещё проверяют переполнение
    }
};
5.4. this и fluent interface+

this — указатель на текущий объект. В обычном методе класса T тип this — T* const в смысле неизменяемого значения указателя; в const-методе он указывает на const T. Нельзя присвоить this другой адрес.

class Builder {
    int x_{};
public:
    Builder& setX(int x) {
        this->x_ = x;
        return *this; // цепочка вызовов
    }
};
Builder b;
b.setX(1).setX(2);

this->x_ нужен, когда имя параметра перекрывает имя поля, а в некоторых шаблонных случаях — для поиска имён зависимых базовых классов.

5.5. const-методы и mutable+
class Sensor {
    int value_ = 10;
    mutable int reads_ = 0;
public:
    int get() const { ++reads_; return value_; }
};

int get() const не позволяет менять обычные нестатические поля через этот объект. mutable разрешает менять конкретное поле даже в const-методе, например счётчик чтений или кеш. Это не делает операцию потокобезопасной: при многопоточном доступе потребуется синхронизация. Перегрузка по const:

class Box {
    int x_{};
public:
    int& get() { return x_; }
    const int& get() const { return x_; }
};
5.6. Статические поля и методы+
class Counter {
    inline static int count_ = 0; // C++17+, определение в классе
public:
    Counter() { ++count_; }
    static int count() { return count_; }
};

static-поле общее для всех объектов класса; static-метод не имеет this и не может непосредственно обращаться к нестатическим полям без объекта. inline static удобен для определения поля в заголовке. Счётчик живых объектов должен учитывать также копирование и уничтожение, иначе он будет неверным.

5.7. friend: функции и классы+
class Secret {
    int value_ = 7;
    friend int reveal(const Secret& s);
};
int reveal(const Secret& s) { return s.value_; }

friend даёт выбранной функции или классу доступ к закрытым членам, но не делает её методом. Дружба не транзитивна, не наследуется и не обязана быть взаимной. Используйте её для тесно связанных операций, например свободного operator<<, не для обхода архитектуры.

5.8. Вложенные классы и enum class+
class Graph {
public:
    struct Node { int id; };
    enum class Color { Red, Green, Blue };
};
Graph::Node n{1};
Graph::Color c = Graph::Color::Red;

Вложенный тип имеет собственное имя внутри области видимости класса. enum class — строго типизированное перечисление, его элементы квалифицируются (Color::Red), не превращаются неявно в int; при необходимости static_cast<int>(c).

5.9. sizeof, alignment, padding+
struct Example {
    char a;
    int b;
    char c;
};

При типичных sizeof(int) == 4, alignof(int) == 4 и однобайтовом char раскладка может быть такой:

Часть объекта Размер в байтах
a 1
Padding перед b 3
b 4
c 1
Padding в конце 3

Итого часто 12 байт; стандарт не гарантирует именно такую раскладку.

alignof(T) — требуемое выравнивание типа. Компилятор может добавлять промежуточные и хвостовые байты padding. Порядок объявления полей влияет на размер; перестановка полей иногда уменьшает padding. sizeof(empty class) не равен нулю (обычно 1), чтобы разные полные объекты могли иметь различимые адреса. В C++20 есть [[no_unique_address]], позволяющий оптимизировать размещение некоторых полей.

5.10. Инкапсуляция и PIMPL+

PIMPL (Pointer to IMPLementation) скрывает детали реализации за указателем на неполный тип, уменьшает зависимости заголовков и может стабилизировать ABI:

// widget.hpp
#include <memory>
class Widget {
    struct Impl;
    std::unique_ptr<Impl> impl_;
public:
    Widget();
    ~Widget();                 // определяем в .cpp после Impl
    Widget(Widget&&) noexcept;
    Widget& operator=(Widget&&) noexcept;
};

В .cpp определяют Widget::Impl, конструктор, деструктор и move-операции. Если оставить деструктор unique_ptr<Impl> неудачно определённым inline там, где Impl неполный, возникнут проблемы с требованием полноты типа при уничтожении. Компромисс: PIMPL добавляет динамическую аллокацию и косвенный доступ.

5.11. Разбор: инвариант важнее набора get/set+

Инвариант — условие, которое должен сохранять объект в предусмотренных контрактом состояниях. Например, прямоугольник не должен иметь неположительные размеры. Закрытые поля сами по себе недостаточны: публичные методы тоже обязаны поддерживать условие.

#include <stdexcept>
class Rectangle {
    double width_;
    double height_;
public:
    Rectangle(double w, double h) : width_(w), height_(h) {
        if (!(w > 0) || !(h > 0)) throw std::invalid_argument("size");
    }
    double area() const { return width_ * height_; }
    void resize(double w, double h) {
        if (!(w > 0) || !(h > 0)) throw std::invalid_argument("size");
        width_ = w;
        height_ = h;
    }
};

Проверка перед присваиванием сохраняет прежнее состояние при неверных размерах. Запись !(w > 0) также отклоняет NaN. Если нужен контракт только для конечных размеров, дополнительно проверяют std::isfinite из <cmath>.

Лекция 6. Конструкторы, деструкторы, RAII и copy/move

6.1. Какие бывают конструкторы+
class Value {
    int x_{};
public:
    Value() = default;                // конструктор по умолчанию
    explicit Value(int x) : x_(x) {} // преобразующий конструктор
    Value(const Value&) = default;   // копирующий
    Value(Value&&) = default;        // перемещающий
};

Конструктор создаёт объект и не имеет возвращаемого типа. Default constructor можно вызвать без аргументов. Copy constructor обычно принимает const T&, move constructor — T&&. Компилятор может автоматически объявлять/определять специальные методы, но это зависит от пользовательских объявлений других специальных методов.

6.2. Список инициализации членов (MIL) и порядок+
struct Example {
    int a;
    int b;
    Example() : b(2), a(b) {} // ОПАСНО: a инициализируется раньше b
};

Фактический порядок: виртуальные базы (в наиболее производном классе) → непосредственные базы по порядку объявления → поля по порядку объявления в классе → тело конструктора. Порядок элементов в : b(...), a(...) не управляет порядком. В примере чтение b до инициализации недопустимо; пишите : a(1), b(a+1) и располагайте поля осмысленно. Для const-полей и ссылок список инициализации обычно обязателен.

При исключении из конструктора уничтожаются уже полностью созданные подобъекты. Деструктор самого недостроенного объекта не вызывается.

6.3. Делегирующие конструкторы+
class Point {
    int x_, y_;
public:
    Point() : Point(0, 0) {} // делегирование
    Point(int x, int y) : x_(x), y_(y) {}
};

Делегирующий конструктор вызывает другой конструктор того же класса. Если список инициализации делегирует, в нём не должно быть дополнительных инициализаторов полей. Циклическое делегирование недопустимо.

6.4. explicit и неявные преобразования+
class Distance {
public:
    explicit Distance(int meters) {}
};
Distance a(5);  // OK
Distance b{5};  // OK
// Distance c = 5; // ошибка: explicit запрещает неявную конверсию

explicit предотвращает неожиданное преобразование int → Distance. В C++20 есть условный explicit(condition). Для конструкторов с одним параметром (или несколькими с умолчаниями) explicit часто хорошая практика; он также применим к операторам преобразования типа.

6.5. =default, =delete и генерация специальных методов+

= default просит компилятор сгенерировать специальную функцию по правилам языка; = delete запрещает её использование.

class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};

Ключевая тонкость: пользовательски объявленный деструктор, copy constructor или copy assignment препятствует неявному объявлению move constructor/move assignment. Наличие пользовательского move может сделать неявные copy-операции удалёнными. =default не означает, что операция обязательно доступна: она может быть определена как удалённая из-за полей/баз. Rule of Zero рекомендует не писать эти методы, если поля уже правильно управляют ресурсами.

6.6. Деструктор и обратный порядок уничтожения+
struct A { ~A() { std::cout << "A "; } };
struct B { ~B() { std::cout << "B "; } };
struct C {
    A a;
    B b;
    ~C() { std::cout << "C "; }
};
// При уничтожении C: сначала тело ~C -> "C ", затем b -> "B ", затем a -> "A "

Деструктор ~T() вызывается при окончании времени жизни объекта; его тело выполняется до уничтожения полей и баз. Для локальных объектов в одном блоке уничтожение обычно идёт в порядке, обратном успешному конструированию. При исключении из конструктора деструктор самого недостроенного объекта не вызывается, но уже построенные базы и поля уничтожаются.

6.7. RAII — Resource Acquisition Is Initialization+

Идея: ресурс захватывается при создании объекта, освобождается в его деструкторе. Работает и при обычном return, и при раскрутке стека из-за исключения.

#include <fstream>
void write() {
    std::ofstream out("log.txt");
    out << "hello\n";
} // out закрывает файл автоматически

std::vector, std::string, std::unique_ptr, std::lock_guard, std::fstream — примеры RAII. Владение должно быть однозначным. Сильный принцип: если ресурс можно представить RAII-объектом, избегайте голого new/delete в прикладном коде.

6.8. Время жизни и временные объекты+
std::string makeName() { return "Ada"; }
const std::string& s = makeName(); // временный живёт до конца жизни s

Но:

const std::string& bad() {
    return std::string("temp"); // возвращается висячая ссылка
}

Нельзя считать, что продление времени жизни «передаётся» через возвращаемую ссылку. Временные объекты обычно уничтожаются в конце полного выражения, если специальное правило не продлевает их жизнь. Для параметра-ссылки, связанного с временным в вызове функции, временный обычно живёт до конца полного выражения с вызовом, а не до конца жизни параметра.

6.9. Copy vs move и владение динамической памятью+

При глубоком копировании b получает собственную копию ресурса a. При перемещении ресурс может перейти от a к b; состояние источника определяется контрактом класса. Перемещение само по себе не означает, что источник обязательно становится пустым.

Если класс владеет int*, неявное почленное копирование указателя создаёт два владельца одного блока, что приводит к double delete. Правильное копирование создаёт новый ресурс, перемещение передаёт владение и оставляет источник в допустимом состоянии.

#include <algorithm>
#include <cstddef>
#include <utility>
class Buffer {
    std::size_t size_ = 0;
    int* data_ = nullptr;
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)
        : size_(other.size_), data_(new int[other.size_]) {
        if (size_ != 0) std::copy(other.data_, other.data_ + size_, data_);
    }
    Buffer(Buffer&& other) noexcept
        : size_(std::exchange(other.size_, 0)),
          data_(std::exchange(other.data_, nullptr)) {}

    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            Buffer tmp(other);   // сначала безопасно скопировать
            swap(tmp);           // затем обменяться ресурсами
        }
        return *this;
    }
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            size_ = std::exchange(other.size_, 0);
            data_ = std::exchange(other.data_, nullptr);
        }
        return *this;
    }
    void swap(Buffer& other) noexcept {
        using std::swap;
        swap(size_, other.size_);
        swap(data_, other.data_);
    }
};

Тонкость: проверка size_ != 0 в копирующем конструкторе важна для перемещённого источника, у которого data_ == nullptr: не нужно формировать диапазон из нулевого указателя. Уточнение для C++20: прибавление нуля к нулевому указателю допустимо и даёт нулевой указатель; ненулевое смещение недопустимо.

В реальном проекте лучше std::vector<int> data_ и Rule of Zero: компилятор автоматически обеспечивает корректные копирование, перемещение и уничтожение.

Указатель сам по себе не выражает владение. Глубокое копирование — решение автора класса.

6.10. Правило трёх, пяти и нуля+
  • Rule of Three: если нужен пользовательский деструктор, часто нужны copy constructor и copy assignment.
  • Rule of Five: при ручном владении дополнительно рассмотрите move constructor и move assignment.
  • Rule of Zero: если ресурсы хранятся в RAII-полях, специальные функции лучше не объявлять вовсе.

Ловушка: std::move(x) не гарантирует вызов move-конструктора: если подходящего move нет, может быть вызван copy-конструктор, принимающий const T&. noexcept для move важен: некоторые контейнеры предпочитают копирование перемещению, которое может бросить исключение, чтобы сохранить гарантии безопасности.

6.11. Практика: инициализация, присваивание и move из const+
#include <iostream>
#include <utility>
struct Item {
    Item() = default;
    Item(const Item&) { std::cout << "copy\n"; }
    Item(Item&&) noexcept { std::cout << "move\n"; }
    Item& operator=(const Item&) {
        std::cout << "copy assignment\n";
        return *this;
    }
};
int main() {
    Item a;
    Item b = a;                 // copy: новый объект, не operator=
    b = a;                      // copy assignment: объект уже существует
    Item c = std::move(a);      // move
    const Item d;
    Item e = std::move(d);      // copy: const Item&& не подходит к Item&&
}

Вывод: copy, copy assignment, move, copy — по одной строке. std::move сохраняет const. Пользовательское объявление деструктора (даже = default) подавляет неявное объявление move-операций; копирование при этом иногда позволяет выражению с rvalue успешно компилироваться.

Лекция 7. Перегрузка операторов

7.1. Основные правила+

Перегруженный оператор — функция с особым синтаксисом вызова. Хотя бы один операнд перегружаемого оператора должен иметь классный или перечислимый тип; нельзя изменить работу int + int, создать новый оператор или поменять приоритет/число операндов. Нельзя перегрузить ::, ., .*, ?: и sizeof.

Метод T::operator+(...) имеет неявный левый операнд *this; свободная функция operator+(T, U) принимает оба операнда явно. Для симметричных бинарных операций свободная функция часто удобнее, потому что допускает преобразования обоих операндов.

7.2. Каноническая арифметика: += и ++
struct Vec2 {
    int x{}, y{};
    Vec2& operator+=(const Vec2& rhs) {
        x += rhs.x; y += rhs.y;
        return *this;
    }
    friend Vec2 operator+(Vec2 lhs, const Vec2& rhs) {
        lhs += rhs;
        return lhs;
    }
};

a += b меняет a и возвращает ссылку на него. a + b не меняет аргументы и возвращает новый объект по значению. Реализация + через += избегает дублирования логики. Для -, *, / действуют аналогичные соображения, но математическая семантика должна соответствовать типу.

7.3. Префиксный и постфиксный ++/--+
class Counter {
    int n_{};
public:
    Counter& operator++() { ++n_; return *this; } // ++x
    Counter operator++(int) {                     // x++
        Counter old = *this;
        ++*this;
        return old;
    }
};

Параметр int в постфиксном операторе — фиктивный маркер для различения сигнатур. Префиксный обычно возвращает T& на изменённый объект, постфиксный — T со старым значением. Аналогично --.

7.4. Сравнение и <=> в C++20+
#include <compare>
struct Point {
    int x{}, y{};
    auto operator<=>(const Point&) const = default;
};

Компилятор генерирует лексикографическое трёхстороннее сравнение членов в порядке объявления; из него могут быть переписаны <, <=, >, >=, а == может быть неявно объявлен для подходящего defaulted <=>. Если написать собственный, не defaulted <=>, == автоматически из него не появляется.

Категория Когда подходит Особенность
std::strong_ordering целые, строгая эквивалентность equal означает эквивалентность с возможностью подстановки
std::weak_ordering эквивалентные, но различимые значения equivalent не обязательно идентичность
std::partial_ordering например, double с NaN возможен unordered

auto operator<=>(...) const = default может оказаться удалённым, если члены не поддерживают нужные сравнения. Сравнение double может дать unordered при NaN.

7.5. Ввод/вывод как свободные функции+
class Complex {
    double re_{}, im_{};
public:
    Complex(double re, double im) : re_(re), im_(im) {}
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        return os << c.re_ << ' ' << c.im_;
    }
    friend std::istream& operator>>(std::istream& is, Complex& c) {
        return is >> c.re_ >> c.im_;
    }
};

Левый операнд std::cout << obj — std::ostream, поэтому для обычного синтаксиса перегрузка должна быть свободной функцией (её можно объявить friend). Возвращайте ссылку на поток, чтобы работали цепочки cout << a << b. Ввод принимает изменяемый объект. Для сложного формата сначала считывайте во временные переменные, затем обновляйте объект только при успешном разборе.

7.6. operator[]: const и non-const+
class Array2 {
    int a_[2]{1,2};
public:
    int& operator[](std::size_t i) { return a_[i]; }
    const int& operator[](std::size_t i) const { return a_[i]; }
};

Неконстантный operator[] возвращает T&, чтобы работало a[0] = 5. Константный возвращает const T& и запрещает изменение через константный объект. В отличие от std::vector::at, operator[] часто не проверяет границы. Можно добавить проверку и бросать std::out_of_range.

7.7. operator() — функторы+
struct Adder {
    int offset;
    int operator()(int x) const { return x + offset; }
};
Adder add5{5};
int result = add5(10); // 15

Функтор — объект с оператором вызова. В отличие от простой функции он хранит состояние. Лямбда компилируется в объект особого безымянного типа с operator().

7.8. operator-> и proxy-объекты+
struct Item { int value = 7; };
struct Handle {
    Item* p;
    Item* operator->() const { return p; }
};
Item item;
Handle h{&item};
int x = h->value; // 7

Если operator-> возвращает указатель, выполняется доступ к члену. Если возвращает объект класса с собственным operator->, механизм применяется рекурсивно, пока не будет получен указатель. На этом основаны умные указатели и некоторые proxy-типы. operator-> должен быть методом класса.

7.9. Операторы преобразования+
class Flag {
    bool value_;
public:
    explicit Flag(bool v) : value_(v) {}
    explicit operator bool() const { return value_; }
};
Flag f{true};
if (f) { /* contextual conversion to bool */ }
// bool b = f; // ошибка: explicit
bool b = static_cast<bool>(f); // OK

Оператор преобразования записывается operator T() const без возвращаемого типа перед operator. explicit operator bool допускается в контекстах логической проверки (if, while, !), но запрещает многие неявные конверсии.

7.10. Пользовательские литералы и канонические формы+
struct Meters { long double value; };
constexpr Meters operator""_m(long double x) { return {x}; }
Meters distance = 2.5_m;

Пользовательский суффикс обычно должен начинаться с _, а объявление operator""_m располагают в подходящем пространстве имён. Литерал 2.5_m вызывает соответствующую функцию. Перегружайте операторы только когда семантика очевидна: например, + для векторов, [] для индексируемого контейнера, << для вывода. Не делайте operator+ удаляющим файл или operator== изменяющим объект.

7.11. Практика: класс с инвариантом, композицией и операторами+
#include <cassert>
#include <iostream>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>
class Student {
    std::string name_;
    std::vector<int> grades_;   // композиция; vector владеет памятью
public:
    explicit Student(std::string name) : name_(std::move(name)) {
        if (name_.empty()) throw std::invalid_argument("empty name");
    }
    Student& operator+=(int grade) {
        if (grade < 2 || grade > 5) throw std::out_of_range("grade");
        grades_.push_back(grade);
        return *this;
    }
    double average() const {
        if (grades_.empty()) return 0.0;
        double sum = 0;
        for (int grade : grades_) sum += grade;
        return sum / grades_.size();
    }
    friend std::ostream& operator<<(std::ostream& out, const Student& s) {
        return out << s.name_ << ": " << s.average();
    }
};
int main() {
    Student a{"Anna"};
    (a += 5) += 3;
    Student b = a;             // независимая копия vector и string
    b += 5;
    assert(a.average() == 4.0);
    std::cout << a << '\n';    // Anna: 4
    try { a += 1; }
    catch (const std::out_of_range&) { std::cout << "invalid grade\n"; }
    assert(a.average() == 4.0); // неверная оценка не изменила объект
}

Здесь действует Rule of Zero. Закрытые поля защищают инвариант: имя непустое, каждая оценка от 2 до 5. Возвращение Student& позволяет цепочки операций, average() const доступен для константного объекта, friend даёт потоковой функции доступ к полям. После перемещения стандартные поля остаются допустимыми, но имя источника может стать пустым: если нужен такой же инвариант и для перемещённого объекта, контракт класса и move-операции надо продумать отдельно.

Лекция 8. Наследование

8.1. Наследование = отношение is-a+
class Animal {
protected:
    std::string name_;
public:
    explicit Animal(std::string n) : name_(std::move(n)) {}
    void info() const { std::cout << name_; }
};
class Dog : public Animal {
public:
    Dog(std::string n) : Animal(std::move(n)) {}
    void bark() const { std::cout << "woof"; }
};

Dog — разновидность Animal, поэтому при public-наследовании Dog& может использоваться как Animal&. Это подстановочность: производный тип должен выполнять контракт базового. Если машина имеет двигатель, правильнее class Car { Engine engine_; };, а не Car : Engine.

Класс Animal содержит name_ и метод info() const. Класс Dog публично наследует Animal и добавляет bark() const: собака является разновидностью животного.

8.2. Модификаторы наследования+
Доступ члена в Base public Base protected Base private Base
public public protected private
protected protected protected private
private напрямую недоступен напрямую недоступен напрямую недоступен

Важно: private-члены базы существуют внутри базового подобъекта наследника, но недоступны напрямую из кода наследника. При class Derived : Base наследование по умолчанию private; при struct Derived : Base — public.

8.3. Порядок конструирования и разрушения+
struct Base { Base(){std::cout<<"B ";} ~Base(){std::cout<<"~B ";} };
struct Member { Member(){std::cout<<"M ";} ~Member(){std::cout<<"~M ";} };
struct Derived : Base {
    Member m;
    Derived(){std::cout<<"D ";}
    ~Derived(){std::cout<<"~D ";}
};
// Для { Derived d; }:
// B M D ~D ~M ~B

База полностью конструируется до членов и тела конструктора наследника. При разрушении сначала выполняется тело деструктора наследника, затем уничтожаются его поля, затем базы. Порядок членов — по объявлению, порядок прямых баз — по списку наследования.

8.4. Наследование конструкторов+
struct Base {
    explicit Base(int) {}
    Base(int, double) {}
};
struct Derived : Base {
    using Base::Base; // наследовать доступные конструкторы
    int extra = 5;
};
Derived d(1); // Base(int), extra == 5

using Base::Base делает конструкторы базы доступными для конструирования производного класса, но не наследует copy/move-конструкторы как обычные конструкторы и не заменяет инициализацию полей наследника. Если полю не задан default member initializer, оно может остаться неинициализированным.

8.5. Сокрытие имён (name hiding)+
struct Base {
    void f(int) { std::cout << "int"; }
    void f(double) { std::cout << "double"; }
};
struct Derived : Base {
    void f(int) { std::cout << "derived int"; }
};
Derived d;
d.f(3.14);       // "derived int": Base::f(double) скрыт!
d.Base::f(3.14); // "double"

Любое объявление f в наследнике может скрыть набор одноимённых перегрузок базы. Чтобы добавить перегрузку и сохранить базовые, используйте using Base::f; внутри класса. Сокрытие имени — не то же самое, что переопределение виртуальной функции.

8.6. Срезка объектов (object slicing)+
struct Base { int x = 1; virtual ~Base() = default; };
struct Derived : Base { int y = 2; };
Derived d;
Base b = d;      // копируется только Base-подобъект
Base& r = d;     // срезки нет
Base* p = &d;    // срезки нет

Объект Derived d содержит базовый подобъект Base и собственные поля Derived. При Base b = d создаётся отдельный объект Base: копируется базовая часть, а поля производной части в b отсутствуют.

Срезка возникает при копировании производного объекта по значению в базовый тип, в том числе при передаче void f(Base) и хранении std::vector<Base>. Виртуальность методов не отменяет срезку: после копирования b — самостоятельный объект Base. Чтобы сохранить полиморфное поведение, передавайте Base&, Base* или храните std::unique_ptr<Base> (при корректном виртуальном деструкторе).

8.7. Приватное наследование vs композиция+

class Stack : private std::vector<int> означает «реализован через» с использованием базового подобъекта, но не публичное is-a. class Stack { std::vector<int> data_; } выражает has-a. Композиция обычно предпочтительна: меньше связанность, проще менять реализацию и управлять инвариантами. Приватное наследование может иметь смысл для доступа к protected, специальных возможностей переопределения или оптимизации пустого базового класса, но не является универсальной заменой композиции.

8.8. final и принцип подстановки+
struct Base {
    virtual ~Base() = default;
    virtual void run() final {}
    virtual void save() {}
};
struct Derived final : Base {
    void save() override {}
    // void run() override {} // ошибка: final
};
// struct More : Derived {}; // ошибка: класс final

final на классе запрещает дальнейшее наследование; на виртуальном методе — дальнейшее переопределение. override проверяет, что метод действительно переопределяет виртуальный метод базы. Принцип Лисков (LSP): объект наследника должен использоваться вместо базы без нарушения обещанного поведения. Не всякое внешне похожее отношение является корректным наследованием.

8.9. Множественное наследование+
struct Printer { void status() {} };
struct Scanner { void status() {} };
struct Copier : Printer, Scanner {};
Copier c;
// c.status();          // неоднозначно
c.Printer::status();   // явно выбираем базу

При множественном наследовании объект содержит подобъекты нескольких прямых баз. Адрес Printer* и Scanner*, полученный из Copier*, может различаться: корректное преобразование указателя на базу учитывает смещение подобъекта. reinterpret_cast не заменяет корректное приведение к базе.

8.10. Проблема ромба+

В обычном ромбе Printer и Scanner наследуют Device, а Copier наследует оба класса. В Copier находятся два подобъекта Device, по одному через каждую ветвь. Виртуальное наследование Device обеими ветвями позволяет иметь один общий подобъект.

struct Device { int id = 0; };
struct Printer : Device {};
struct Scanner : Device {};
struct Copier : Printer, Scanner {};
Copier c;
// c.id = 1; // неоднозначно: ДВА Device-подобъекта
c.Printer::id = 1;
c.Scanner::id = 2;

Без виртуального наследования Copier содержит две отдельные копии Device, каждая со своим id. Квалификация имени выбирает одну ветку, но не устраняет дублирование состояния.

8.11. Виртуальное наследование+
struct Device { explicit Device(int id) : id(id) {} int id; };
struct Printer : virtual Device { Printer() : Device(1) {} };
struct Scanner : virtual Device { Scanner() : Device(2) {} };
struct Copier : Printer, Scanner {
    Copier() : Device(42), Printer(), Scanner() {}
};
Copier c;
// c.id == 42: общий Device-подобъект ровно один
Схема наследования Число подобъектов Device в Copier
Printer : Device, Scanner : Device Два отдельных подобъекта
Printer : virtual Device, Scanner : virtual Device Один общий подобъект

Ключевой нюанс: виртуальную базу инициализирует наиболее производный класс (Copier), а инициализаторы Device(...) в промежуточных конструкторах игнорируются, когда эти классы являются подобъектами Copier. Виртуальные базы конструируются до невиртуальных баз; детали расположения служебных указателей/таблиц (vbptr, vptr) — детали ABI, а не обязательная модель памяти стандарта C++.

8.12. Примеси, интерфейсы и альтернативы+

Mixin добавляет типу небольшую возможность через наследование (например, CRTP-шаблон). Интерфейс в C++ часто задаётся абстрактным классом с чисто виртуальными методами:

struct Drawable {
    virtual void draw() const = 0;
    virtual ~Drawable() = default;
};
struct Circle : Drawable {
    void draw() const override { std::cout << "circle"; }
};

Чисто виртуальный метод (= 0) делает класс абстрактным, если в наиболее производном классе остаётся непереопределённым. В интерфейсах нужен виртуальный деструктор, если объекты могут удаляться через указатель на базу. Альтернативы наследованию: композиция, шаблоны, концепты C++20, std::variant и свободные функции. Важное разграничение: virtual-методы и динамический полиморфизм подробно развиваются в следующих темах курса; здесь они введены ровно настолько, насколько нужны для понимания наследования, срезки и интерфейсов.

8.13. Практика: виртуальная функция и аргумент по умолчанию+

#include <iostream>
struct Base {
    virtual void print(int n = 1) const { std::cout << "B" << n; }
    virtual ~Base() = default;
};
struct Derived : Base {
    void print(int n = 2) const override { std::cout << "D" << n; }
};
int main() {
    Derived d;
    const Base& b = d;
    b.print();         // D1: тело по динамическому типу, аргумент по статическому
    d.print();         // D2
    d.Base::print();   // B1: явная квалификация подавляет виртуальный вызов
}

Вывод: D1D2B1. override требует совпадения нужных характеристик функции: отсутствие const у метода наследника здесь приведёт к ошибке компиляции. Обычный конструктор не бывает виртуальным; деструктор может быть виртуальным.

8.14. Самопроверка по ООП и особенностям C+++
  1. Почему T x = other; вызывает конструктор, а x = other; — присваивание?
  2. Почему T(T&& other) : field(other.field) {} может копировать поле? Исправление: field(std::move(other.field)); имя other — lvalue.
  3. Что произойдёт при delete basePtr, если он указывает на Derived, а деструктор базы невиртуален? Для обычного удаления такого объекта — UB.
  4. Почему private не означает «поля базы отсутствуют в наследнике»? Они входят в базовый подобъект, но прямой доступ ограничен.
  5. Чем virtual Base отличается от virtual void f()? Первое управляет общим базовым подобъектом, второе — выбором реализации при вызове.
  6. Почему нельзя вернуть ссылку на локальный результат operator+? Объект разрушится при выходе, ссылка станет висячей; возвращайте значение.

Дополнительная практика с виртуальными вызовами расширяет вводный материал лекции 8; это не утверждение о точном содержании контрольной.

const T* нельзя менять T через указатель

9.2. Пять видов ответа на вопрос «что выведет код?»+
  1. Компилируется, результат определён: можно назвать точный вывод.
  2. Ошибка компиляции: нет исполняемого файла; объясните причину (например, private, ambiguous overload, narrowing).
  3. Ошибка компоновки: объявление есть, определения нет, либо конфликт определений.
  4. UB: стандарт не определяет поведение; нельзя обещать конкретный вывод.
  5. Unspecified / implementation-defined: программа может иметь несколько разрешённых вариантов или зависеть от реализации; не путайте с UB.
9.3. Алгоритм решения задачи по коду+
  1. Проверить синтаксис, типы, доступ и перегрузки: иначе ошибка компиляции.
  2. Проверить наличие определений: возможна ошибка компоновки.
  3. Проверить время жизни, границы и остальные причины UB. При UB точного вывода нет.
  4. Если поведение определено, разобрать вызовы, порядок действий и вычислить вывод.

Перед ответом проверяйте: (1) тип каждого выражения; (2) категорию значения; (3) const и доступ; (4) перегрузку; (5) время жизни; (6) копирование или перемещение; (7) порядок конструирования и уничтожения; (8) выход за границы/неинициализированные значения; (9) особенности C++20.

Тренировочная контрольная с решениями

Сначала решите без просмотра ответов. Для фрагментов подразумеваются нужные стандартные заголовки и std:: там, где это очевидно; если не указано иначе, каждый пример рассматривается отдельно.

Задача 1. Целочисленное деление+
int a = 7, b = 2;
std::cout << a / b << ' ' << a % b << ' ' << a / 2.0;

Ответ: 3 1 3.5. Первые две операции целочисленные; в третьей a преобразуется к double.

Задача 2. Префикс и постфикс+
int x = 4;
int y = x++;
int z = ++x;
std::cout << x << ' ' << y << ' ' << z;

Ответ: 6 4 6. Постфикс сохраняет старое значение 4 и делает x=5; префикс делает x=6 и возвращает 6.

Задача 3. Массив и указатель+
int a[]{3, 6, 9};
int* p = a;
std::cout << *(p + 1) << ' ' << (a + 3 - p);

Ответ: 6 3. a+3 — допустимый one-past-end указатель; разность считается в элементах.

Задача 4. const+
int x = 1, y = 2;
const int* p = &x;
p = &y;
// *p = 3;

Ответ: без закомментированной строки компилируется. p перенаправляется; *p=3 — ошибка компиляции из-за const.

Задача 5. Время жизни+
int* make() {
    int x = 10;
    return &x;
}
int main() { std::cout << *make(); }

Ответ: обращение через висячий указатель, UB; нельзя утверждать, что будет напечатано 10.

Задача 6. Перегрузка+
void f(int) { std::cout << "I"; }
void f(double) { std::cout << "D"; }
int main() { f(1); f(1.0); f('a'); }

Ответ: IDI. char обычно продвигается к int (integral promotion), что лучше conversion к double.

Задача 7. Ссылка против копии+
void a(int x) { x += 2; }
void b(int& x) { x += 3; }
int main() { int n=1; a(n); b(n); std::cout << n; }

Ответ: 4. a меняет копию, b — исходный n.

Задача 8. Порядок полей+
struct S {
    int x = 2;
    int y = x + 3;
    S() : y(100), x(5) {}
};
int main() { S s; std::cout << s.x << ' ' << s.y; }

Ответ: 5 100. Поля инициализируются в порядке объявления, но явный инициализатор y(100) перекрывает default member initializer y = x+3.

Задача 9. Деструкторы+
struct A { ~A(){std::cout << "A";} };
struct B { ~B(){std::cout << "B";} };
int main() { A a; B b; }

Ответ: BA. Локальные объекты уничтожаются в обратном порядке конструирования.

Задача 10. Копирование и владение+
struct Bad {
    int* p = new int(5);
    ~Bad() { delete p; }
};
int main() { Bad a; Bad b = a; }

Ответ: копирование Bad b=a по умолчанию копирует адрес; при разрушении обоих объектов возникает double delete / UB. Исправление: std::unique_ptr<int> с запретом копирования, std::vector<int> или глубокое копирование с Rule of Five.

Задача 11. Перегрузка +++
struct C {
    int x{};
    C& operator++() { ++x; return *this; }
    C operator++(int) { C old=*this; ++*this; return old; }
};
int main() { C c{2}; C a=c++; C b=++c; std::cout << a.x << ' ' << b.x << ' ' << c.x; }

Ответ: 2 4 4. После c++: a=2, c=3; после ++c: c=4, b копирует 4.

Задача 12. Сокрытие имён+
struct Base {
    void f(int) { std::cout << "I"; }
    void f(double) { std::cout << "D"; }
};
struct Derived : Base {
    void f(int) { std::cout << "X"; }
};
int main() { Derived d; d.f(2.5); }

Ответ: X. Имя f в наследнике скрывает обе перегрузки базы; double преобразуется в int. Добавление using Base::f; сделает вывод D.

Задача 13. Срезка+
struct B { virtual ~B() = default; virtual int f() const { return 1; } };
struct D : B { int f() const override { return 2; } };
int byValue(B b) { return b.f(); }
int byRef(const B& b) { return b.f(); }
int main() { D d; std::cout << byValue(d) << byRef(d); }

Ответ: 12. В byValue происходит срезка до B, в byRef динамический тип объекта остаётся D и виртуальный вызов выбирает D::f.

Задача 14. Ромб+
struct A { int x=1; };
struct B : A {};
struct C : A {};
struct D : B, C {};
int main() { D d; /* std::cout << d.x; */ }

Ответ: d.x неоднозначно — в D две копии A. Можно выбрать d.B::x или d.C::x; для единой общей базы используйте struct B : virtual A и struct C : virtual A.

Задача 15. std::move и категории+
void f(const std::string&) { std::cout << "L"; }
void f(std::string&&) { std::cout << "R"; }
int main() {
    std::string s = "abc";
    f(s);
    f(std::move(s));
}

Ответ: LR. Именованное s — lvalue; std::move(s) — xvalue. Сам вызов f(std::move(s)) ничего не перемещает: выбранная перегрузка лишь принимает ссылку.

Задача 16. explicit+
struct T { explicit T(int) {} };
void f(T) {}
int main() {
    T a{3};
    // T b = 3;
    // f(3);
    f(T{3});
}

Ответ: T a{3} и f(T{3}) корректны; T b = 3 и f(3) — ошибки из-за запрета неявного преобразования.

Задача 17. operator<=>+
struct P {
    int x, y;
    auto operator<=>(const P&) const = default;
};
int main() { P a{1,9}, b{2,0}; std::cout << (a < b); }

Ответ: 1. Сравнение лексикографическое: сначала x, а 1 < 2, поэтому y не определяет результат.

Задача 18. Виртуальная база+
struct A { int x; explicit A(int n) : x(n) {} };
struct B : virtual A { B() : A(1) {} };
struct C : virtual A { C() : A(2) {} };
struct D : B, C { D() : A(7), B(), C() {} };
int main() { D d; std::cout << d.x; }

Ответ: 7. В наиболее производном объекте D виртуальную базу A инициализирует D, а не B или C.

Задача 19. Написать класс без ручного new/delete+

Условие: реализовать класс Scores, который хранит оценки, добавляет оценку, возвращает среднее, запрещает оценки вне диапазона 0–100.

#include <vector>
#include <stdexcept>
class Scores {
    std::vector<int> values_;
public:
    void add(int x) {
        if (x < 0 || x > 100) throw std::out_of_range("score");
        values_.push_back(x);
    }
    double average() const {
        if (values_.empty()) return 0.0;
        long long sum = 0;
        for (int x : values_) sum += x;
        return static_cast<double>(sum) / values_.size();
    }
};

Разбор: private защищает инвариант; add проверяет данные; average() const не изменяет объект; std::vector автоматически управляет памятью; static_cast<double> не даёт целочисленному делению испортить среднее. При чрезвычайно большом числе оценок даже long long теоретически может переполниться — для заданных ограничений это нужно учитывать.

Задача 20. Написать класс с каноническими операторами+

Условие: реализовать двумерный целочисленный вектор с +=, +, ==, <<.

#include <iostream>
struct Vector2 {
    int x{}, y{};
    Vector2& operator+=(const Vector2& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;
    }
    friend Vector2 operator+(Vector2 lhs, const Vector2& rhs) {
        lhs += rhs;
        return lhs;
    }
    bool operator==(const Vector2&) const = default;
    friend std::ostream& operator<<(std::ostream& os, const Vector2& v) {
        return os << '(' << v.x << ',' << v.y << ')';
    }
};

Разбор: += меняет объект; + использует копию lhs; == C++20 сравнивает поля; потоковый оператор свободный и возвращает ostream&. Для int арифметика может переполниться — это отдельное ограничение типа.
