# C++20 и ООП с нуля: от первой строки до наследования

Эта книга рассчитана на человека, который ещё не знает C++. Здесь недостаточно запомнить, что «ссылка — это псевдоним», а «конструктор создаёт объект». Нужно увидеть, какую проблему решает каждый механизм, научиться читать его запись и проследить, что происходит во время выполнения программы.

Мы будем постепенно строить одну картину. Сначала программа научится хранить числа и выполнять команды. Затем мы выделим повторяющиеся действия в функции. После этого объединим связанные данные и действия в классы, научимся управлять временем жизни объектов и только потом перейдём к наследованию. В технических разделах каждой лекции есть дополнительные правила и задачи: их следует читать после вводного объяснения этой лекции.

Основа книги — восемь учебных презентаций в папке `docs`: введение, операторы, указатели, функции, классы, конструкторы и RAII, перегрузка операторов, наследование. Примеры и объяснения относятся к C++20. Названия сложных механизмов будут встречаться постепенно; при первом чтении не требуется знать их заранее.

**Как устроены примеры.** Блок с `int main()` обычно представляет отдельную программу. Его можно сохранить в файл `main.cpp` и собрать командой `clang++ -std=c++20 -Wall -Wextra -Wpedantic main.cpp -o app`, а затем запустить `./app`. Если установлен GCC, вместо `clang++` можно использовать `g++`. Блок без `main()` обычно показывает часть программы: определение функции, класса или несколько строк, которые нужно вставить внутрь функции. Нельзя просто склеить все примеры в один файл: у программы должна быть одна точка входа.

**Как читать.** Не пытайтесь сразу удержать в памяти все правила. Сначала объясните словами, что хранится в программе и какая команда меняет эти данные. Затем прочитайте запись на C++. После запуска сравните результат со своим прогнозом. Ошибочные строки в примерах специально закомментированы; их назначение — показать границы допустимого, а не дать программу для запуска.

# Перед первой лекцией: как читать программу

## Программа — это описание действий над данными

Представьте задачу: у студента есть три оценки, и нужно найти среднюю. Человек видит условие целиком и понимает смысл слов. Компьютеру нужно дать более точное описание: где взять оценки, как их сложить, на какое число разделить сумму и куда отправить ответ.

Мы записываем это описание на языке программирования. Сам текст называется **исходным кодом**. C++ задаёт правила, по которым такой текст должен быть построен. Правила нужны не для красоты: по ним другой инструмент, компилятор, понимает, какие действия мы описали.

```cpp
#include <iostream>

int main() {
    int first = 4;
    int second = 5;
    int third = 3;

    double average = (first + second + third) / 3.0;
    std::cout << average << '\n';
}
```

Программа напечатает `4`. Теперь прочитаем её без предположения, что синтаксис уже знаком.

Первая строка подключает стандартный заголовок `iostream`. В нём описаны средства ввода и вывода. Мы используем готовый инструмент вывода, поэтому сначала должны сделать его описание доступным компилятору. Угловые скобки в `#include <iostream>` относятся к записи подключения заголовка; это не сравнение чисел.

`int main()` начинает определение главной функции. Пока достаточно понимать функцию как именованный участок программы. Имя `main` особенное: в обычной программе для компьютера это точка входа в написанный нами код. Круглые скобки относятся к параметрам функции. Сейчас они пустые, потому что параметры нам не нужны. Слово `int` перед `main` означает, что функция возвращает целочисленный код завершения. Это не число, которое пользователь видит на экране.

Фигурная скобка `{` открывает тело функции, а соответствующая `}` закрывает. Между ними находятся команды. В простых примерах выполнение идёт сверху вниз. Пустые строки помогают человеку разделять мысли, но сами действий не выполняют.

В строке `int first = 4;` появляется **переменная** с именем `first`. Представьте подписанное место для хранения значения. Здесь `int` — тип: он сообщает, что мы работаем с целым числом. `first` — выбранное нами имя. `4` — начальное значение. Точка с запятой завершает объявление. Имена `first`, `second` и `third` не встроены в язык: мы придумали их сами.

Когда программа доходит до вычисления `average`, три оценки уже существуют. Скобки в `(first + second + third)` объединяют сложение в одно выражение. **Выражение** — часть кода, у которой вычисляется результат. Затем сумма делится на `3.0`. Десятичная точка существенна: так мы просим деление с плавающей точкой. Позже разберём, почему `/ 3` могло бы потерять дробную часть. Результат сохраняется в переменной `average`, чей тип `double` предназначен для чисел с дробной частью.

Наконец, `std::cout << average << '\n';` отправляет значение в стандартный поток вывода, а затем переводит строку. `std` — пространство имён стандартной библиотеки. Запись `std::cout` означает «имя `cout`, находящееся в `std`». Оператор `<<` здесь работает как отправка значения в поток. Одинаковые символы в другом контексте могут иметь другое значение; например, для целых чисел `<<` означает битовый сдвиг.

В конце `main` можно написать `return 0;`. Для этой конкретной функции достижение конца тела и без явного `return` означает успешное завершение с кодом ноль. Это особое правило `main`; переносить его на любую функцию нельзя.

## Что такое синтаксис и почему важен каждый знак

В обычном тексте опечатка часто не мешает понять смысл. В программе `first` и `First` — разные имена, потому что C++ различает регистр. Одинарные кавычки `'A'` задают символьный литерал, а двойные `"A"` — строковый литерал. `=` задаёт присваивание либо участвует в инициализации, а `==` проверяет равенство. Компилятор не обязан угадывать, какой знак вы хотели написать.

Слово **литерал** означает значение, записанное прямо в коде: `42`, `3.0`, `'A'`, `true`. Имя переменной устроено иначе: `first` обозначает объект, значение которого нужно получить. Поэтому `first + 1` зависит от содержимого `first`, а `4 + 1` использует два непосредственно записанных числа.

Комментарии служат читателю. После `//` до конца строки можно написать пояснение. Многострочный комментарий ограничивается `/*` и `*/`. Компилятор не выполняет текст комментария. Если ошибочную строку превратить в комментарий, это не исправляет действие — оно просто исчезает из программы.

Отступы помогают увидеть вложенность: команды внутри фигурных скобок обычно сдвигают вправо. C++ в основном не придаёт отступам смысл Python: границы блоков задают скобки. Поэтому красиво выровненный код с неправильными скобками всё равно может работать неправильно.

## Текст программы и выполнение — разные этапы

Сначала вы сохраняете исходный код. Затем компилятор проверяет его и участвует в создании исполняемого файла. Только после запуска файла начинаются описанные действия: создаются переменные, читается ввод, вычисляются результаты.

Если вы забыли точку с запятой, программа обычно не будет собрана. Если вы написали правильную по синтаксису формулу `first - second` вместо нужного сложения, программа может собраться и выдать неверный ответ. Это логическая ошибка: язык разрешает записанное действие, но оно не соответствует вашей задаче.

Есть и более сложный случай: программа собирается, но выполняет действие, для которого язык не устанавливает требований к поведению. Например, читает элемент за границей массива. Это **неопределённое поведение**, часто обозначаемое английским сокращением UB. Нельзя учиться на предположении «на моём компьютере получилось 7, значит ответ 7». В таком месте задача уже состоит в поиске нарушения правил, а не в вычислении гарантированного вывода.

## Первая самостоятельная проверка

Замените третью оценку на `4`. Сначала вручную получите сумму `13` и ожидаемое среднее примерно `4.33333`. Затем запустите программу. Число отображаемых знаков после точки зависит от настройки вывода; пока важно увидеть, что результат не ограничен целым числом.

После этого замените `3.0` на `3`. Вы получите `4`, потому что сначала произошло целочисленное деление `13 / 3`, а уже его результат был сохранён в `double`. Эта маленькая программа показывает главный способ изучения языка: изменение одного элемента записи должно сопровождаться объяснением, какое действие изменилось.

# Лекция 1. Язык, компиляция, инструменты и типы

## Сначала разберёмся: что именно хранит программа

До знакомства с классами нужно освоить четыре слова: **тип, объект, значение и имя**. Они описывают разные стороны одной ситуации. В строке `int age = 18;` тип — `int`, значение — `18`, имя — `age`, а объект — конкретная область хранения, в которой это значение находится во время жизни переменной. Имя позволяет обращаться к объекту в тексте программы. Позже мы увидим объекты без собственных имён и несколько способов обращаться к одному объекту.

Тип отвечает не только за объём памяти. Он определяет допустимые операции и их смысл. Над целыми числами можно выполнять арифметику; строку можно объединить с другой строкой; у объекта нашего класса могут быть собственные методы. Сначала компилятор смотрит на типы, а затем решает, допустимо ли выражение. Он не рассуждает по принципу «в памяти всё равно биты, поэтому разрешено всё».

Представьте, что мы храним число студентов. Тип `int` естественен, потому что полтора студента в этой задаче не бывает. Для среднего балла удобнее `double`, поскольку результат может содержать дробную часть. Для имени подходит `std::string`. Выбор типа — первый шаг моделирования задачи: мы выбираем, какие значения вообще имеют смысл.

### Создание значения и его последующее изменение

```cpp
int score = 10;
score = 15;
int saved = score;
score = 20;
```

Первая строка создаёт `score` с начальным значением `10`. Вторая меняет значение уже существующего объекта на `15`. Третья создаёт другой объект, `saved`, и берёт для него текущее значение `score`, то есть `15`. Последняя строка меняет только `score`. В результате `score` равно `20`, а `saved` равно `15`.

Это нужно понять до указателей и ссылок: обычное создание одной целочисленной переменной из другой не связывает их будущие изменения. Мы скопировали значение. Если в другой комнате на доске написали то же число, изменение первой доски не перепишет вторую.

Запись `int score = 10;` называется инициализацией. Запись `score = 15;` — присваиванием. Разница становится особенно важной для классов: при создании работает конструктор, а при изменении существующего объекта может работать оператор присваивания. Похожий знак `=` не означает одинаковый этап жизни объекта.

### Почему локальное число нужно инициализировать

При записи `int score;` внутри функции объект появляется, но начальное числовое значение ему не задаётся. В C++20 нельзя прочитать такой `int` и считать полученный результат осмысленным случайным числом: такое чтение приводит к неопределённому поведению. Зато можно сначала выполнить `score = 10;`, а затем прочитать `score`.

В учебном коде полезна запись `int score{};`: она задаёт ноль. Фигурные скобки также помогают обнаружить некоторые опасные преобразования. Например, `int score{3.5};` не разрешит незаметно отбросить дробную часть. Но из этого не следует, что фигурные скобки всегда означают «заполнить всю память нулями»: для классов существуют собственные правила инициализации.

### Что обещает const

```cpp
const int limit = 100;
int current = 20;
current = 30;
// limit = 200; // ошибка: менять limit нельзя
```

`const` сообщает, что через данное объявление нельзя менять значение. Это полезно, когда число выражает неизменное условие задачи. Читатель понимает, что `limit` не должен неожиданно стать другим, а компилятор ловит попытку изменения.

`constexpr` решает связанную, но другую задачу: для переменной он требует инициализации константным выражением и делает переменную константной. Обычный `const` может получить значение во время работы программы. Например, можно прочитать число от пользователя, а затем создать `const int saved = input;`. Для `constexpr` такого неизвестного заранее значения недостаточно.

### Как понимать auto

В объявлении `auto count = 10;` компилятор выводит тип из инициализатора: здесь получается `int`. Это не означает, что тип переменной станет меняться во время выполнения. После объявления тип уже определён. Если затем присвоить `count = 3.8;`, произойдёт преобразование к `int`, а не превращение переменной в `double`.

Пока тип короткий, явная запись часто лучше помогает учиться. `auto` особенно полезен для длинных типов и результатов библиотечных операций. Позже станет важно различать `auto`, создающее значение, и `auto&`, сохраняющее ссылку на существующий объект.

### Зачем нужны отдельные файлы и сборка

Когда программа мала, все определения помещаются в одном `.cpp`. Когда появляются десятки функций, удобно разложить их по файлам. Заголовок обычно сообщает, чем можно воспользоваться, а `.cpp` содержит реализацию. Если один файл вызывает функцию из другого, компилятору нужно знать её объявление, а компоновщику — найти её определение.

Так становится понятна разница ошибок. Фраза компилятора о неизвестном имени часто означает, что объявление не видно в этом месте. Ошибка компоновки о ненайденной функции означает, что вызов удалось понять, но подходящую реализацию не удалось найти при сборке программы. Системы Make и CMake помогают повторять нужные команды сборки; они не заменяют сам язык C++.

В следующих подразделах эти идеи уточняются: появляются размеры типов, формы инициализации и правила отдельных файлов. Сначала для каждого примера отвечайте на простой вопрос: здесь создаётся новый объект, меняется существующий или только описывается имя?

## 1.1. Что такое C++ и зачем он нужен

C++ — **компилируемый мультипарадигменный язык**: поддерживает процедурный стиль, ООП, обобщённое и функциональное программирование. Объектно-ориентированное программирование связывает **состояние** (поля объекта) и **поведение** (методы), контролирует доступ и позволяет моделировать отношения между типами. C++ добавляет к этому управление временем жизни объектов, шаблоны, перегрузку, стандартные контейнеры и RAII.

Важные стандарты: **C++11** (`auto`, `nullptr`, move, лямбды); **C++14** (улучшения `constexpr`); **C++17** (`if constexpr`, structured bindings, `std::optional`); **C++20** (`concepts`, `ranges`, `<=>`, `std::span`, `std::numbers`, `consteval`). Если на контрольной разрешён C++20, не нужно ограничиваться синтаксисом C++11.

## 1.2. Структура программы

```cpp
#include <iostream>            // объявление std::cout

int main() {                   // точка входа
    std::cout << "Hello!\n";  // печать
    return 0;                  // успешное завершение
}
```

`#include` обрабатывается препроцессором; `std::` — квалификация имени в пространстве имён; `main` возвращает `int`, а отсутствие явного `return` в конце `main` равнозначно `return 0`. Допустима также форма `int main(int argc, char* argv[])`: `argc` — число аргументов, `argv` — их C-строки.

**Объявление** сообщает компилятору о существовании сущности: `int sum(int, int);`. **Определение** создаёт её реализацию: `int sum(int a, int b) { return a + b; }`. Для переменных `extern int count;` обычно только объявляет, а `int count = 0;` определяет.

## 1.3. Как исходный код становится программой

Препроцессор обрабатывает исходные файлы и заголовки, формируя единицу трансляции. Компилятор создаёт объектный файл. Компоновщик объединяет его с другими объектными файлами и библиотеками в исполняемый файл, который затем загружается и запускается.

1. **Препроцессор** раскрывает `#include`, макросы и условную компиляцию (`g++ -E main.cpp -o main.i`).
2. **Компилятор** анализирует синтаксис и типы и генерирует объектный файл (`g++ -std=c++20 -c main.cpp -o main.o`).
3. **Компоновщик** связывает определения функций между объектными файлами (`g++ main.o utils.o -o app`).
4. **Загрузчик** ОС размещает программу в памяти и запускает её.

Если написать `void f(); int main(){f();}` без определения `f`, компиляция отдельного файла может пройти, а компоновка выдаст `undefined reference`. Если не закрыта скобка, это **ошибка компиляции**. Если обращение идёт за пределы массива — программа может собраться, но при выполнении возникает **undefined behavior (UB)**.

### ODR — One Definition Rule

В каждой единице трансляции нельзя иметь два определения одного и того же определяемого объекта. Для обычной функции с внешней связью программа должна иметь одно определение; специальные правила разрешают идентичные определения `inline`-функций, шаблонов и типов в разных единицах трансляции.

```cpp
// math.hpp
#pragma once
int add(int a, int b);             // объявление
inline int square(int x) { return x*x; } // допустимо в заголовке

// math.cpp
#include "math.hpp"
int add(int a, int b) { return a+b; } // определение
```

**Ловушка:** определение обычной не-`inline` функции в `.hpp`, включённом в два `.cpp`, часто приводит к `multiple definition`. `#pragma once` защищает только от повторного включения заголовка в **одну** единицу трансляции; оно не устраняет нарушение ODR между разными `.cpp`.

## 1.4. make, CMake, Google Test и отладка

Представим, что программа состоит из `main.cpp` и `math.cpp`. Можно каждый раз вручную вызывать компилятор для обоих файлов, но по мере роста проекта становится трудно помнить все параметры. Система сборки хранит эти зависимости и команды. Если изменился только один файл реализации, нет необходимости заново переводить все остальные исходные файлы. Если изменился общий заголовок, пересобрать может потребоваться сразу несколько файлов, которые его включают.

Отладчик решает другую задачу: позволяет остановить уже запущенную программу и посмотреть её состояние. Например, если среднее вычисляется неверно, можно поставить точку останова перед делением, проверить сумму и количество оценок и выяснить, на каком шаге ожидание перестало совпадать с действительностью. Команда `step` обычно позволяет войти внутрь вызванной функции, а `next` — выполнить строку, не разбирая внутренности вызова по шагам.

Тест формулирует проверяемое ожидание. Для сложения это может быть утверждение «при аргументах 2 и 3 результат равен 5». Успешный тест подтверждает конкретный проверенный случай, но не доказывает отсутствие всех ошибок. Google Test — библиотека для записи и запуска таких проверок; её имена не являются встроенными ключевыми словами C++.

`make` использует правила вида `цель: зависимости`, затем **команду с отступом табуляцией**. При изменении зависимости пересобирает нужные цели.

```makefile
app: main.o math.o
	g++ main.o math.o -o app

main.o: main.cpp math.hpp
	g++ -std=c++20 -Wall -Wextra -c main.cpp -o main.o
```

CMake описывает проект на более высоком уровне:

```cmake
cmake_minimum_required(VERSION 3.16)
project(OOP LANGUAGES CXX)
set(CMAKE_CXX_STANDARD 20)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
add_executable(app main.cpp math.cpp)
target_compile_options(app PRIVATE -Wall -Wextra -Wpedantic)
```

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
./build/app
```

`Debug` обычно содержит `-g -O0`; `Release` оптимизирует. Для поиска ошибок полезны `gdb ./build/app`, команды `break main`, `run`, `next`, `step`, `print x`, `backtrace`. В Google Test тест выглядит так:

```cpp
#include <gtest/gtest.h>
TEST(Math, Add) {
    EXPECT_EQ(5, add(2, 3));
    ASSERT_EQ(0, add(-1, 1));
}
```

`EXPECT_*` фиксирует неудачу и продолжает тест, `ASSERT_*` прерывает текущую тестовую функцию. Наличие Google Test требует отдельной настройки зависимостей/сборки.

## 1.5. Типы, литералы, размеры

| Тип | Смысл | Пример | Тонкость |
|---|---|---|---|
| `bool` | логическое значение | `true` | не обязательно 1 байт по стандарту |
| `char` | символьный/байтовый тип | `'A'` | signedness обычного `char` зависит от реализации |
| `int` | целое со знаком | `42` | обычно 32 бита, но не гарантировано |
| `unsigned` | беззнаковое | `42u` | переполнение по модулю 2^N |
| `long long` | целое не менее 64 бит | `42LL` | точная ширина зависит от платформы |
| `float` | плавающая точка | `1.5f` | ограниченная точность |
| `double` | плавающая точка | `1.5` | обычно IEEE 754 binary64 |
| `std::string` | строковый объект | `"hi"s` | суффикс `s` требует соответствующего namespace литералов |

`sizeof(T)` возвращает размер **в байтах** типа `std::size_t`; `sizeof(char) == 1` по определению. Размер указателя зависит от платформы (часто 8 байт в 64-битной программе), а не от типа объекта, на который он указывает. `sizeof(arr)` для настоящего массива даёт размер всего массива, а для указателя — размер указателя.

```cpp
int a = 10;             // десятичный
int b = 0b1010;         // двоичный: 10
int c = 0xFF;           // шестнадцатеричный: 255
int d = 1'000'000;      // разделители разрядов
unsigned long long n = 10ULL;
double e = 1.2e3;       // 1200.0
```

## 1.6. Инициализация — крайне важная тема

Инициализация задаёт начальное состояние **при создании** объекта. Присваивание меняет уже существующий объект. Сначала найдите в строке объявление нового объекта: знак `=` сам по себе не означает вызов оператора присваивания.

```cpp
int a = 5; // создаём a: инициализация
int b{a};  // создаём b: инициализация
b = 9;     // b уже существует: присваивание
```

### 1.6.1. Формы записи: что именно они означают

| Запись | Название | Для локального int | Особенность для классов |
|---|---|---|---|
| `T x;` | Default-initialization | Значение не задано | Вызывается подходящий конструктор без аргументов |
| `T x = value;` | Copy-initialization | Начальное значение из value | Не использует explicit-конструктор для такого преобразования |
| `T x(value);` | Direct-initialization | Начальное значение из value | Может использовать explicit-конструктор |
| `T x{value};` | Direct-list-initialization | Запрет narrowing | Агрегатная инициализация либо выбор конструктора |
| `T x = {value};` | Copy-list-initialization | Запрет narrowing | Ошибка, если выбран explicit-конструктор |
| `int x{};` | Пустая list-initialization, затем value-initialization | Ноль | Для произвольного T поведение зависит от типа и конструкторов |

Название copy-initialization **не гарантирует фактическое копирование**. Например, `std::string s = "hi";` конструирует строку из C-строки, а `T x = T{};` при подходящих условиях C++17+ создаёт объект сразу на месте без copy/move.

### 1.6.2. Когда получается ноль, а когда значение не задано

```cpp
int global;                 // статическое хранение: 0
int main() {
    int a;                  // автоматический int: неопределённое значение
    int b{};                // 0
    static int c;           // статическое хранение: 0
    int* p = new int;       // выделенный int: неопределённое значение
    int* q = new int{};     // 0
    // Не читаем a и *p до присваивания!
    delete p;
    delete q;
}
```

Для этих `int` чтение неопределённого значения в C++20 приводит к UB. Само объявление `int a;` и последующее присваивание `a = 10;` допустимы. Не следует объяснять это как «всегда случайное число»: определённого результата стандарт не обещает.

**Правило для запоминания:** локальный скаляр без инициализатора не получает автоматически ноль. Объекты со статическим хранением проходят статическую инициализацию; в примере `global` и `c` нулевые. Классы нужно анализировать отдельно: `std::string name;` создаёт корректную пустую строку через конструктор.

### 1.6.3. Фигурные скобки и narrowing

```cpp
int a = 3.14;             // 3: дробная часть отбрасывается
int b(3.14);              // 3
// int c{3.14};           // ошибка компиляции
// int d = {3.14};        // тоже ошибка
unsigned char e{42};      // допустимо: константа представима
int n = 42;
// unsigned char f{n};    // ошибка: n не константное выражение,
                         // а int не весь представим в unsigned char
constexpr int k = 42;
unsigned char g{k};       // допустимо
```

Сужение проверяется по правилам языка, а не только по текущему значению переменной. Поэтому `n` и `k` дают разный результат. Приведение `static_cast` может явно разрешить преобразование, но само по себе не проверяет диапазон.

### 1.6.4. Почему () и {} не взаимозаменяемы

```cpp
#include <vector>
std::vector<int> a(3, 7); // три элемента: 7, 7, 7
std::vector<int> b{3, 7}; // два элемента: 3, 7
std::vector<int> c(3);    // три нуля
std::vector<int> d{3};    // один элемент со значением 3
```

Для такого класса непустой список в `{}` сначала рассматривает конструкторы с `std::initializer_list`. Это причина различий. В `a(3, 7)` выбран конструктор «количество, значение», в `b{3, 7}` — список элементов. Скобки выбирают не стиль оформления, а семантику.

Не смешивайте **список инициализации членов конструктора** (`: x_(x)`) и **тип `std::initializer_list`**: это разные понятия.

### 1.6.5. Класс и explicit: какой конструктор доступен

```cpp
struct Count {
    explicit Count(int) {}
};
void use(Count) {}

int main() {
    Count a(5);           // direct: допустимо
    Count b{5};           // direct-list: допустимо
    // Count c = 5;       // ошибка: неявное преобразование запрещено
    // Count d = {5};     // ошибка: выбран explicit-конструктор
    // use(5);            // ошибка
    use(Count{5});        // явно создаём Count
}
```

`explicit` защищает от непреднамеренного превращения числа в объект. Подробнее конструкторы и специальные методы изучаются в лекции 6; здесь важно различать формы инициализации.

### 1.6.6. Пустые скобки и most vexing parse

```cpp
#include <string>
std::string a;       // объект: пустая строка
std::string b{};     // объект: пустая строка
std::string c();     // объявление функции c, возвращающей string!
```

`T x();` в таком объявлении не создаёт объект. Чтобы создать объект без аргументов и избежать этой неоднозначности, используйте `T x{};`.

### 1.6.7. Массивы и агрегаты

```cpp
int a[4]{1, 2};    // 1, 2, 0, 0
int b[4]{};        // четыре нуля

struct Point {
    int x;
    int y = 9;
};
Point p{2, 3};     // x=2, y=3
Point q{2};        // x=2, y=9: инициализатор поля
Point r{};         // x=0, y=9
Point t;           // x не задан, y=9; не читайте t.x
Point u{.x = 4};   // C++20: x=4, y=9
```

`Point` здесь агрегат: у него нет пользовательски объявленных конструкторов и других признаков, исключающих агрегатность. `struct` сам по себе не гарантирует, что тип является агрегатом. Для designated initializers C++20 имена полей должны следовать порядку их объявления; нельзя произвольно переставить `.y` перед `.x`.

### 1.6.8. auto, const и ссылки

```cpp
#include <initializer_list>
const int x = 10;
auto a = x;            // int: верхний const убран
auto& b = x;           // const int&: ссылка на x
const auto& c = x;     // const int&
auto d{1};             // int
auto e = {1};          // std::initializer_list<int>
// auto f{1, 2};       // ошибка вывода типа
int n = 3;
int& ref = n;          // ref обозначает n
// int& bad = 3;       // неконстантная lvalue-ссылка не связывается с 3
const int& ok = 3;     // допустимо, время жизни временного продлено
```

`auto` — вывод типа, а не динамическая типизация. `auto a = x` создаёт независимую копию значения; `auto& b = x` связывает ссылку. Для данного `x`: `decltype(x)` — `const int`, `decltype((x))` — `const int&`.

### 1.6.9. const и constexpr не равны

```cpp
int read();
const int a = read();      // неизменяемое значение, получаемое при выполнении
constexpr int b = 5 * 5;   // инициализатор обязан быть константным выражением
// constexpr int c = read(); // ошибка: read не constexpr
```

`const` ограничивает изменение объекта. `constexpr` у такой переменной требует константного выражения в инициализаторе и также делает объект константным. Для функции `constexpr` означает возможность вычисления на этапе компиляции при подходящих аргументах и контексте, а не обязательное compile-time исполнение каждого вызова.

### 1.6.10. Осторожно: {} не обнуляет любой класс

```cpp
struct A { int x; };             // агрегат
struct B { int x; B() {} };      // пользовательский конструктор не задаёт x
struct C { int x{}; C() {} };    // поле имеет свой инициализатор

A a{}; // x=0
B b{}; // x не задан! Тело B() не инициализирует int
C c{}; // x=0
```

Запоминать «`{}` всегда всё обнуляет» неверно. Нужно определить, агрегат ли это, какой конструктор вызывается и как инициализируются его поля. Для полей скалярных типов полезно задавать default member initializer: `int x{};`.

### 1.6.11. Инициализация полей и присваивание в теле

```cpp
#include <string>
#include <utility>
class Person {
    const int id_;
    std::string name_;
public:
    Person(int id, std::string name)
        : id_(id), name_(std::move(name)) {} // поля создаются сразу
};
```

До входа в тело конструктора базы и поля уже инициализированы. `const`-поле и ссылочное поле нужно инициализировать, им нельзя «назначить начальное значение потом» обычным присваиванием. Порядок полей задаётся их объявлением в классе. Подробный порядок, включая базы, — в лекциях 6 и 8.

### 1.6.12. Проверь себя перед переходом дальше

Сначала определите, создаётся ли объект или объявляется функция. Затем назовите вид инициализации, проверьте narrowing и `explicit`, выберите конструктор и разберите состояние полей.

| Вопрос | Ответ |
|---|---|
| `int x{};` | Ноль |
| Локальный `int x;` и сразу `std::cout << x;` | UB в C++20 |
| `int x = 3.9;` | Значение 3 |
| `int x{3.9};` | Ошибка компиляции |
| `std::vector<int> v{4, 2};` | Два элемента: 4 и 2 |
| `std::vector<int> v(4, 2);` | Четыре элемента со значением 2 |
| `T object();` | Объявление функции |
| `T b = a;` | Инициализация нового b, не присваивание |

Правила сверены с проектом стандарта C++20 N4861: [инициализация](https://timsong-cpp.github.io/cppwp/n4861/dcl.init), [list-initialization](https://timsong-cpp.github.io/cppwp/n4861/dcl.init.list), [инициализация баз и полей](https://timsong-cpp.github.io/cppwp/n4861/class.base.init).

## 1.7. namespace и конфликт имён

В большом проекте разные авторы могут назвать функцию одинаково: например, `print`. Пространство имён позволяет уточнить, чья именно функция нужна. Это похоже на одинаковые названия улиц в разных городах: одно короткое имя не всегда определяет объект, а уточнение снимает неоднозначность.

В записи `std::cout` часть слева от `::` указывает пространство имён. Свои объявления можно поместить в `namespace Geometry { ... }`, а затем обращаться к ним как к `Geometry::Point`. Директива `using namespace std;` делает многие имена доступными для неквалифицированного поиска, но не переносит объявления физически в ваш файл и не подключает нужные заголовки. В книге полные имена помогают видеть происхождение библиотечных средств.

```cpp
namespace A { int value = 1; }
namespace B { int value = 2; }
int x = A::value;  // 1
```

`using namespace A; using namespace B; int x = value;` — неоднозначность. В заголовочных файлах особенно нежелательно `using namespace std;`: оно загрязняет пространство имён каждого включающего файла.

**Проверка:** почему `const int size = getSize(); int arr[size];` не является стандартным C++20, если `getSize()` — обычная функция? Потому что встроенному массиву с автоматическим хранением требуется размер, являющийся константным выражением; `const` здесь недостаточно. Используйте `std::vector<int> arr(size)`.

## 1.8. Тип, объект, значение и выражение: не смешивайте понятия

**Тип** задаёт множество допустимых значений и операций. **Объект** занимает область памяти и имеет время жизни. **Значение** — состояние, которое можно получить при вычислении. **Выражение** — запись в программе, у которой есть тип и категория значения.

В `int x = 7;` имя `x` обозначает объект типа `int`. В выражении `x + 1` получается значение 8, но это не изменяет `x`. В `int& r = x;` создаётся ссылка на тот же объект: отдельного второго `int` с числом 7 не появляется.

Сначала находите тип, затем операцию. Одинаковая запись может иметь разный смысл: `+` для целых складывает числа, а для `std::string` объединяет строки. Для `int a = 5, b = 2;` выражение `a / b` имеет тип `int`; последующее присваивание в `double` уже не восстанавливает потерянную дробную часть.

```cpp
// 01_types.cpp
#include <iostream>
int main() {
    int a = 5, b = 2;
    double first = a / b;
    double second = static_cast<double>(a) / b;
    std::cout << first << ' ' << second << '\n';
}
```

**Вывод:** `2 2.5`. В первом случае деление выполнено до преобразования в `double`. Во втором операнд уже имеет тип `double`, и деление становится вещественным.

### Как читать объявления с const

В `const int* p` константным является объект, доступный через указатель; сам `p` можно перенаправить. В `int* const p` константен объект-указатель, поэтому перенаправлять его нельзя. В `const int* const p` действуют оба ограничения. Отдельно проверяйте, что относится к указателю, а что — к объекту по адресу.

Важна разница между **нельзя изменить через данный путь доступа** и **сам объект создан константным**. Если исходный `int` не константен, его можно изменять через другое допустимое имя, даже когда существует `const int*` на него.

### Самопроверка по лекции 1

1. Почему `double x = 5 / 2;` даёт 2? Потому что деление целочисленное.
2. Почему нельзя считать `sizeof(int) == 4` правилом языка? Это свойство распространённых реализаций.
3. Чем `const int*` отличается от `int* const`? Местом ограничения изменения.
4. Почему отсутствие определения функции может обнаружиться только при линковке? Единица трансляции может компилироваться по одному объявлению.
5. Почему `T a = other;` не вызывает `operator=`? `a` создаётся, а не изменяется после создания.

# Лекция 2. Операторы, ввод-вывод, ветвления и циклы

## Как программа выбирает действия и повторяет их

Переменные позволяют хранить состояние, но сами по себе ничего не решают. Теперь нам нужны выражения, которые получают новые значения, условия, которые выбирают действия, и циклы, которые повторяют их. Рассмотрим вычисление среднего балла для нескольких оценок, вводимых пользователем.

```cpp
#include <iostream>

int main() {
    int count{};
    std::cout << "How many grades? ";
    if (!(std::cin >> count) || count <= 0) {
        std::cout << "Invalid count\n";
        return 1;
    }

    double total = 0.0;
    for (int i = 0; i < count; ++i) {
        double grade{};
        if (!(std::cin >> grade)) {
            std::cout << "Invalid grade\n";
            return 1;
        }
        total += grade;
    }

    std::cout << "Average: " << total / count << '\n';
}
```

У программы теперь два возможных пути: продолжить вычисления или завершиться из-за некорректного ввода. Это принципиальное изменение по сравнению с линейной последовательностью команд.

### Ввод тоже может не получиться

`std::cin >> count` пытается прочитать целое число. Если пользователь ввёл `abc`, получить целое не удалось, и поток запоминает ошибку. Результат операции можно использовать в условии: успешное состояние рассматривается как истина. Знак `!` меняет логическое значение на противоположное. Поэтому `!(std::cin >> count)` читается как «прочитать count не удалось».

В условии также написано `|| count <= 0`. `||` означает логическое «или»: для ошибки достаточно хотя бы одной из двух причин. У встроенного `||` есть сокращённое вычисление. Если левое условие уже истинно, правое не вычисляется, потому что ответ «истина» и так известен. У `&&`, логического «и», правое условие не вычисляется, если левое ложно.

При входе в тело `if` выводится сообщение и выполняется `return 1;`. Здесь `return` сразу завершает `main`, поэтому дальнейшего деления не будет. Мы не просто просим пользователя вводить правильные данные: программа сама проверяет необходимое условие `count > 0`.

### Как читать цикл for без заучивания

Запись `for (int i = 0; i < count; ++i)` состоит из трёх частей. Сначала один раз создаётся счётчик `i` со значением ноль. Перед каждой итерацией проверяется `i < count`. Если условие истинно, выполняется тело. После тела выполняется `++i`, увеличивающее счётчик на один. Затем проверка повторяется.

Для `count == 3` тело выполнится при `i`, равном `0`, `1` и `2`. После третьего выполнения счётчик станет `3`, условие `3 < 3` окажется ложным, и цикл закончится. Здесь не нужно угадывать количество повторений: достаточно последовательно выписать значения счётчика.

Внутри тела каждый раз создаётся `grade`. После чтения оценки команда `total += grade` прибавляет её к накопленной сумме. Для этих числовых переменных смысл соответствует `total = total + grade`. Само значение `total` сохраняется между итерациями, потому что объект создан снаружи цикла. `grade` создаётся заново при каждом входе в тело и заканчивает жизнь при выходе из него.

### Область видимости и время жизни — близкие, но разные понятия

Область видимости отвечает, где в исходном тексте можно использовать имя. Время жизни отвечает, когда существует сам объект во время выполнения. У простой локальной переменной эти границы часто идут рядом: имя видно после объявления внутри блока, а объект существует до выхода из блока. Позже динамическая память покажет, почему эти понятия нельзя отождествлять.

Если объявить `total` внутри тела цикла, сумма будет начинаться заново на каждой итерации. Это типичная логическая ошибка: формально все команды допустимы, но место объявления не соответствует нужному времени жизни данных.

### Почему результат зависит от типов операндов

В выражении `7 / 2` оба операнда целые, поэтому частное тоже целое: получится `3`. Для целых отрицательных значений дробная часть отбрасывается к нулю. В выражении `7.0 / 2` один операнд имеет тип `double`; второй преобразуется, и результатом будет `3.5`.

Запись `double result = 7 / 2;` не исправляет первое деление. Сначала вычисляется правая часть по её собственным типам, то есть получается целое `3`. Затем оно преобразуется в `double`. Поэтому важно читать выражение изнутри наружу, а не от типа переменной слева.

Аналогичная осторожность нужна со знаковыми и беззнаковыми числами. Перед сравнением язык может привести их к общему типу. Если отрицательное число превращается в большое беззнаковое, результат оказывается неожиданным. В подробных разделах ниже мы будем разбирать конкретные правила таких преобразований.

### Как читать сложное выражение

Приоритет сообщает, какие операции группируются вместе. Например, `a + b * c` означает `a + (b * c)`. Однако группировка сама по себе не задаёт порядок вычисления независимых вызовов функций. Если написано `f() + g()`, из приоритета `+` нельзя сделать вывод, что `f()` обязательно выполнится раньше `g()`.

Начинающему полезно временно разделять сложные выражения на команды. Вместо попытки сразу прочитать несколько инкрементов в одной строке сохраните промежуточные значения и объясните изменения по очереди. В C++20 выражение `i++ + i++` с одним и тем же `i` имеет неопределённое поведение из-за неупорядоченных изменений. Его нельзя превратить в корректную арифметическую задачу простым выбором «считать слева направо».

### Биты — ещё один уровень представления

Побитовые операторы работают с отдельными двоичными разрядами целых чисел. Чтобы понять их, начнём с `5`, которое в четырёх младших разрядах записывается как `0101`, и `3`, то есть `0011`. Побитовое `&` оставляет единицу только там, где единица была у обоих: получается `0001`, то есть `1`. Побитовое `|` оставляет единицу там, где она была хотя бы у одного: получается `0111`, то есть `7`.

Это другая задача, чем логическое объединение условий. `&&` спрашивает, истинны ли два условия, а `&` сопоставляет биты. Например, маска `flags & 4u` позволяет проверить третий бит набора флагов. Суффикс `u` задаёт беззнаковый литерал. Сдвиги и маски удобнее сначала изучать на беззнаковых значениях, отдельно проверяя допустимость величины сдвига.

### Переходим к подробным правилам и примерам

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 2.1. Арифметика и преобразования

```cpp
int a = 17, b = 5;
// a+b = 22; a-b = 12; a*b = 85
// a/b = 3;  a%b = 2
// -17 / 5 = -3; -17 % 5 = -2
// 17 / 5.0 = 3.4
```

При делении двух целых результат целый, **усечение идёт к нулю**. `%` работает с целочисленными типами. Деление целого на ноль — UB. Переполнение знакового целого — UB; беззнаковое переполняется по модулю `2^N`. Перед вычислением применяются **integer promotions** и **usual arithmetic conversions**. Например, `int + double` даёт `double`; при сравнении отрицательного `int` с `unsigned` можно неожиданно получить огромное положительное беззнаковое значение.

```cpp
int a = -1;
unsigned b = 1;
// a < b обычно false: a преобразуется в unsigned
```

**Важно:** не пытайтесь «предсказать число» при UB. Корректный ответ на контрольной: *поведение не определено*, а не «скорее всего напечатает ...».

## 2.2. Побитовые операции

Для `a = 0b1100` (12) и `b = 0b1010` (10):

| Выражение | Двоичный результат | Десятичный результат | Смысл |
|---|---|---|---|
| `a & b` | `1000` | 8 | Оба бита равны 1 |
| `a &#124; b` | `1110` | 14 | Хотя бы один бит равен 1 |
| `a ^ b` | `0110` | 6 | Биты различаются |
| `a << 1` | `11000` | 24 | Сдвиг влево |
| `a >> 1` | `0110` | 6 | Сдвиг вправо |

`~a` инвертирует **все биты типа после promotions**, а не только четыре показанных бита. Для битовых масок обычно выбирают `unsigned`:

```cpp
constexpr unsigned READ = 1u << 0;
constexpr unsigned WRITE = 1u << 1;
unsigned flags = READ | WRITE;
bool canRead = (flags & READ) != 0;
flags &= ~WRITE;  // снять флаг
flags |= WRITE;   // поставить флаг
flags ^= READ;    // переключить флаг
```

Сдвиг на отрицательное число бит или на число, не меньше ширины продвинутого левого операнда, — UB. Для отрицательных signed-значений и переполнения особенно осторожно применяйте сдвиги; C++20 уточнил некоторые правила сдвигов относительно старых стандартов. Для ясной побитовой арифметики используйте unsigned.

## 2.3. Логические операции и short-circuit

`&&` — логическое И, `||` — логическое ИЛИ, `!` — отрицание. Результат — `bool`. **Короткое вычисление:** в `A && B` правая часть не выполняется, если `A` ложно; в `A || B` — если `A` истинно.

```cpp
int* p = nullptr;
if (p != nullptr && *p > 0) { /* безопасная проверка */ }
```

`&` и `|` **не** являются заменой `&&` и `||`: они побитовые и не обеспечивают short-circuit. При сравнении `double` обычно учитывают абсолютную/относительную погрешность:

```cpp
#include <cmath>
bool near(double a, double b) {
    return std::abs(a-b) <= 1e-9 * std::max({1.0, std::abs(a), std::abs(b)});
}
```

Для этого примера требуется также `#include <algorithm>`. Порог подбирают под задачу; `numeric_limits<double>::epsilon()` сам по себе не является универсальным допуском.

## 2.4. Приоритет, ассоциативность, ++/--

```cpp
int a = 5;
int b = ++a;  // a=6, b=6: сначала изменить
int c = a++;  // c=6, a=7: сначала вернуть старое значение
```

Приоритет определяет **группировку**, но не всегда **порядок вычисления**. `*p++` означает `*(p++)`, а не `(*p)++`. `a = b = 3` группируется как `a = (b = 3)`. Не пишите выражения с несколькими конфликтующими изменениями одного объекта: `i++ + ++i` имеет UB из-за неупорядоченных побочных эффектов. В C++20 правила порядка вычислений уточнены, но это выражение по-прежнему некорректно.

## 2.5. Составные операторы и numeric_limits

`x += y` семантически близок к `x = x + y`, но левый операнд вычисляется один раз. Аналогично `-=`, `*=`, `/=`, `%=`, `&=`, `|=`, `^=`, `<<=`, `>>=`.

```cpp
#include <limits>
int maxInt = std::numeric_limits<int>::max();
double eps = std::numeric_limits<double>::epsilon();
double low = std::numeric_limits<double>::lowest();
double minPosNormal = std::numeric_limits<double>::min();
```

Для `double` `min()` — **наименьшее положительное нормализованное** число, не самое отрицательное. `lowest()` — наименьшее конечное. `NaN != NaN` истинно, проверяйте `std::isnan(x)`.

## 2.6. Математические функции `<cmath>`

Обычные операторы покрывают не все математические действия. Для квадратного корня есть `std::sqrt`, для степени — `std::pow`, для округления — отдельные функции. Чтобы пользоваться ими, подключают заголовок `<cmath>`. Вызов `std::sqrt(9.0)` возвращает результат вычисления корня, а не меняет аргумент на месте.

Математический смысл функции включает область допустимых аргументов. Квадратный корень из отрицательного числа не является действительным числом. При работе с типами с плавающей точкой возможны специальные значения и ошибки области; их нельзя автоматически приравнивать к исключениям C++. Отдельно помните, что `^` в C++ — побитовое исключающее «или», а не возведение в степень.

`std::abs`, `std::sqrt`, `std::pow`, `std::ceil`, `std::floor`, `std::round`, `std::sin`, `std::cos`, `std::log`, `std::log10`, `std::log2`. Тригонометрия принимает **радианы**. В C++20 число π доступно как `std::numbers::pi` из `<numbers>`:

```cpp
#include <cmath>
#include <numbers>
double x = std::sin(std::numbers::pi / 2.0); // около 1
```

`M_PI` и `M_E` — распространённые, но **не стандартные** макросы C++20. `std::pow(x, 2)` часто проще заменить на `x*x`, когда нужна именно вторая степень.

## 2.7. Ввод и вывод

```cpp
#include <iostream>
#include <iomanip>
#include <string>
#include <limits>

int age{};
if (!(std::cin >> age)) {
    std::cin.clear(); // сбросить флаг ошибки
    std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n');
}
std::string name;
std::getline(std::cin >> std::ws, name); // пропустить ведущие пробельные символы
std::cout << std::fixed << std::setprecision(2) << 3.14159 << '\n';
```

`operator>>` для строки читает до пробельного символа; `getline` — до разделителя (обычно `\n`). После `cin >> age` в буфере остаётся перевод строки; используйте `ignore(..., '\n')`, если хотите прочитать **всю следующую строку, включая возможные начальные пробелы**. `std::ws` удаляет все ведущие пробельные символы, что иногда нежелательно. `std::setw(n)` действует на следующее поле, `std::fixed`, `std::hex`, `std::boolalpha` сохраняют состояние потока до изменения. `std::endl` печатает перевод строки **и принудительно сбрасывает буфер**; обычно достаточно `'\n'`.

## 2.8. if, switch и область видимости

```cpp
if (int score = 85; score >= 90) {
    std::cout << "A";
} else if (score >= 75) {
    std::cout << "B";
} else {
    std::cout << "C";
}
// score здесь уже недоступен
```

В `switch` выполняется переход к подходящему `case`, затем выполнение продолжается до `break`, `return` или конца `switch`. `[[fallthrough]];` документирует намеренный переход к следующему `case`.

```cpp
switch (x) {
    case 1: std::cout << "one"; break;
    case 2: std::cout << "two"; [[fallthrough]];
    case 3: std::cout << "three"; break;
    default: std::cout << "other";
}
```

`switch` требует целочисленного или перечислимого управляющего типа (с учётом допустимых преобразований), не `std::string`.

## 2.9. Циклы и управление потоком

```cpp
for (int i = 0; i < 3; ++i) { std::cout << i; } // 012
int n = 0;
while (n < 3) ++n;     // проверка до тела
do { --n; } while (n > 0); // тело хотя бы один раз
```

`break` выходит из **ближайшего** цикла или `switch`, `continue` переходит к следующей итерации **ближайшего цикла**. В `for` после `continue` выполняется выражение обновления. Range-based `for`:

```cpp
std::vector<int> v{1, 2, 3};
for (int x : v) x *= 2;   // изменяется копия
for (int& x : v) x *= 2;  // изменяются элементы: 2,4,6
```

## 2.10. Преобразования типов

**Неявные:** promotion (`char` → `int`), usual arithmetic conversions, преобразование к `bool`. **Явные:** `static_cast<int>(3.9)` → `3` (усечение к нулю). C-style cast `(T)x` менее прозрачен, чем именованные C++-приведения. `static_cast` не выполняет произвольную проверку диапазона: преобразование вещественного числа в целое вне представимого диапазона — UB.

**Контрольный вопрос:** что выведет `std::cout << (5 / 2 * 2.0);`? **Ответ: `4`**, потому что `5/2` вычисляется как целое `2`, затем `2*2.0` → `4.0`.

## 2.11. Разбор: значение выражения и побочный эффект

В строке `int old = x++;` есть два результата: в `old` попадает старое значение, а `x` увеличивается. Не определяйте порядок вычисления только по приоритету операторов: приоритет задаёт группировку выражения.

```cpp
#include <iostream>
int main() {
    int x = 3;
    int old = x++;
    int now = ++x;
    std::cout << old << ' ' << now << ' ' << x; // 3 5 5
}
```

У встроенных `&&` и `||` правый операнд вычисляется только при необходимости: `p != nullptr && *p > 0` не разыменует нулевой указатель. У перегруженных операторов `&&` и `||` такой короткой схемы нет. Для контрольной безопаснее разбивать изменения одного объекта на отдельные строки и затем считать результат.

## 2.12. Преобразования в выражениях: где исчезает точность

Перед вычислением арифметики компилятор приводит операнды к подходящим типам. Это влияет и на результат, и на допустимость операции. Маленькие целые типы, например `char` и `short` на обычных платформах, часто сначала продвигаются к `int`; тип результата не обязан совпадать с типом исходной переменной.

```cpp
// 02_conversions.cpp
#include <iostream>
#include <type_traits>
int main() {
    short a = 10, b = 20;
    static_assert(std::is_same_v<decltype(a + b), int>);
    unsigned u = 1;
    int n = -1;
    std::cout << a + b << ' ' << (n < u) << '\n';
}
```

**Вывод:** `30 0`. В сравнении `int` и `unsigned int` одинакового ранга отрицательный `n` преобразуется в большое беззнаковое значение. Поэтому математическое ожидание «минус один меньше единицы» здесь не совпадает с результатом C++.

Не исправляйте предупреждения компилятора случайным приведением типа. Сначала определите, может ли значение быть отрицательным, и каков допустимый диапазон. Для сравнения знаковых и беззнаковых целых в C++20 есть `std::cmp_less` и другие функции из `<utility>`.

### Приоритет, ассоциативность и порядок вычисления

| Понятие | На какой вопрос отвечает | Пример |
|---|---|---|
| Приоритет | Как сгруппировано выражение? | `a + b * c` означает `a + (b * c)` |
| Ассоциативность | Как группируются операторы одного уровня? | `a - b - c` означает `(a - b) - c` |
| Порядок вычисления | Когда вычисляется каждый операнд? | Для встроенного `&&` левый операнд раньше правого |

Из записи `f() + g()` нельзя заключить, что `f()` обязательно выполнится раньше `g()`. Не пытайтесь предсказывать порядок по расположению функций в строке. Если порядок нужен для логики, запишите два отдельных вызова.

### Ввод как операция, которая может не удаться

После `std::cin >> value` нужно проверять состояние потока. Если пользователь ввёл текст вместо числа, использовать значение так, будто ввод точно успешен, неверно.

```cpp
// 03_input.cpp
#include <iostream>
#include <sstream>
int main() {
    std::istringstream input{"12 wrong"};
    int first{}, second{};
    if (input >> first) std::cout << first << '\n';
    if (!(input >> second)) std::cout << "input error\n";
}
```

**Вывод:** две строки: `12` и `input error`. `std::istringstream` здесь позволяет воспроизвести ошибку без ручного ввода. Правила проверки состояния такие же, как у `std::cin`.

**Проверь себя:** почему нельзя лечить любое переполнение переходом на `unsigned`? Потому что модульная арифметика может быть определена языком, но не соответствовать смыслу задачи: отрицательная разность превратится в большое положительное значение.

# Лекция 3. Память, указатели, ссылки и категории значений

## От значения к месту, где оно находится

До сих пор мы в основном передавали сами значения. Теперь представьте другую задачу: функция должна изменить уже существующую переменную вызывающего кода. Если передать ей обычную копию числа, она изменит копию. Нужен способ добраться до исходного объекта. Для этого C++ предоставляет ссылки и указатели.

```cpp
int score = 10;
int copy = score;
int& alias = score;
int* pointer = &score;

copy = 20;
alias = 30;
*pointer = 40;
```

После этих строк `copy` равно `20`, а `score` равно `40`. Объясним каждое отличие.

`copy` — самостоятельный целочисленный объект. Строка с `alias` объявляет ссылку на `score`. Символ `&` здесь входит в объявление типа `int&`: он означает, что новое имя связано с существующим объектом. Присваивание через `alias` меняет сам `score`. Нельзя позднее «перенастроить» эту ссылку на другую переменную обычным присваиванием: `alias = other` скопирует значение `other` в `score`.

Строка с `pointer` создаёт объект другого типа, `int*`. Его значение — указатель на `score`. В выражении `&score` символ `&` означает взятие адреса. А в выражении `*pointer` символ `*` означает разыменование: обращение к объекту, на который указывает указатель.

Таким образом, смысл символа определяется его местом. В объявлении `int* pointer` звёздочка помогает описать тип. В выражении `*pointer = 40` она выполняет операцию. В выражении `2 * 3` она умножает. Это не три разных магических свойства указателя, а использование одного знака в разных грамматических конструкциях.

### Указатель можно изменить, объект при этом остаётся прежним

```cpp
int first = 10;
int second = 20;
int* p = &first;
p = &second;
*p = 99;
```

После изменения `p` первый объект всё ещё существует и хранит `10`. Указатель теперь позволяет обратиться к `second`, поэтому последняя строка меняет `second` на `99`. Изменение адреса в указателе и изменение объекта по адресу — разные действия.

Указатель может иметь значение `nullptr`, означающее отсутствие объекта, на который он указывает. Так удобно обозначать необязательный результат поиска. Но `*p` при `p == nullptr` не даёт «пустой объект»: обращение через такой указатель недопустимо. Сначала требуется проверить, что объект есть. И даже ненулевой адрес ещё не доказывает, что объект жив.

### Почему адрес не продлевает жизнь объекта

```cpp
int* p = nullptr;
{
    int local = 7;
    p = &local;
}
// Объект local уже закончил жизнь.
// std::cout << *p; // недопустимое обращение
```

Указатель `p` существует снаружи блока, а `local` — только внутри. Когда выполнение выходит из блока, жизнь `local` заканчивается. В `p` может остаться прежнее значение адреса, но разрешения обращаться к прежнему объекту уже нет. Такой указатель называют висячим.

Из этого следует общее правило: хранение адреса не означает владение объектом. Указатель часто лишь позволяет временно наблюдать объект, за жизнь которого отвечает кто-то другой. Тот же риск есть у ссылки: синтаксис удобнее, но ссылка тоже может пережить объект, с которым связана.

### Массив и границы допустимого

Массив хранит несколько элементов одного типа подряд. В `int values[3]{10, 20, 30};` находятся три целых объекта. Индексы начинаются с нуля: `values[0]` — первый, `values[2]` — последний. Выражение `values[3]` уже не обозначает существующий элемент массива.

Указатель на первый элемент можно увеличивать, чтобы переходить к следующим элементам этого же массива. Прибавление единицы перемещает указатель на один элемент, а не обязательно на один байт. Можно получить указатель сразу за последним элементом и сравнивать его с другими допустимыми указателями этого массива, но разыменовывать его нельзя.

В большинстве выражений имя массива преобразуется в указатель на первый элемент. Из этого не следует, что массив и указатель — один тип. `sizeof` для самого массива учитывает все элементы, а `sizeof` для указателя измеряет только объект указателя.

### Зачем появляется динамическая память

Иногда объект должен жить дольше текущего блока либо его размер определяется во время выполнения. Выражение `new int{7}` создаёт динамический объект и возвращает указатель на него. Этот объект не исчезнет только потому, что закончился блок с переменной указателя. Его нужно уничтожить подходящей операцией `delete`.

```cpp
int* p = new int{7};
*p = 9;
delete p;
p = nullptr;
```

`delete p` завершает жизнь выделенного объекта и освобождает его память. Оно не уничтожает саму локальную переменную `p`, поэтому следующая строка может присвоить ей `nullptr`. Обнуление этого одного указателя не исправляет другие указатели, если они тоже хранили адрес освобождённого объекта.

Если потерять последний адрес до освобождения памяти, возникает утечка. Если дважды освободить один объект, программа нарушает правила. Если после освобождения обратиться к объекту, получается использование после освобождения. Именно множество таких обязанностей привело к RAII и умным указателям, которые подробно разберём в шестой лекции.

В обычной прикладной задаче динамический массив чаще следует представить как `std::vector<int>`, а единоличное владение объектом — как `std::unique_ptr<T>`. Ручные `new` и `delete` нужны здесь для понимания механизма, а не как обязательный стиль каждого решения.

### Что означают lvalue, prvalue и xvalue

Категория значения характеризует выражение. Не путайте её с типом объекта. Выражение с именем `score` позволяет обозначить конкретный существующий объект; это lvalue. Выражение `10 + 20` вычисляет новое значение; это prvalue. Выражение `std::move(score)` относится к xvalue: оно позволяет рассматривать существующий объект как источник ресурсов для возможного перемещения.

Пока достаточно двух важных выводов. Во-первых, имя переменной является lvalue даже тогда, когда переменная объявлена с типом rvalue-ссылки `T&&`. Во-вторых, `std::move` само ничего не переносит и не освобождает. Оно меняет способ рассмотрения выражения, после чего выбранный конструктор или оператор может выполнить перемещение. Реальное действие зависит от выбранной функции.

Имена категорий понадобятся для объяснения перегрузок и копирования. Сейчас важнее уверенно различать объект, самостоятельную копию, ссылку на него и указатель на него.

## 3.1. Модель памяти процесса

| Область типичной реализации | Назначение |
|---|---|
| Stack | Кадры вызовов и автоматические объекты |
| Heap | Динамически выделяемая память |
| Data/BSS | Хранение глобальных и статических объектов |
| Text | Машинный код программы |

Это условная модель реализации, а не требуемая стандартом C++ раскладка памяти. Порядок областей и направления их роста зависят от платформы.

Это **иллюстрация типичной ОС**, не гарантия стандарта C++: стандарт задаёт длительности хранения, а не обязательные физические сегменты или направления роста. `int local;` обычно размещается в стеке; `static int x;` имеет статическую длительность хранения; `new int` создаёт объект с динамической длительностью хранения. Сам **указатель** на выделенный объект может лежать в стеке, а объект — в динамической памяти.

```cpp
int global = 10;
void f() {
    int local = 20;
    int* p = new int(40);
    delete p;
}
```

## 3.2. Адрес и разыменование

```cpp
int x = 42;
int* p = &x; // p хранит адрес x
*p = 100;   // меняем объект x
// x == 100
```

Если `p = &x`, указатель `p` хранит адрес объекта `x`, а выражение `*p` обозначает сам `x`. Например, при `x == 100` чтение `*p` даёт 100.

`&x` — адрес объекта; `*p` — доступ к объекту, на который указывает `p`. `*` в объявлении (`int* p`) и в выражении (`*p`) выполняет разные роли. `nullptr` — типобезопасный нулевой указатель. **Разыменование `nullptr` — UB.**

## 3.3. Арифметика указателей и массивы

```cpp
int a[]{10, 20, 30, 40};
int* p = a;         // указывает на a[0]
int x = *(p + 2);   // 30
int y = p[3];       // 40
```

Для массива `int a[4]{10, 20, 30, 40}` при условных адресе начала 1000 и `sizeof(int) == 4`:

| Элемент | Указатель | Условный адрес | Значение |
|---|---|---|---|
| `a[0]` | `p` | 1000 | 10 |
| `a[1]` | `p + 1` | 1004 | 20 |
| `a[2]` | `p + 2` | 1008 | 30 |
| `a[3]` | `p + 3` | 1012 | 40 |

Здесь `p = a`; адреса приведены только для иллюстрации.

`p + n` сдвигается на **n элементов**, не на n байт. Допустимы адреса элементов **одного массива** и адрес «на один за концом» (`a + 4`), но разыменовывать последний нельзя. `a[2] == *(a+2) == 2[a]` (последнее синтаксически допустимо, но не рекомендуется). Разность указателей внутри массива имеет тип `std::ptrdiff_t`.

**Тонкость:** массив **не является указателем**. Во многих выражениях `a` преобразуется в указатель на первый элемент (array-to-pointer decay), но `sizeof(a)` измеряет весь массив, `&a` имеет тип `int (*)[4]`, а `a` не переназначается. В параметре `void f(int a[])` тип фактически корректируется до `int*` и размер массива теряется. В C++20 удобны `std::span<int>` и `std::array<int, N>`.

## 3.4. Четыре сочетания const

Сначала отдельно спросим: разрешено ли изменить сам адрес и разрешено ли изменить число по этому адресу? Это два независимых ограничения. В `const int* p` константным является доступное через указатель число: `*p = 5` запрещено, но `p = &other` допустимо. В `int* const p` константен сам указатель: перенаправить его нельзя, а изменить целое через него можно.

В `const int* const p` действуют оба ограничения. При этом указатель на константу может указывать на исходно изменяемый объект. Если другой допустимый способ доступа меняет этот объект, чтение через `p` увидит новое значение. Ограничение относится к пути доступа, а не обязательно ко всему существованию объекта. Если же сам объект объявлен `const`, попытка обойти запрет и изменить его уже нарушает правила.

```cpp
int x = 1, y = 2;
int* p1 = &x;              // меняем адрес и *p1
const int* p2 = &x;        // p2 можно перенаправить; *p2 менять нельзя
int* const p3 = &x;        // p3 нельзя перенаправить; *p3 менять можно
const int* const p4 = &x;  // нельзя ни перенаправить, ни менять через p4
```

| Объявление | Изменить `*p` через этот указатель? | Присвоить `p = &y`? |
|---|---|---|
| `int* p` | да | да |
| `const int* p` | нет | да |
| `int* const p` | да | нет |
| `const int* const p` | нет | нет |

`const int* p` не делает исходный объект обязательно константным: если `x` не `const`, его можно изменить другим способом. `nullptr` имеет тип `std::nullptr_t`; предпочитайте его `NULL` и `0` при работе с указателями и перегрузками. `const`-указатель (`int* const`) обязательно инициализируется.

## 3.5. new/delete и владение памятью

```cpp
int* p = new int(42);
delete p;                   // один объект
p = nullptr;               // лишь этот указатель обнулён

int* a = new int[5]{};     // массив из пяти нулей
delete[] a;                 // строго delete[]
```

`new int` без инициализатора оставляет значение неинициализированным; `new int{}` инициализирует нулём. `new` по умолчанию при неудаче бросает `std::bad_alloc`. `delete nullptr;` безопасен. `new[]` **нельзя** парно освобождать обычным `delete` и наоборот: это UB. Современная альтернатива:

```cpp
std::vector<int> v(5);                // массив переменной длины
std::unique_ptr<int> p = std::make_unique<int>(42);
```

`delete p; p = nullptr;` защищает только от повторного удаления **через p**; копии адреса в других указателях остаются висячими.

## 3.6. Ошибки памяти

| Ошибка | Пример | Почему опасно |
|---|---|---|
| **Leak** | `new int(5);` без сохранения/освобождения | потерян ресурс |
| **Dangling** | `int* p = &local;` после выхода из функции | время жизни объекта закончилось |
| **Use-after-free** | `delete p; std::cout << *p;` | обращение к уничтоженному объекту |
| **Double delete** | `delete p; delete q;` при `q == p` | повторное освобождение |
| **Out-of-bounds** | `a[5]` для `int a[5]` | выход за границу |
| **Mismatched delete** | `delete` после `new[]` | неверная пара операций |

```cpp
int* bad() {
    int x = 10;
    return &x; // адрес перестанет быть действительным после выхода
}
```

Такой код часто выдаёт предупреждение компилятора. Правильнее вернуть значение `int`, либо объект с корректно организованным временем жизни. **RAII** устраняет необходимость ручного освобождения в большинстве пользовательских классов.

## 3.7. Санитайзеры

Ошибки памяти часто не дают понятного сообщения сразу в месте нарушения. Обращение за границу может случайно попасть в доступную область и внешне «сработать». Санитайзер добавляет к собранной программе проверки некоторых таких нарушений во время выполнения. AddressSanitizer помогает искать ошибки обращений к памяти, UndefinedBehaviorSanitizer — ряд видов неопределённого поведения.

Это диагностические инструменты, а не новые правила языка. Если конкретный запуск с санитайзером ничего не сообщил, это ещё не доказывает, что все пути программы корректны. Зато сообщение часто показывает стек вызовов и место нарушения намного яснее, чем позднее аварийное завершение. Ошибочные примеры нужно сначала понимать по правилам C++, а уже затем использовать инструмент для изучения диагностики.

```bash
g++ -std=c++20 -g -O1 -fno-omit-frame-pointer \
    -fsanitize=address,undefined main.cpp -o app
./app
```

**ASan** обнаруживает многие выходы за границы, use-after-free, double-free; обнаружение утечек зависит от доступности/настройки LeakSanitizer. **UBSan** диагностирует ряд нарушений правил языка (например, некоторые переполнения и недопустимые преобразования). Ни один санитайзер **не доказывает отсутствие всех ошибок**. Для разработки полезны также `-Wall -Wextra -Wpedantic`.

## 3.8. Ссылки и алиасы

```cpp
int x = 10;
int& r = x;          // r — другое имя x
r = 20;             // x == 20
const int& cr = 42; // временный int живёт столько, сколько cr
// int& wrong = 42; // ошибка компиляции
```

Обычная ссылка должна быть инициализирована и не может быть переназначена: `r = y` **присваивает значение** объекту `x`, а не привязывает ссылку к `y`. В корректной программе ссылка должна обозначать действующий объект; при этом **висячие ссылки возможны**, если объект уже уничтожен. `const T&` может связываться с временным объектом, иногда продлевая его время жизни; правила продления зависят от контекста, и **не всякая передача временного через ссылку продлевает жизнь**.

**Передача параметров:** `f(T)` — копия/перемещение, `f(T&)` — изменение исходного объекта, `f(const T&)` — чтение без копии и связывание с временными, `f(T*)` — допускается `nullptr` и явная семантика адреса.

## 3.9. Категории значений: lvalue, prvalue, xvalue

| Категория | Входит в группы | Примеры |
|---|---|---|
| lvalue | glvalue | `x`, `*p` |
| xvalue | glvalue и rvalue | `std::move(x)` |
| prvalue | rvalue | `42`, `x + 1` |

Это **категории выражений**, а не типы переменных. `lvalue`: `x`, `*p`, `a[0]`, `++x` для встроенного `int`. `prvalue`: `42`, `x+1`, `std::string{}`, `&x`. `xvalue`: `std::move(x)`, `static_cast<T&&>(x)`. `std::move` **ничего не перемещает само по себе** — это приведение к rvalue-ссылке; реальное перемещение делает соответствующий конструктор/оператор. Именованная переменная типа `T&&` при использовании по имени является **lvalue**.

```cpp
std::string s = "hello";
std::string t = std::move(s); // может вызвать move-конструктор
// s остаётся корректным, но его содержимое после move не определено заранее
```

## 3.10. Именованные приведения

Приведение типа выражает явное намерение рассмотреть значение иначе. Но под этим общим словом скрываются разные задачи. Преобразовать число в другой числовой тип, проверить фактический тип полиморфного объекта и снять ограничение константности — разные операции с разными условиями корректности. Поэтому C++ предоставляет несколько именованных форм.

`static_cast<double>(sum)` делает числовое преобразование явным. `dynamic_cast` позволяет, в частности, проверить некоторые переходы внутри полиморфной иерархии: неудачный проверяемый переход указателя даёт `nullptr`, а соответствующий неудачный переход ссылки бросает `std::bad_cast`. `const_cast` меняет квалификаторы доступа, но не даёт права изменять исходно константный объект. `reinterpret_cast` относится к низкоуровневому переосмыслению; возможность получить указатель не означает, что через него разрешено обращаться к произвольному объекту.

Увидев приведение, задайте вопрос: какую гарантию оно действительно даёт? Большинство приведений не проверяют диапазон автоматически, не создают недостающий объект и не продлевают время жизни.

- `static_cast<T>(x)` — проверяемые на этапе компиляции допустимые преобразования, но **не гарантия отсутствия потери данных**.
- `const_cast<T>(x)` — изменение cv-квалификации; попытка изменить **изначально const** объект через снятый `const` — UB.
- `dynamic_cast<T>(x)` — проверяемое во время выполнения приведение в полиморфной иерархии (для указателя неудача → `nullptr`, для ссылки — `std::bad_cast`).
- `reinterpret_cast<T>(x)` — низкоуровневая интерпретация представления; не делает доступ к произвольному объекту безопасным.

**Задание:** `int a[3]{1,2,3}; int* p=a+3;` — создание `p` допустимо; `*p` — UB. `p-a` равно `3`.

## 3.11. Разбор: объект, ссылка, указатель и время жизни

Ссылка не владеет объектом и не продлевает жизнь произвольного объекта автоматически. Её корректность зависит от того, существует ли объект, к которому она привязана.

```cpp
#include <iostream>
int main() {
    int x = 7;
    int copy = x;
    int& alias = x;
    int* ptr = &x;
    alias = 9;
    std::cout << x << ' ' << copy << ' ' << *ptr; // 9 7 9
}
```

`copy` — отдельный объект, `alias` — другое имя `x`, `ptr` — отдельный объект-указатель, который хранит адрес `x`. `delete ptr` здесь недопустим: `x` не создан через `new`. При разборе всегда отдельно отвечайте: кто владеет ресурсом, кто лишь обращается к нему и когда заканчивается его время жизни.

## 3.12. Владение и доступ: разные обязанности

У объекта может быть один владелец и несколько наблюдателей. Владелец отвечает за время жизни ресурса. Наблюдатель получает доступ, но не должен освобождать ресурс и не может продолжать доступ после его уничтожения.

| Запись | Типичная роль | Что нужно проверить |
|---|---|---|
| `T value;` | Самостоятельный объект | Область видимости и порядок уничтожения |
| `T& ref = value;` | Наблюдение или изменение существующего объекта | Не переживёт ли ссылка объект |
| `T* ptr = &value;` | Невладеющий адрес | Может ли быть `nullptr`, действителен ли адрес |
| `std::unique_ptr<T>` | Исключительное владение | Когда владение передаётся или сбрасывается |
| `std::vector<T>` | Владение последовательностью элементов | Какие операции инвалидируют адреса элементов |

Это соглашения проектирования: тип `T*` сам по себе не сообщает, владеет ли он памятью. Поэтому в интерфейсе с сырым указателем нужно явно понимать контракт. `delete` применяют к подходящему указателю на динамически выделенный объект, а не к любому имеющемуся адресу.

```cpp
// 04_ownership.cpp
#include <iostream>
#include <memory>
int main() {
    auto owner = std::make_unique<int>(7);
    int* observer = owner.get();
    *observer = 9;
    std::cout << *owner << '\n';
    owner.reset();
    // observer теперь висячий: не разыменовываем его
    observer = nullptr;
}
```

**Вывод:** `9`. `get()` не передаёт владение. `reset()` уничтожает принадлежащий объект. Присваивание `nullptr` наблюдателю не освобождает память и не исправляет другие возможные висячие указатели, но запрещает случайно использовать прежний адрес через это имя.

## 3.13. Ссылки и указатели на элементы контейнера

Нельзя считать адрес элемента `std::vector` постоянным на всё время жизни контейнера. При увеличении размера вектор может выделить новый блок памяти и перенести элементы. Тогда прежние ссылки, указатели и итераторы на элементы инвалидируются.

```cpp
std::vector<int> values{10};
int* p = &values[0];
values.reserve(values.capacity() + 1); // нужна большая ёмкость: перераспределение
// std::cout << *p;                   // старый p больше использовать нельзя
p = &values[0];                       // получаем актуальный адрес заново
```

`size()` — число существующих элементов, `capacity()` — сколько элементов помещается до следующего необходимого перераспределения. После `reserve(100)` размер не становится 100: индексировать несуществующие элементы по-прежнему нельзя.

```cpp
std::vector<int> a;
a.reserve(10);  // size == 0
// a[0] = 1;  // UB: элемент не создан
a.resize(10);   // size == 10; новые int равны 0
a[0] = 1;      // теперь допустимо
```

**На контрольной:** при каждом изменении контейнера отдельно спрашивайте, сохранились ли ранее полученные адреса. Для `push_back` перераспределение происходит не всегда, поэтому пример без информации о ёмкости иногда нельзя разобрать одним точным предположением.

## 3.14. Время жизни нельзя определить только по типу ссылки

`const T&` умеет связываться с временным, но не делает безопасной любую цепочку возвращаемых ссылок.

```cpp
const std::string& pass(const std::string& s) { return s; }
// const std::string& bad = pass(std::string{"hello"});
// После этой строки временная строка уже уничтожена: bad — висячая ссылка.
```

Временная строка живёт до конца полного выражения с вызовом `pass`, то есть до соответствующей точки с запятой. Возврат ссылки из функции не продлевает её жизнь до конца жизни переменной `bad`.

Сравните с `const std::string& good = std::string{"hello"};`: здесь непосредственное связывание продлевает время жизни временного до времени жизни ссылки в данном объявлении. Для безопасного результата функции часто лучше вернуть `std::string` по значению.

**Самопроверка:** выражения `*p`, `array[i]` и имя переменной `int&& r` являются lvalue в обычных рассматриваемых случаях; `std::move(r)` — xvalue. Категория выражения не говорит, жив ли объект: висячую ссылку можно иметь и при синтаксически корректном lvalue-выражении.

# Лекция 4. Функции и разрешение перегрузки

## Как выделить действие и точно описать его вход и выход

Когда одна формула встречается несколько раз, копировать её по программе неудобно. Ошибку придётся исправлять в каждом месте. Функция даёт действию имя и описывает, какие данные ему нужны и какой результат оно возвращает.

```cpp
#include <iostream>

int square(int value) {
    return value * value;
}

int main() {
    int number = 4;
    int result = square(number);
    std::cout << result << ' ' << number << '\n';
}
```

Программа выводит `16 4`. Вызов `square(number)` создаёт параметр `value`, инициализируя его значением `number`. В теле функции умножаются два значения параметра. `return` передаёт результат вызывающему коду, после чего вызов заканчивается. Полученным результатом инициализируется `result`.

Имя `value` существует внутри функции, имя `number` — внутри `main`. Функция не получает доступ к исходной переменной по сходству смысла или имени. Она работает с тем, что предусмотрено её параметрами. Поэтому изменение обычного параметра `int value` не меняет `number`.

### Три разных договора с вызывающим кодом

```cpp
void change_copy(int value) {
    value = 100;
}

void change_original(int& value) {
    value = 100;
}
```

У первой функции собственная копия числа. У второй параметр связан с исходным объектом. Если выполнить `change_original(number)`, изменится `number`. Обе записи полезны: выбор зависит от назначения функции.

Если функции нужна большая строка только для чтения, часто используют `const std::string& text`. Ссылка позволяет избежать обязательного создания отдельной копии строки, а `const` запрещает изменять её через этот параметр. Это договор: «дайте доступ к существующей строке, я не буду менять её таким способом».

Указатель `T*` удобно использовать, когда допустимо отсутствие объекта или требуется явно работать с адресами. Тогда функция должна учитывать `nullptr`. Ссылка `T&` обычно выражает обязательное наличие объекта, но вызывающий код всё равно обязан предоставить живой объект.

### Возврат результата и его время жизни

Начинающий иногда боится возвращать большой объект по значению и пытается вернуть ссылку на локальную переменную. Это разрушает корректность: локальная переменная закончится вместе с вызовом, а ссылка останется без живого объекта.

```cpp
#include <string>

std::string make_name() {
    std::string name = "Student";
    return name;
}
```

Здесь возврат по значению корректен. Результат функции является самостоятельным объектом. Реализация может применить NRVO и построить `name` сразу в месте результата; если это устранение копирования не применяется, для подходящего типа может использоваться перемещение. Нельзя объяснять корректность этого кода предположением, что локальная строка «просто не уничтожается». Корректность даёт семантика возврата значения.

### Почему у функций бывает одинаковое имя

Можно определить `print(int)` и `print(double)`. Они образуют набор перегрузок: одно понятное действие поддерживает разные типы данных. При вызове компилятор рассматривает кандидатов и допустимые преобразования аргументов. Выбор происходит по статическим типам выражений в месте вызова.

Если вызвать `print(5)`, точное соответствие `int` обычно лучше преобразования в `double`. Если доступен только `print(double)`, число может быть преобразовано. В более сложном наборе две функции могут оказаться одинаково хорошими, и тогда вызов неоднозначен. Компилятор не выбирает «первую сверху».

Возвращаемого типа недостаточно для создания двух обычных перегрузок с одинаковыми параметрами: `int get()` и `double get()` нельзя различить только по тому, куда затем сохраняется результат. Сам вызов `get()` уже должен иметь однозначный смысл.

### Аргумент по умолчанию не означает новый параметр

В объявлении `void repeat(int count = 1);` параметр один. Запись `repeat()` позволяет компилятору подставить указанное значение вместо отсутствующего аргумента. Запись `repeat(3)` передаёт явное значение. Это удобство в месте вызова, а не отдельная функция, тайно читающая значение в момент выполнения.

Поэтому добавление значений по умолчанию может сделать перегрузки неоднозначными. Если есть `f(int)` и `f(int, int = 0)`, вызову `f(1)` подходят обе. Удобство записи не отменяет необходимость однозначного выбора.

### Когда действие само становится данными

Иногда алгоритму нужно передать не число, а способ действия: например, правило сравнения элементов. Указатель на функцию позволяет хранить адрес подходящей функции. Лямбда позволяет определить небольшое действие прямо в месте использования.

```cpp
auto greater_than_ten = [](int value) {
    return value > 10;
};
bool result = greater_than_ten(12); // true
```

Здесь `[]` начинает лямбду, `(int value)` описывает параметр, а тело возвращает результат сравнения. В переменной хранится объект, который можно вызвать как функцию. Если лямбда использует внешние переменные, нужно разобраться с захватом: копирование значения и сохранение ссылки дают разные требования ко времени жизни. Ссылка на уже умершую локальную переменную останется опасной и внутри лямбды.

### Рекурсия — обычный вызов с условием остановки

Функция может вызвать сама себя. Например, вычисление факториала положительного числа можно свести к умножению числа на факториал предыдущего. Каждый вызов получает свои параметры и локальные объекты. Поэтому рекурсия не означает, что одна переменная автоматически меняет значение во всех вызовах.

Нужен базовый случай: условие, при котором новый вызов уже не требуется. Также нужно доказать, что последовательность вызовов к нему приближается. Без этого программа будет наращивать незавершённые вызовы, пока не исчерпает доступные ресурсы. Даже с правильной остановкой следует учитывать переполнение числового типа.

### Переходим к подробным правилам и примерам

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 4.1. Объявление, определение, сигнатура

```cpp
int sum(int a, int b);                 // объявление
int sum(int a, int b) { return a+b; } // определение
```

Имя и типы параметров участвуют в перегрузке. **Нельзя перегружать только по возвращаемому типу**:

```cpp
int f(int);
// double f(int); // конфликт
```

При объявлении функции можно не указывать имена параметров, но в определении они нужны, если используются в теле.

## 4.2. Способы передачи аргументов

```cpp
void byValue(int x) { ++x; }   // копия
void byRef(int& x) { ++x; }    // изменяет исходный объект
void byConstRef(const std::string& s) { std::cout << s; }
void byPointer(int* p) { if (p) ++*p; }
```

Выбирайте по значению для маленьких скаляров, `const T&` для больших объектов без необходимости копирования, `T&` для обязательного изменяемого объекта, `T*` если допустимо отсутствие объекта. Для передачи владения подходят `std::unique_ptr` и другие явные интерфейсы владения. Нельзя возвращать ссылку/указатель на локальный объект с автоматическим хранением.

## 4.3. Перегрузка функций

```cpp
void print(int);
void print(double);
void print(const std::string&);
print(3);     // int
print(3.14);  // double
```

Компилятор: (1) находит кандидатов; (2) отбирает жизнеспособные; (3) сравнивает последовательности преобразований; (4) выбирает лучшую или сообщает неоднозначность. Упрощённая иерархия: **точное совпадение > promotion > conversion > пользовательское преобразование**. Но полный алгоритм сложнее, учитывает ссылки, шаблоны, квалификаторы и другие правила.

```cpp
void f(long);
void f(double);
// f(1); // неоднозначно: int -> long и int -> double — conversions
```

**Тонкость:** `const` для параметра **по значению** не образует новую перегрузку: `void f(int)` и `void f(const int)` — одна сигнатура функции. Для ссылок `void f(int&)` и `void f(const int&)` — разные перегрузки.

## 4.4. Разрешение перегрузки: const, ссылки, временные

```cpp
void show(int&);       // изменяемое lvalue
void show(const int&); // const lvalue и rvalue
void show(int&&);      // rvalue

int x = 1;
show(x);            // int&
show(std::move(x)); // int&&
show(42);           // int&&
const int y = 2;
show(y);            // const int&
```

Для объекта класса перегрузки `f() &`, `f() const&`, `f() &&` могут различать категорию и константность объекта. **Результат разрешения определяется типами и категориями выражений**, а не только текстом аргумента.

## 4.5. Аргументы по умолчанию

```cpp
void log(std::string msg, int level = 1);
log("start"); // эквивалентно log("start", 1)
```

Аргументы по умолчанию задаются обычно в объявлении, а не повторяются в определении. После первого параметра с умолчанием следующие параметры в той же области объявления должны иметь умолчания (с учётом ранее видимых объявлений). Умолчания **не входят в тип функции** и могут приводить к неоднозначности:

```cpp
void f(int);
void f(int, int = 0);
// f(1); // неоднозначно
```

## 4.6. inline, constexpr, consteval

Эти три слова относятся к разным вопросам. Историческое название `inline` легко понять неправильно: оно не приказывает обязательно вставить тело функции вместо вызова. Для устройства программы важнее специальные правила определений, благодаря которым подходящую `inline`-функцию можно определять в заголовке и включать его в разные единицы трансляции.

`constexpr` у функции означает возможность использования в константном вычислении при соблюдении необходимых условий. Один и тот же вызов такой функции может вычисляться во время работы, если аргументы становятся известны только тогда. `consteval` задаёт немедленную функцию: её соответствующие вызовы должны давать константное вычисление. Поэтому «можно вычислить заранее» и «требуется вычислить заранее» — разные обещания.

`inline` позволяет иметь идентичное определение функции в нескольких единицах трансляции (например, в заголовке), но **не гарантирует** встраивания машинного кода. `constexpr` разрешает вычисление при компиляции, когда выполнены условия constant evaluation; функцию можно вызвать и во время выполнения. `consteval` (C++20) требует, чтобы вызов был пригоден для вычисления в константном выражении.

```cpp
constexpr int sq(int x) { return x*x; }
constexpr int a = sq(4); // compile-time: 16
int n; std::cin >> n;
int b = sq(n);           // runtime допустим
consteval int cube(int x) { return x*x*x; }
constexpr int c = cube(3);
// int d = cube(n); // ошибка
```

## 4.7. RVO, NRVO, возврат по значению

```cpp
std::string make() {
    return std::string("hello"); // гарантированное устранение копии в C++17+
}
std::string make2() {
    std::string s = "hello";
    return s; // NRVO разрешён, но не гарантирован
}
```

**RVO / guaranteed copy elision:** для подходящих prvalue возвращаемый объект конструируется сразу в месте назначения; наличие копирующего/move-конструктора может быть не нужно, хотя деструктор должен быть доступен и не удалён. **NRVO:** возврат именованной локальной переменной, оптимизация обычно применяется, но не гарантируется. Если NRVO не выполнен, язык предусматривает правила попытки перемещения из подходящей локальной переменной.

**Ошибка:** `return std::move(s);` в `make2()` часто **мешает NRVO**. Не добавляйте `std::move` к каждому `return` автоматически.

## 4.8. Указатели на функции, std::function, лямбды

```cpp
int add(int a, int b) { return a+b; }
int (*pf)(int,int) = &add;
int x = pf(2,3); // 5

std::function<int(int,int)> op = add;
auto twice = [](int x) { return 2*x; };
```

Указатель на функцию хранит адрес обычной функции с подходящей сигнатурой. `std::function` (заголовок `<functional>`) — типостёртая оболочка для вызываемых объектов, часто с дополнительными затратами. Лямбда `[&]` захватывает используемые переменные по ссылке, `[=]` — по значению, `[x]` — конкретную переменную по значению. **Захват по ссылке опасен**, если лямбда живёт дольше захваченной локальной переменной.

## 4.9. Рекурсия

```cpp
int factorial(int n) {
    if (n < 0) throw std::invalid_argument("negative");
    if (n <= 1) return 1;         // базовый случай
    return n * factorial(n-1);   // рекурсивный шаг
}
```

У рекурсии должны быть базовый случай и движение к нему. Каждый вызов обычно добавляет кадр стека; слишком глубокая рекурсия может исчерпать стек. `factorial` на `int` быстро переполняется, даже если сама рекурсия логически правильна. Для больших `n` используйте другой тип/алгоритм и проверяйте диапазон.

## 4.10. ADL — Argument-Dependent Lookup

Когда мы пишем `Geometry::draw(p)`, место поиска указано явно. Но запись `draw(p)` иногда тоже работает, даже если обычный поиск не видел такую функцию напрямую. Язык учитывает тип аргумента `p` и связанные с ним пространства имён. Так свободная функция, определённая рядом с пользовательским типом, может естественно участвовать в операциях над ним.

Эта идея помогает объяснить и `std::cout << point`: операторная запись позволяет найти подходящую свободную функцию для пользовательского типа. Чтобы понимать ADL, не нужно представлять глобальный поиск по всем подключённым библиотекам. Поиск ограничен правилами языка и связанными сущностями.

```cpp
namespace Geometry {
    struct Point { int x; };
    void draw(const Point&) { std::cout << "point\n"; }
}
int main() {
    Geometry::Point p{1};
    draw(p); // ADL найдёт Geometry::draw
}
```

Кроме обычного поиска имён, компилятор ищет подходящие свободные функции в пространствах имён, **ассоциированных с типами аргументов**. Поэтому `operator<<`, `swap` и свободные операторы часто определяют в пространстве имён своего типа. ADL не является универсальным поиском всех функций по всему проекту.

## 4.11. Разбор: как выбирать способ передачи параметра

Передача по значению создаёт отдельный параметр. Передача по ссылке позволяет обратиться к исходному объекту; `const T&` запрещает его обычное изменение через эту ссылку.

```cpp
#include <iostream>
#include <string>
void rename(std::string& s) { s = "new"; }
std::size_t length(const std::string& s) { return s.size(); }
int main() {
    std::string name = "old";
    rename(name);
    std::cout << name << ' ' << length(name); // new 3
}
```

Для небольшого `int` обычно подходит значение; для чтения большой строки — `const std::string&`; для изменения аргумента — `std::string&`. Само наличие `const T&` не делает объект владельцем ресурса и не разрешает сохранить ссылку на временный аргумент для использования после окончания его времени жизни.

## 4.12. Разрешение перегрузки: последовательность рассуждения

Не выбирайте функцию по принципу «эта выглядит подходящей». Сначала найдите объявления с нужным именем; затем оставьте применимые кандидаты; затем сравните качество преобразований аргументов. Проверка доступа не служит способом автоматически перейти к «второй лучшей» закрытой перегрузке.

Для простых примеров используйте такую шкалу: точное совпадение лучше продвижения, продвижение лучше обычного стандартного преобразования. Пользовательское преобразование обычно хуже подходящего стандартного. В сложном случае нельзя сравнивать только один аргумент: может не существовать единственного лучшего кандидата сразу по всем параметрам.

```cpp
void f(int, double);
void f(double, int);
// f(1, 1); // ошибка: первый кандидат лучше по первому аргументу,
            // второй — по второму; единственного лучшего нет
```

Значения аргументов по умолчанию позволяют вызвать функцию с меньшим числом явно записанных аргументов, но не становятся частью её типа и не создают новую функцию.

```cpp
void print(int value, int width = 4);
// print(7) означает вызов той же функции print с двумя аргументами
```

### Передача ссылки не равна перемещению

```cpp
void inspect(std::string&& value) {
    // value — ссылка на объект вызывающего кода или временный объект
    // ресурс никуда не передан, пока не выполнена соответствующая операция
}
```

Функция может принять `T&&` и вообще не переместить объект. И наоборот, чтобы сконструировать своё поле из именованного параметра `T&&`, обычно нужно `std::move(value)`, поскольку имя параметра — lvalue.

## 4.13. Возврат из функции: значение, ссылка или указатель

| Возврат | Когда подходит | Основной риск |
|---|---|---|
| `T` | Создание самостоятельного результата | Продумать стоимость и доступность copy/move |
| `T&` | Доступ к существующему изменяемому объекту | Вернуть ссылку на уже уничтоженный объект |
| `const T&` | Чтение существующего объекта без копии | Источник должен жить достаточно долго |
| `T*` | Невладеющий доступ, иногда с отсутствием результата | `nullptr`, висячий адрес, неясное владение |

```cpp
// 05_return.cpp
#include <iostream>
#include <string>
std::string makeName() {
    return std::string{"Ada"};
}
int main() {
    std::string name = makeName();
    std::cout << name << '\n';
}
```

**Вывод:** `Ada`. В C++20 подходящий prvalue `std::string{"Ada"}` создаёт результат без промежуточного обязательного копирования. Не заменяйте возврат по значению ссылкой на локальный объект «для ускорения»: это сделает корректную функцию опасной.

`inline` не обещает встраивания машинного кода, `constexpr` не обещает вычисления каждого вызова на этапе компиляции, а `std::move` не обещает реального перемещения. Эти три термина часто ошибочно понимают как команды оптимизатору; у каждого есть собственные правила языка.

# Лекция 5. Классы и инкапсуляция

## Почему отдельных переменных становится недостаточно

Допустим, у нас есть учебный курс: его название и список оценок. Можно завести строку `title` и вектор `grades`. Но если таких курсов двадцать, придётся постоянно помнить, какие данные относятся друг к другу и какие операции над ними допустимы. Класс объединяет состояние и правила работы с ним в один пользовательский тип.

```cpp
#include <iostream>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>

class Course {
private:
    std::string title_;
    std::vector<int> grades_;

public:
    explicit Course(std::string title)
        : title_(std::move(title)) {
    }

    void add_grade(int grade) {
        if (grade < 2 || grade > 5) {
            throw std::invalid_argument("Grade must be from 2 to 5");
        }
        grades_.push_back(grade);
    }

    double average() const {
        if (grades_.empty()) {
            throw std::logic_error("No grades");
        }
        double sum = 0.0;
        for (int grade : grades_) {
            sum += grade;
        }
        return sum / static_cast<double>(grades_.size());
    }

    const std::string& title() const {
        return title_;
    }
};

int main() {
    Course course{"C++"};
    course.add_grade(4);
    course.add_grade(5);
    std::cout << course.title() << ": " << course.average() << '\n';
}
```

Эта программа выводит `C++: 4.5`. Впервые код достаточно велик, поэтому разберём не только строки, но и причины устройства.

### Класс — описание типа, объект — конкретный экземпляр

`class Course { ... };` определяет тип. Само это определение не создаёт учебный курс с конкретными оценками. Внутри `main` строка `Course course{"C++"};` создаёт объект этого типа. Если объявить второй объект, у него будет собственное название и собственный вектор оценок.

`title_` и `grades_` называются полями, или нестатическими членами данных. Знак подчёркивания в конце — выбранное соглашение об именовании, а не специальный синтаксис C++. Он помогает отличать поле `title_` от параметра `title`.

`add_grade`, `average` и `title` — функции-члены, часто называемые методами. Вызов `course.add_grade(4)` означает выполнение действия именно над объектом `course`. Точка связывает имя объекта с его членом.

### Конструктор устанавливает начальное состояние

Функция с именем `Course` и без возвращаемого типа — конструктор. Он вызывается при создании объекта. Часть `: title_(std::move(title))` инициализирует поле перед входом в тело конструктора. Вектор `grades_` не указан в списке и здесь создаётся пустым своим конструктором по умолчанию.

Параметр `title` — самостоятельная строка. Мы передаём её содержимое в поле, используя возможность перемещения. Это не обязательное условие для понимания класса: запись с копированием тоже могла бы быть корректной. Подробный смысл перемещения будет разобран отдельно; сейчас достаточно видеть, что поле получает собственную строку.

`explicit` ограничивает неявное использование этого конструктора для преобразований. Мы хотим создавать курс осознанно. Курс — самостоятельное понятие, и не всякое место, где существует название, должно автоматически считаться курсом.

### private нужен для сохранения правил

Если открыть вектор всем, внешний код сможет записать туда оценку `100`. Смысл операции `add_grade` тогда теряется: проверку можно обойти прямым доступом. `private` закрывает поля от обычного внешнего обращения, а `public` оставляет доступными разрешённые действия.

Правило «каждая сохранённая оценка находится от 2 до 5» — **инвариант** класса. Оно должно оставаться верным после завершения разрешённых операций. Метод сначала проверяет аргумент, а потом меняет состояние. Если оценка недопустима, `throw` сообщает об ошибке через исключение, и добавление не происходит.

Исключение передаёт управление подходящему обработчику `catch`, если он есть. В демонстрационном `main` мы передаём только корректные оценки. Если исключение выйдет из `main` необработанным, нормальное продолжение программы не состоится. Позже разберём, как при таком выходе освобождаются ресурсы.

Инкапсуляция поэтому означает больше, чем наличие `private`. Если сделать метод `set_grades`, без проверки принимающий произвольный вектор, запрет легко обойти через этот метод. Настоящий вопрос звучит так: может ли разрешённая операция оставить объект в бессмысленном состоянии?

### Как метод узнаёт, с каким объектом работает

В нестатическом методе доступен указатель `this`. Когда выполняется `course.add_grade(4)`, он указывает на `course`. Обращение `grades_` внутри метода можно понимать как `this->grades_`. Благодаря этому одна реализация метода обслуживает много объектов, а данные выбираются по конкретному вызову.

Метод `average() const` обещает не изменять обычное состояние объекта через `this`. Это позволяет вызвать его для `const Course`. Метод добавления оценки такого обещания не делает, потому что действительно меняет вектор. `const` после круглых скобок относится к объекту, для которого вызван метод, а не к типу результата.

### Почему title возвращает ссылку

Возвращение `const std::string&` позволяет прочитать существующее название без обязательной копии строки и запрещает менять его через полученную ссылку. Но такая ссылка остаётся пригодной только пока жив соответствующий объект и его строковый подобъект. Если сохранить ссылку, а затем уничтожить курс, она станет висячей.

Возврат строки по значению даёт независимый результат и часто проще для пользователя интерфейса. Выбор требует учитывать размер данных, стоимость копирования и время жизни. Нельзя механически объявлять каждую возвращаемую величину ссылкой «для скорости».

### Чем struct отличается от class

Оба ключевых слова позволяют определять типы с полями, методами и конструкторами. Основное различие — доступ по умолчанию: у `struct` члены открыты, у `class` закрыты. Есть также соответствующее различие для доступа при наследовании по умолчанию.

Часто `struct` используют для простой группы данных, а `class` — для типа с правилами использования. Это соглашение помогает читателю, но само по себе не добавляет и не убирает возможности языка.

### Когда член принадлежит всему классу

Обычное поле есть отдельно у каждого объекта. Статический член связан с классом, а не с одним его экземпляром. Например, `inline static int created = 0;` задаёт общий счётчик. Статический метод не получает `this`: чтобы обратиться к обычному полю, ему нужен явно указанный объект.

Общий счётчик требует продуманного смысла. Считать когда-либо созданные объекты и считать живые объекты — разные задачи. Для живых нужно учитывать не только обычный конструктор, но и копирование, перемещение и разрушение. Это хороший пример того, почему отдельный факт о `static` становится понятным лишь внутри модели жизни объектов.

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 5.1. struct vs class

Единственные языковые различия: для `struct` **доступ по умолчанию `public`** и **наследование по умолчанию `public`**; для `class` оба по умолчанию `private`. Оба могут иметь конструкторы, деструкторы, виртуальные методы, шаблоны и перегрузки.

```cpp
struct Point { int x, y; }; // public
class Counter { int value_; }; // private
```

## 5.2. Поля и методы: внутри и снаружи

```cpp
class Rectangle {
    double width_ = 1.0;
    double height_ = 1.0;
public:
    double area() const;           // объявление
    void resize(double w, double h) { width_ = w; height_ = h; }
};
double Rectangle::area() const { return width_ * height_; }
```

Поля принадлежат конкретному объекту (кроме `static`). Методы получают неявный параметр объекта; определение вне класса требует `ClassName::`. В C++20 неявный объект традиционно доступен через `this`.

## 5.3. public, protected, private

- `public`: доступен клиентскому коду.
- `protected`: доступен самому классу, друзьям и определённым образом производным классам.
- `private`: доступен методам и друзьям **своего** класса, но не напрямую наследникам.

Инкапсуляция — не просто «сделать всё private», а защитить **инварианты**: например, ширина прямоугольника не должна становиться отрицательной.

```cpp
class Account {
    int balance_ = 0;
public:
    explicit Account(int initial) : balance_(initial) {
        if (initial < 0) throw std::invalid_argument("negative");
    }
    int balance() const { return balance_; }
    void deposit(int amount) {
        if (amount <= 0) throw std::invalid_argument("amount");
        balance_ += amount; // в реальном коде ещё проверяют переполнение
    }
};
```

## 5.4. this и fluent interface

`this` — prvalue-выражение с указателем на текущий объект. В обычном неконстантном методе класса `T` его тип — `T*`, в `const`-методе — `const T*`. Само выражение `this` не является изменяемым lvalue, поэтому присвоить ему другой адрес нельзя. Называть его тип `T* const` неточно: запрет присваивания здесь связан с категорией выражения, а не с верхнеуровневым `const`.

```cpp
class Builder {
    int x_{};
public:
    Builder& setX(int x) {
        this->x_ = x;
        return *this; // цепочка вызовов
    }
};
Builder b;
b.setX(1).setX(2);
```

`this->x_` нужен, когда имя параметра перекрывает имя поля, а в некоторых шаблонных случаях — для поиска имён зависимых базовых классов.

## 5.5. const-методы и mutable

```cpp
class Sensor {
    int value_ = 10;
    mutable int reads_ = 0;
public:
    int get() const { ++reads_; return value_; }
};
```

`int get() const` не позволяет менять обычные нестатические поля через этот объект. `mutable` разрешает менять **конкретное поле** даже в `const`-методе, например счётчик чтений или кеш. Это не делает операцию потокобезопасной: при многопоточном доступе потребуется синхронизация. Перегрузка по `const`:

```cpp
class Box {
    int x_{};
public:
    int& get() { return x_; }
    const int& get() const { return x_; }
};
```

## 5.6. Статические поля и методы

```cpp
class Counter {
    inline static int count_ = 0; // C++17+, определение в классе
public:
    Counter() { ++count_; }
    static int count() { return count_; }
};
```

`static`-поле общее для всех объектов класса; `static`-метод **не имеет `this`** и не может непосредственно обращаться к нестатическим полям без объекта. `inline static` удобен для определения поля в заголовке. Счётчик живых объектов должен учитывать также копирование и уничтожение, иначе он будет неверным.

## 5.7. friend: функции и классы

Закрытый доступ означает, что обычный внешний код не может обращаться к полям напрямую. Иногда конкретной свободной функции нужен такой доступ: например, оператор вывода должен получить координаты. Объявление `friend` предоставляет доступ выбранной функции или классу, сохраняя запрет для остального кода.

Дружба не превращает свободную функцию в метод и не создаёт у неё `this`. Также она не распространяется автоматически на друзей друга и не становится взаимной. Если тип `A` объявил `B` другом, это само по себе не разрешает `A` обращаться к закрытым членам `B`.

Использовать `friend` стоит как часть интерфейса сотрудничества типов. Если приходится объявлять другом почти весь проект, нужно проверить, удачно ли проведены границы ответственности.

```cpp
class Secret {
    int value_ = 7;
    friend int reveal(const Secret& s);
};
int reveal(const Secret& s) { return s.value_; }
```

`friend` даёт выбранной функции или классу доступ к закрытым членам, но **не делает её методом**. Дружба **не транзитивна**, **не наследуется** и не обязана быть взаимной. Используйте её для тесно связанных операций, например свободного `operator<<`, не для обхода архитектуры.

## 5.8. Вложенные классы и enum class

Вложенный тип позволяет показать принадлежность понятия: например, `Course::Status` относится к курсу. Это организация имён и доступа, а не автоматическое создание скрытого объекта внешнего класса. Чтобы вложенный объект работал с конкретным курсом, соответствующую ссылку или указатель нужно передать явно.

`enum class` задаёт ограниченный набор именованных значений, например `Status::active` и `Status::finished`. Это полезнее неясных чисел `0` и `1`: вызов с понятным именем проще прочитать. Кроме того, разные scoped-перечисления не смешиваются неявно как обычные числа. Если статус и оценка случайно представлены одним `int`, компилятор не всегда сможет отличить их назначение; отдельные типы помогают выразить смысл.

```cpp
class Graph {
public:
    struct Node { int id; };
    enum class Color { Red, Green, Blue };
};
Graph::Node n{1};
Graph::Color c = Graph::Color::Red;
```

Вложенный тип имеет собственное имя внутри области видимости класса. `enum class` — строго типизированное перечисление, его элементы квалифицируются (`Color::Red`), не превращаются неявно в `int`; при необходимости `static_cast<int>(c)`.

## 5.9. sizeof, alignment, padding

Поля класса занимают память, но объект не обязан иметь размер, точно равный сумме их размеров. У типов есть требования выравнивания: некоторые объекты должны начинаться по адресам с определённой кратностью. Для соблюдения этих требований реализация может оставлять промежутки между полями и в конце объекта.

Например, после маленького символьного поля перед более строго выровненным целым может появиться незанятый промежуток. Концевое дополнение позволяет следующему элементу массива таких объектов тоже начинаться с допустимого адреса. Поэтому нельзя считать точную раскладку универсальной для всех платформ и компиляторов.

`sizeof` измеряет сам объект, но не всю память, которой он владеет косвенно. Размер объекта `std::vector<int>` не растёт вместе с каждым добавленным элементом: элементы обычно размещаются в отдельном буфере. Это различие особенно важно, когда оценивают потребление памяти контейнером.

```cpp
struct Example {
    char a;
    int b;
    char c;
};
```

При типичных `sizeof(int) == 4`, `alignof(int) == 4` и однобайтовом `char` раскладка может быть такой:

| Часть объекта | Размер в байтах |
|---|---|
| `a` | 1 |
| Padding перед `b` | 3 |
| `b` | 4 |
| `c` | 1 |
| Padding в конце | 3 |

Итого часто 12 байт; стандарт не гарантирует именно такую раскладку.

`alignof(T)` — требуемое выравнивание типа. Компилятор может добавлять промежуточные и хвостовые байты padding. Порядок объявления полей влияет на размер; перестановка полей иногда уменьшает padding. `sizeof(empty class)` **не равен нулю** (обычно 1), чтобы разные полные объекты могли иметь различимые адреса. В C++20 есть `[[no_unique_address]]`, позволяющий оптимизировать размещение некоторых полей.

## 5.10. Инкапсуляция и PIMPL

Обычный `private` запрещает внешний доступ, но описание полей всё ещё видно в определении класса. Если изменить внутренние поля в заголовке, зависящие от него файлы часто придётся пересобрать. PIMPL решает более узкую инженерную задачу: основное представление прячут в отдельный тип реализации, а в публичном классе оставляют указатель-владелец на него.

Название происходит от «pointer to implementation». Пользователь видит интерфейс, а детали полей определяются в файле реализации. За такое разделение приходится платить дополнительной косвенностью, а иногда и выделением памяти. Это не обязательная форма каждого класса. В учебной задаче с двумя целыми полями прямое хранение обычно проще.

**PIMPL (Pointer to IMPLementation)** скрывает детали реализации за указателем на неполный тип, уменьшает зависимости заголовков и может стабилизировать ABI:

```cpp
// widget.hpp
#include <memory>
class Widget {
    struct Impl;
    std::unique_ptr<Impl> impl_;
public:
    Widget();
    ~Widget();                 // определяем в .cpp после Impl
    Widget(Widget&&) noexcept;
    Widget& operator=(Widget&&) noexcept;
};
```

В `.cpp` определяют `Widget::Impl`, конструктор, деструктор и move-операции. Если оставить деструктор `unique_ptr<Impl>` неудачно определённым inline там, где `Impl` неполный, возникнут проблемы с требованием полноты типа при уничтожении. **Компромисс:** PIMPL добавляет динамическую аллокацию и косвенный доступ.

## 5.11. Разбор: инвариант важнее набора get/set

Инвариант — условие, которое должен сохранять объект в предусмотренных контрактом состояниях. Например, прямоугольник не должен иметь неположительные размеры. Закрытые поля сами по себе недостаточны: публичные методы тоже обязаны поддерживать условие.

```cpp
#include <stdexcept>
class Rectangle {
    double width_;
    double height_;
public:
    Rectangle(double w, double h) : width_(w), height_(h) {
        if (!(w > 0) || !(h > 0)) throw std::invalid_argument("size");
    }
    double area() const { return width_ * height_; }
    void resize(double w, double h) {
        if (!(w > 0) || !(h > 0)) throw std::invalid_argument("size");
        width_ = w;
        height_ = h;
    }
};
```

Проверка перед присваиванием сохраняет прежнее состояние при неверных размерах. Запись `!(w > 0)` также отклоняет NaN. Если нужен контракт только для конечных размеров, дополнительно проверяют `std::isfinite` из `<cmath>`.

## 5.12. Как спроектировать класс по условию задачи

Начните с состояния, которое нужно хранить, затем определите допустимые состояния и операции. Если задача просит «счёт с пополнением и снятием», публичное поле `balance` не решает её: внешний код сможет записать туда недопустимое значение.

Рабочая последовательность:

1. Перечислите данные и единицы измерения. В примере ниже деньги представлены целым числом минимальных денежных единиц.
2. Запишите инвариант: баланс неотрицателен и представим типом `int`.
3. Сделайте поля закрытыми.
4. В конструкторе проверьте начальное состояние.
5. В изменяющих методах проверяйте аргументы **до** изменения объекта.
6. Методы чтения сделайте `const`.
7. Решите, нужны ли собственные copy/move и деструктор. Для одного `int` — нет.

```cpp
// 06_account.cpp
#include <cassert>
#include <iostream>
#include <limits>
#include <stdexcept>
class Account {
    int balance_{};
public:
    explicit Account(int initial = 0) : balance_(initial) {
        if (initial < 0) throw std::invalid_argument("initial balance");
    }
    int balance() const noexcept { return balance_; }
    void deposit(int amount) {
        if (amount <= 0) throw std::invalid_argument("amount");
        if (amount > std::numeric_limits<int>::max() - balance_)
            throw std::overflow_error("balance overflow");
        balance_ += amount;
    }
    void withdraw(int amount) {
        if (amount <= 0) throw std::invalid_argument("amount");
        if (amount > balance_) throw std::out_of_range("not enough money");
        balance_ -= amount;
    }
};
int main() {
    Account a{100};
    a.deposit(50);
    a.withdraw(20);
    try { a.withdraw(1000); }
    catch (const std::out_of_range&) { std::cout << "rejected "; }
    assert(a.balance() == 130);
    const Account& readOnly = a;
    std::cout << readOnly.balance() << '\n';
}
```

**Вывод:** `rejected 130`. Проверка переполнения использует вычитание из максимума: если сначала посчитать `balance_ + amount`, переполнение могло бы произойти уже внутри проверки. Неудачное снятие не меняет баланс.

**Почему без setBalance:** произвольная установка состояния может противоречить смыслу предметной области. `deposit` и `withdraw` показывают намерение вызывающего кода и дают место для проверок.

## 5.13. const-метод — ограничение пути доступа

В `const`-методе `this` имеет тип `const T*`. Обычные поля нельзя менять через него; `mutable`-поля составляют предусмотренное языком исключение. Но константность не распространяется автоматически на все объекты, адреса которых хранятся в полях.

```cpp
// 07_const.cpp
#include <iostream>
class Observer {
    int* ptr_;
public:
    explicit Observer(int& value) : ptr_(&value) {}
    void set(int value) const { *ptr_ = value; }
};
int main() {
    int number = 1;
    const Observer observer{number};
    observer.set(8);
    std::cout << number << '\n';
}
```

**Вывод:** `8`. Не меняется поле `ptr_`, меняется внешний `int` по его адресу. Если контракт наблюдателя обещает только чтение, храните `const int*` и не предоставляйте изменяющую операцию. `Observer` здесь не владеет `number` и не должен пережить его.

### Когда возвращать значение, а когда ссылку

Геттер `int value() const` возвращает число, и вызывающий код не может изменить поле через результат. Геттер `int& value()` открывает прямую запись в поле, обходя проверки класса. Поэтому неконстантная ссылка уместна не всегда, даже если её легко написать.

Возврат `const std::string&` экономит копирование строки, но связывает время жизни результата с объектом. Полученную ссылку нельзя использовать после уничтожения объекта или после операции, которая инвалидирует соответствующий доступ. Возврат по значению даёт самостоятельный результат.

## 5.14. Члены принадлежат объекту, static — классу

У двух объектов `Counter a, b;` обычные поля разные. У `inline static int total` хранение общее для класса, а не отдельное для каждого объекта. Статический метод можно вызвать как `Counter::count()`; у него нет неявного текущего объекта и нет `this`.

Закрытый доступ устанавливается для класса, а не «для одного конкретного экземпляра». Поэтому метод класса может читать закрытые поля другого объекта того же класса, например в копирующем конструкторе или сравнении.

```cpp
class Number {
    int value_{};
public:
    bool same(const Number& other) const {
        return value_ == other.value_; // доступ к private другого Number разрешён
    }
};
```

Вложенный тип `Outer::Inner` не содержит скрытую ссылку на объект `Outer`. Если внутреннему объекту нужно работать с конкретным внешним объектом, его нужно передать явно. Организация имён внутри класса не равна владению экземпляром внешнего класса.

## 5.15. Как объяснить инкапсуляцию на контрольной

Хороший ответ связывает три части: **состояние**, **инвариант**, **публичные операции**. Например: «Класс хранит баланс. Баланс не может быть отрицательным. Закрытое поле изменяется только методами, которые проверяют сумму до изменения».

Плохой ответ ограничивается фразой «поля private». Если публичный метод возвращает изменяемую ссылку на баланс, внешний код снова сможет нарушить инвариант, несмотря на `private`.

**Самопроверка:** почему `friend operator<<` не нарушает инкапсуляцию автоматически? Доступ получает конкретная функция, которая входит в спроектированный интерфейс. Нарушение возникает, когда интерфейс позволяет произвольно ломать состояние, а не от самого наличия ключевого слова `friend`.

# Лекция 6. Конструкторы, деструкторы, RAII и copy/move

## У каждого объекта есть история жизни

В предыдущей лекции класс объединил данные и правила. Теперь нужно ответить на вопросы: как объект получает первое корректное состояние, кто освобождает его ресурсы и что означает создать другой объект из него. Эти вопросы связаны: неверное копирование может привести к тому, что два объекта попытаются освободить один ресурс.

Начнём с `Course`. Внутри него находятся `std::string` и `std::vector<int>`. Они сами управляют своей памятью. Когда курс создаётся, создаются его поля. Когда курс уничтожается, поля тоже уничтожаются, а их память освобождается. Мы не пишем цикл с `delete` для каждой оценки, потому что ресурсом управляет вектор.

Это пример **RAII**: управление ресурсом связывается со временем жизни объекта-владельца. Ресурсом может быть не только память, но и открытый файл или захваченная блокировка. Важно, чтобы объект получил ответственность за освобождение ресурса и выполнял её при разрушении.

### Конструктор и деструктор решают разные задачи

Конструктор устанавливает начальное корректное состояние. Деструктор выполняет завершающие действия перед прекращением существования объекта. У деструктора имя вида `~Course()`, нет возвращаемого типа и нет обычных параметров.

Локальный объект автоматически уничтожается при нормальном выходе из блока. Если в блоке созданы сначала `first`, затем `second`, уничтожаются они в обратном порядке: сначала `second`, затем `first`. Это соответствует зависимости: более поздний объект мог использовать более ранний.

У класса поля инициализируются в порядке их объявления, а не в порядке записи списка инициализации. Поэтому список следует писать в том же порядке, что и поля. При разрушении порядок полей обратный. Тело деструктора выполняется прежде, чем автоматически разрушаются поля этого объекта.

### Почему присваивание в теле конструктора запаздывает

Перед входом в тело конструктора базовые части и поля уже проходят свою инициализацию. Если написать внутри тела `title_ = title;`, строка `title_` к этому времени уже должна была быть создана. Это присваивание существующей строке. Вариант `: title_(title)` сразу задаёт её начальное состояние.

Для ссылочного поля и некоторых константных полей такой выбор ещё строже: связать ссылку или задать значение константы нужно при инициализации. Нельзя сначала создать «несвязанную ссылку», а потом присвоить ей объект в теле конструктора.

### Четыре операции, которые нельзя смешивать

```cpp
Course first{"C++"};
first.add_grade(5);
Course second = first;
Course third{"Math"};
third = first;
Course fourth = std::move(second);
third = std::move(fourth);
```

Строка `Course second = first` создаёт новый объект из существующего: это копирующая инициализация с использованием доступного конструктора. Строка `third = first` меняет уже созданный объект: это копирующее присваивание. Вызовы с `std::move` дают возможность выбрать перемещающие операции: создание `fourth` и изменение `third` соответственно.

Для `Course` компилятор может сгенерировать эти операции на основе операций его полей. Строка и вектор умеют корректно копироваться и перемещаться. Поэтому нам не нужно вручную реализовывать владение памятью. Такой подход называют **правилом нуля**: если ресурсы уже представлены подходящими типами, собственные специальные операции часто не нужны.

### Почему поверхностное копирование указателя опасно

Представим другой класс, который хранит `int* data_`, полученный через `new`, и освобождает его в деструкторе. Если просто скопировать значение указателя, два объекта будут хранить один адрес. При разрушении первого память освободится. Второй всё ещё будет считать её своей и позднее попытается освободить повторно.

Это не недостаток копирования указателей вообще. Для невладеющего указателя два наблюдателя одного объекта могут быть совершенно нормальны. Проблема в противоречии между скопированным адресом и договором об исключительном владении.

Чтобы дать двум объектам независимое владение, копирование должно создать новый ресурс и скопировать содержимое — это глубокая копия. Другая возможность: запретить копирование и разрешить только передачу владения. `std::unique_ptr` следует второму пути.

### Что на самом деле делает перемещение

При перемещении вектора часто можно передать новому объекту уже выделенный буфер, не создавая копию каждого элемента. Но это возможная реализация подходящего типа, а не смысл всякого выражения со `std::move`. Для целого числа перемещение практически не отличается от копирования значения. Для пользовательского класса поведение задаётся его операциями.

После перемещения объект-источник продолжает существовать. Он должен корректно разрушаться. Для многих стандартных типов гарантируется корректное, но неуточнённое состояние; конкретные операции могут обещать больше. Нельзя универсально утверждать, что любая перемещённая строка или вектор обязательно пусты. Перед дальнейшим использованием нужно учитывать договор конкретного типа и требования вызываемой операции.

`std::move` от константного объекта обычно даёт `const T&&`. Обычному перемещающему конструктору нужен `T&&`, чтобы иметь возможность изменить источник. Поэтому в типичном наборе операций будет выбрано копирование из `const T&`. Наличие слова `move` в строке ещё не доказывает вызов перемещения.

### Зачем нужны правила трёх и пяти

Если класс сам управляет сырым ресурсом и определяет деструктор, почти наверняка нужно отдельно решить, как он копируется. Исторически это называют правилом трёх: деструктор, копирующий конструктор, копирующее присваивание рассматриваются вместе. С появлением перемещения добавились перемещающий конструктор и перемещающее присваивание — правило пяти.

Это правило проектирования, а не требование всегда писать пять длинных функций. Иногда правильное решение — `= delete` для запрещённой операции. Иногда `= default` явно просит обычное поведение. Часто лучший вариант — заменить сырой ресурс готовым владельцем и вернуться к правилу нуля.

### Что происходит при исключении

Допустим, конструктор успел создать первое поле, а создание второго выбросило исключение. Полностью сконструированные поля будут уничтожены. Деструктор самого объекта, чьё создание не завершилось, не вызывается как для успешно созданного объекта. Поэтому владение нужно передавать полям сразу, чтобы они могли выполнить очистку самостоятельно.

При выходе из уже выполняющейся функции из-за исключения уничтожаются соответствующие автоматические объекты в покидаемых областях. Это называется раскруткой стека. RAII полезен именно тем, что не требует дублировать ручное освобождение перед каждым `return` и в каждой ветке ошибки.

Деструкторы обычно не должны выпускать исключения наружу. Если во время обработки одного исключения деструктор выбросит другое и оно покинет деструктор, выполнение завершится через `std::terminate`. Поэтому очистку проектируют так, чтобы она была надёжной и не требовала обычного восстановления через новое исключение.

### Почему важен noexcept

`noexcept` у функции заявляет, что исключение не выйдет из неё наружу. Нарушение этого обещания приводит к `std::terminate`; это не команда компилятору автоматически подавлять ошибки. Для перемещения такое обещание влияет на выбор стратегий стандартных контейнеров. Например, при перераспределении вектор может предпочесть доступное копирование, если перемещение способно бросить исключение и требуется сохранить определённые гарантии.

Поэтому `noexcept` нужно писать по реальному поведению операции. Оно связано не только с производительностью, но и с тем, сможет ли алгоритм восстановить прежнее состояние при неудаче.

### Переходим к подробным правилам и примерам

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 6.1. Какие бывают конструкторы

```cpp
class Value {
    int x_{};
public:
    Value() = default;                // конструктор по умолчанию
    explicit Value(int x) : x_(x) {} // преобразующий конструктор
    Value(const Value&) = default;   // копирующий
    Value(Value&&) = default;        // перемещающий
};
```

Конструктор создаёт объект и не имеет возвращаемого типа. **Default constructor** можно вызвать без аргументов. **Copy constructor** обычно принимает `const T&`, **move constructor** — `T&&`. Компилятор может автоматически объявлять/определять специальные методы, но это зависит от пользовательских объявлений других специальных методов.

## 6.2. Список инициализации членов (MIL) и порядок

```cpp
struct Example {
    int a;
    int b;
    Example() : b(2), a(b) {} // ОПАСНО: a инициализируется раньше b
};
```

**Фактический порядок:** виртуальные базы (в наиболее производном классе) → непосредственные базы по порядку объявления → поля по порядку объявления в классе → тело конструктора. Порядок элементов в `: b(...), a(...)` **не управляет** порядком. В примере чтение `b` до инициализации недопустимо; пишите `: a(1), b(a+1)` и располагайте поля осмысленно. Для `const`-полей и ссылок список инициализации обычно обязателен.

![Порядок создания и разрушения объекта](assets/object-lifetime.svg)

При исключении из конструктора уничтожаются уже полностью созданные подобъекты. Деструктор самого недостроенного объекта не вызывается.

## 6.3. Делегирующие конструкторы

Если несколько вариантов создания объекта должны устанавливать одни и те же правила, дублирование опасно: при изменении проверки один конструктор можно забыть исправить. Делегирующий конструктор передаёт работу другому конструктору того же класса.

Например, вариант без аргументов может делегировать варианту с конкретным размером или названием. Это отличается от вызова `ClassName(...)` внутри тела: такая запись в теле обычно создала бы отдельный временный объект, а не повторно построила текущий. Делегирование указывается именно в списке инициализации. После успешного выполнения выбранного конструктора выполняется тело делегирующего.

```cpp
class Point {
    int x_, y_;
public:
    Point() : Point(0, 0) {} // делегирование
    Point(int x, int y) : x_(x), y_(y) {}
};
```

Делегирующий конструктор вызывает другой конструктор **того же класса**. Если список инициализации делегирует, в нём не должно быть дополнительных инициализаторов полей. Циклическое делегирование недопустимо.

## 6.4. explicit и неявные преобразования

```cpp
class Distance {
public:
    explicit Distance(int meters) {}
};
Distance a(5);  // OK
Distance b{5};  // OK
// Distance c = 5; // ошибка: explicit запрещает неявную конверсию
```

`explicit` предотвращает неожиданное преобразование `int → Distance`. В C++20 есть условный `explicit(condition)`. Для конструкторов с одним параметром (или несколькими с умолчаниями) `explicit` часто хорошая практика; он также применим к операторам преобразования типа.

## 6.5. =default, =delete и генерация специальных методов

`= default` просит компилятор сгенерировать специальную функцию по правилам языка; `= delete` запрещает её использование.

```cpp
class NonCopyable {
public:
    NonCopyable() = default;
    NonCopyable(const NonCopyable&) = delete;
    NonCopyable& operator=(const NonCopyable&) = delete;
};
```

**Ключевая тонкость:** пользовательски объявленный деструктор, copy constructor или copy assignment препятствует **неявному объявлению move constructor/move assignment**. Наличие пользовательского move может сделать неявные copy-операции удалёнными. `=default` не означает, что операция обязательно доступна: она может быть определена как удалённая из-за полей/баз. **Rule of Zero** рекомендует не писать эти методы, если поля уже правильно управляют ресурсами.

## 6.6. Деструктор и обратный порядок уничтожения

```cpp
struct A { ~A() { std::cout << "A "; } };
struct B { ~B() { std::cout << "B "; } };
struct C {
    A a;
    B b;
    ~C() { std::cout << "C "; }
};
// При уничтожении C: сначала тело ~C -> "C ", затем b -> "B ", затем a -> "A "
```

Деструктор `~T()` вызывается при окончании времени жизни объекта; его тело выполняется **до** уничтожения полей и баз. Для локальных объектов в одном блоке уничтожение обычно идёт в порядке, обратном успешному конструированию. При исключении из конструктора деструктор **самого недостроенного объекта не вызывается**, но уже построенные базы и поля уничтожаются.

## 6.7. RAII — Resource Acquisition Is Initialization

**Идея:** ресурс захватывается при создании объекта, освобождается в его деструкторе. Работает и при обычном `return`, и при раскрутке стека из-за исключения.

```cpp
#include <fstream>
void write() {
    std::ofstream out("log.txt");
    out << "hello\n";
} // out закрывает файл автоматически
```

`std::vector`, `std::string`, `std::unique_ptr`, `std::lock_guard`, `std::fstream` — примеры RAII. Владение должно быть однозначным. **Сильный принцип:** если ресурс можно представить RAII-объектом, избегайте голого `new/delete` в прикладном коде.

## 6.8. Время жизни и временные объекты

```cpp
std::string makeName() { return "Ada"; }
const std::string& s = makeName(); // временный живёт до конца жизни s
```

Но:

```cpp
const std::string& bad() {
    return std::string("temp"); // возвращается висячая ссылка
}
```

Нельзя считать, что продление времени жизни «передаётся» через возвращаемую ссылку. Временные объекты обычно уничтожаются в конце полного выражения, если специальное правило не продлевает их жизнь. Для параметра-ссылки, связанного с временным в вызове функции, временный обычно живёт до конца полного выражения с вызовом, а не до конца жизни параметра.

## 6.9. Copy vs move и владение динамической памятью

При глубоком копировании `b` получает собственную копию ресурса `a`. При перемещении ресурс может перейти от `a` к `b`; состояние источника определяется контрактом класса. Перемещение само по себе не означает, что источник обязательно становится пустым.

Если класс владеет `int*`, неявное почленное копирование указателя создаёт **два владельца одного блока**, что приводит к double delete. Правильное копирование создаёт новый ресурс, перемещение передаёт владение и оставляет источник в допустимом состоянии.

```cpp
#include <algorithm>
#include <cstddef>
#include <utility>
class Buffer {
    std::size_t size_ = 0;
    int* data_ = nullptr;
public:
    explicit Buffer(std::size_t n) : size_(n), data_(new int[n]{}) {}
    ~Buffer() { delete[] data_; }

    Buffer(const Buffer& other)
        : size_(other.size_), data_(new int[other.size_]) {
        if (size_ != 0) std::copy(other.data_, other.data_ + size_, data_);
    }
    Buffer(Buffer&& other) noexcept
        : size_(std::exchange(other.size_, 0)),
          data_(std::exchange(other.data_, nullptr)) {}

    Buffer& operator=(const Buffer& other) {
        if (this != &other) {
            Buffer tmp(other);   // сначала безопасно скопировать
            swap(tmp);           // затем обменяться ресурсами
        }
        return *this;
    }
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;
            size_ = std::exchange(other.size_, 0);
            data_ = std::exchange(other.data_, nullptr);
        }
        return *this;
    }
    void swap(Buffer& other) noexcept {
        using std::swap;
        swap(size_, other.size_);
        swap(data_, other.data_);
    }
};
```

**Тонкость:** проверка `size_ != 0` в копирующем конструкторе важна для перемещённого источника, у которого `data_ == nullptr`: не нужно формировать диапазон из нулевого указателя. Уточнение для C++20: прибавление нуля к нулевому указателю допустимо и даёт нулевой указатель; ненулевое смещение недопустимо.

В реальном проекте лучше `std::vector<int> data_` и **Rule of Zero**: компилятор автоматически обеспечивает корректные копирование, перемещение и уничтожение.

![Копирование, перемещение и ссылка](assets/copy-move.svg)

Указатель сам по себе не выражает владение. Глубокое копирование — решение автора класса.

## 6.10. Правило трёх, пяти и нуля

- **Rule of Three:** если нужен пользовательский деструктор, часто нужны copy constructor и copy assignment.
- **Rule of Five:** при ручном владении дополнительно рассмотрите move constructor и move assignment.
- **Rule of Zero:** если ресурсы хранятся в RAII-полях, специальные функции лучше не объявлять вовсе.

**Ловушка:** `std::move(x)` не гарантирует вызов move-конструктора: если подходящего move нет, может быть вызван copy-конструктор, принимающий `const T&`. `noexcept` для move важен: некоторые контейнеры предпочитают копирование перемещению, которое может бросить исключение, чтобы сохранить гарантии безопасности.

## 6.11. Практика: инициализация, присваивание и move из const

```cpp
#include <iostream>
#include <utility>
struct Item {
    Item() = default;
    Item(const Item&) { std::cout << "copy\n"; }
    Item(Item&&) noexcept { std::cout << "move\n"; }
    Item& operator=(const Item&) {
        std::cout << "copy assignment\n";
        return *this;
    }
};
int main() {
    Item a;
    Item b = a;                 // copy: новый объект, не operator=
    b = a;                      // copy assignment: объект уже существует
    Item c = std::move(a);      // move
    const Item d;
    Item e = std::move(d);      // copy: const Item&& не подходит к Item&&
}
```

**Вывод:** `copy`, `copy assignment`, `move`, `copy` — по одной строке. `std::move` сохраняет `const`. Пользовательское объявление деструктора (даже `= default`) подавляет неявное объявление move-операций; копирование при этом иногда позволяет выражению с rvalue успешно компилироваться.

| Объявление в классе | Последствие |
|---|---|
| Ни одной специальной функции | Компилятор объявляет специальные функции по правилам языка; часть может оказаться удалённой |
| Пользовательский конструктор с параметрами | Неявного конструктора без параметров больше нет |
| Пользовательский деструктор | Move автоматически не объявляется |
| Пользовательский copy constructor / copy assignment | Move автоматически не объявляется |
| Пользовательский move constructor / move assignment | Неявные copy-операции определяются как удалённые |
| Поле `unique_ptr<T>` | Копирование по умолчанию удалено; перемещение возможно при выполнении остальных условий |

`= default` просит компилятор реализовать функцию, но не гарантирует, что она будет доступна: например, ссылочное поле или `const int` мешает автоматически сгенерированному присваиванию.

## 6.12. Четыре специальные операции: какую вызывает строка

Разбирайте сначала, **существует ли левый объект**, затем категорию правого выражения и доступность перегрузок.

| Строка | Что происходит при подходящих доступных операциях |
|---|---|
| `T b(a);` | Создание b из lvalue: обычно copy constructor |
| `T b = a;` | То же создание b, это не copy assignment |
| `b = a;` | Уже существующий b: copy assignment |
| `T b(std::move(a));` | Создание из xvalue: обычно move constructor |
| `b = std::move(a);` | Изменение существующего b: обычно move assignment |
| `T b = T{};` | В подходящем случае C++20 объект создаётся сразу, без copy/move |

```cpp
// 08_special_members.cpp
#include <iostream>
#include <utility>
struct Trace {
    Trace() { std::cout << "default\n"; }
    Trace(const Trace&) { std::cout << "copy ctor\n"; }
    Trace(Trace&&) noexcept { std::cout << "move ctor\n"; }
    Trace& operator=(const Trace&) {
        std::cout << "copy assign\n";
        return *this;
    }
    Trace& operator=(Trace&&) noexcept {
        std::cout << "move assign\n";
        return *this;
    }
};
int main() {
    Trace a;
    Trace b = a;
    b = a;
    Trace c = std::move(a);
    c = std::move(b);
}
```

**Вывод по строкам:** `default`, `copy ctor`, `copy assign`, `move ctor`, `move assign`.

`std::move(a)` не создаёт отдельный объект. Это выражение с другой категорией значения. Только выбранная специальная функция определяет, что произойдёт с полями и ресурсами.

### Отсутствующая move-операция и удалённая move-операция

Если move-конструктора **нет в наборе кандидатов**, rvalue иногда можно скопировать через `const T&`. Если же явно объявлен `T(T&&) = delete`, эта перегрузка участвует в выборе; если она лучшая, вызов заканчивается ошибкой, а не «откатом» к копированию.

```cpp
struct CopyOnly {
    CopyOnly() = default;
    CopyOnly(const CopyOnly&) = default;
};
struct BlockMove {
    BlockMove() = default;
    BlockMove(const BlockMove&) = default;
    BlockMove(BlockMove&&) = delete;
};
CopyOnly a;
CopyOnly b = std::move(a); // допустимо: копирование
BlockMove x;
// BlockMove y = std::move(x); // ошибка: выбран удалённый move constructor
```

Поэтому фраза «нет перемещения — значит всегда копирование» слишком груба. Дополнительно учитывайте доступность и удалённость выбранной функции.

## 6.13. Как разбирать глубокое копирование и copy-and-swap

У присваивания есть неприятная возможность: выделить новую память не удалось. Если сначала уничтожить старые данные, а потом пытаться создать новые, при ошибке объект потеряет прежнее значение. Поэтому часто сначала готовят независимую копию, не трогая текущий объект.

После успешной подготовки можно обменять ресурсы текущего объекта и временной копии. Если обмен не бросает исключений, новое значение уже установлено, а старое досталось временному объекту. При его разрушении старый ресурс освободится. Эта схема называется copy-and-swap.

Обратите внимание на последовательность ответственности: создать новый ресурс, выполнить безопасную замену, автоматически освободить прежний. Схема также естественно обрабатывает самоприсваивание, потому что подготовленная копия не зависит от дальнейшего изменения текущего объекта. Однако выбор этой реализации должен учитывать стоимость и свойства конкретного типа.

У владельца массива `Buffer` из раздела 6.9 инвариант связывает два поля: размер описывает число доступных элементов, а указатель относится к принадлежащему блоку. Копирование должно создавать **другой блок**, иначе два деструктора попытаются удалить одну память.

Копирующий конструктор выполняет три логических шага: узнаёт размер источника, выделяет новый блок, копирует элементы. Для `int` присваивание элементов не бросает исключений; для произвольного `T` ручная реализация потребовала бы дополнительного контроля уже созданных элементов и освобождения памяти при исключении.

Копирующее присваивание через `Buffer tmp(other); swap(tmp);` устроено иначе:

1. Создать временную полную копию. Если выделение памяти не удалось, исходный объект ещё не менялся.
2. Обменять размеры и указатели. Для этой реализации `swap` не бросает.
3. Уничтожить `tmp`: теперь он владеет прежним ресурсом целевого объекта.

Так достигается сильная гарантия для этой операции: либо копия успешно записана, либо прежнее состояние сохранено. Важно, что потенциально бросающий шаг идёт **до** изменения целевого объекта.

### Самоприсваивание

`a = a;` допустимо ожидать от обычного типа-значения. Если сначала удалить ресурс `a`, а потом читать источник, источник окажется тем же повреждённым объектом. В существующем `Buffer` помогает `if (this != &other)`; сам подход copy-and-swap с корректным `swap` также позволяет строить устойчивую реализацию.

`a = std::move(a);` — отдельный сценарий. Не предполагайте, что произвольный пользовательский move assignment автоматически его корректно обрабатывает: это зависит от кода и контракта. В `Buffer` есть проверка адресов, поэтому его состояние при таком вызове сохраняется.

## 6.14. RAII при исключениях: кто успеет разрушиться

```cpp
// 09_unwinding.cpp
#include <iostream>
#include <stdexcept>
struct Resource {
    Resource() { std::cout << "resource acquired\n"; }
    ~Resource() { std::cout << "resource released\n"; }
};
struct Service {
    Resource resource;
    Service() {
        std::cout << "service body\n";
        throw std::runtime_error("failure");
    }
    ~Service() { std::cout << "service destroyed\n"; }
};
int main() {
    try { Service service; }
    catch (const std::runtime_error&) { std::cout << "caught\n"; }
}
```

**Вывод:** `resource acquired`, `service body`, `resource released`, `caught` — по одной строке. Строки `service destroyed` нет: объект `Service` не был полностью сконструирован. Поле `resource` уже существовало, поэтому его деструктор вызван.

Если вместо RAII-поля конструктор получил сырой ресурс, а освобождение написано только в `~Service`, при таком исключении освобождение не выполнится. Поэтому ресурс нужно передать подходящему RAII-владельцу сразу после получения.

### Гарантии исключений и noexcept

| Гарантия | Что обещает операция |
|---|---|
| Базовая | Нет утечек; объект сохраняет допустимое состояние, но значения могли измениться |
| Сильная | При неуспехе наблюдаемое состояние не меняется |
| Не бросает | Исключение не выходит из операции |

`noexcept` — обязательство, а не блок `try/catch`. Если исключение выйдет из `noexcept`-функции, вызывается `std::terminate`. Поэтому нельзя бездумно объявлять `noexcept` у операции, которая выделяет память. Для move-передачи указателя и размера `noexcept` естественен, если все выполненные действия действительно не бросают.

## 6.15. Состояние после перемещения: что разрешено использовать

«Перемещённый» не означает «уничтоженный». Объект остаётся существовать и его деструктор будет вызван. Для стандартных библиотечных типов обычно действует гарантия корректного, но заранее не определённого состояния после перемещения, если не оговорено иное.

```cpp
std::string a = "hello";
std::string b = std::move(a);
// b содержит переданную строку; не требуйте, чтобы a обязательно была пустой
 a = "again"; // присваивание нового значения допустимо
```

Для собственного класса такие гарантии нужно реализовать. Если вы вручную скопировали владеющий указатель в move-конструкторе и не изменили источник, оба объекта могут продолжить считать себя владельцами. При уничтожении получится двойное освобождение.

Правило для разбора: проверяйте и **получателя ресурса**, и **источник после операции**. У `Buffer` из 6.9 источник получает `size_ == 0` и `data_ == nullptr`, поэтому его можно безопасно разрушить или присвоить ему новый буфер.

## 6.16. Когда выбрать Rule of Zero, Three или Five

Если состояние можно выразить `std::string`, `std::vector` и другими подходящими RAII-полями, начните с Rule of Zero. Тогда специальные операции строятся из операций полей и обычно не требуют ручного кода.

Если по условию нужно показать владение сырым ресурсом, продумайте деструктор, копирование и присваивание как единую систему. Наличие деструктора без корректного копирования — распространённая причина double delete. Если копирование по смыслу запрещено, явно удалите copy-операции и решите, нужно ли перемещение.

Для класса с `std::unique_ptr` копирование по умолчанию запрещено, но это не недостаток: уникальное владение действительно нельзя просто размножить. Если задача требует независимую копию, реализуйте создание нового ресурса; если требует передачу — перемещение.

**Что объяснить преподавателю:** какой ресурс принадлежит объекту, что делает каждая специальная операция, в каком состоянии остаётся источник, что будет при исключении и самоприсваивании.

# Лекция 7. Перегрузка операторов

## Как сделать пользовательский тип естественным в выражениях

Для целых чисел запись `a + b` привычна. Для собственного типа можно предоставить похожую запись, если у операции есть ясный смысл. Например, две двумерные координаты можно складывать покомпонентно. Перегрузка оператора — это определение функции, которую язык позволяет вызывать с помощью операторной записи.

```cpp
#include <iostream>

class Point {
    int x_{};
    int y_{};

public:
    Point(int x, int y) : x_(x), y_(y) {}

    Point& operator+=(const Point& other) {
        x_ += other.x_;
        y_ += other.y_;
        return *this;
    }

    friend Point operator+(Point left, const Point& right) {
        left += right;
        return left;
    }

    friend bool operator==(const Point&, const Point&) = default;

    friend std::ostream& operator<<(std::ostream& out, const Point& point) {
        return out << '(' << point.x_ << ", " << point.y_ << ')';
    }
};

int main() {
    Point first{1, 2};
    Point second{3, 4};
    Point sum = first + second;
    std::cout << first << " + " << second << " = " << sum << '\n';
}
```

Программа выводит `(1, 2) + (3, 4) = (4, 6)`. Исходные точки остаются прежними. Как это получилось?

### Сначала определяем изменение существующего объекта

`operator+=` — метод. Для записи `first += second` объект `first` становится получателем вызова, а `second` передаётся как `other`. Метод изменяет координаты текущего объекта, затем возвращает `*this`, то есть ссылку на него.

Возврат ссылки позволяет продолжать работу с тем же объектом. Это соответствует поведению привычных составных присваиваний. Если вернуть независимую копию, некоторые выражения будут иметь другой смысл и лишнюю стоимость.

### Затем определяем получение нового результата

В `operator+` левый операнд принимается по значению: параметр `left` — самостоятельный объект. Функция меняет его через уже реализованный `+=`, а затем возвращает результат. Благодаря этому проверенная логика сложения написана один раз, а исходный левый операнд не меняется.

`friend` здесь разрешает свободной функции обращаться к закрытым частям класса и позволяет определить такую функцию рядом с типом. Это не делает функцию методом. У неё два обычных параметра, потому что слева от свободной функции нет неявного `this`.

Для симметричных операций свободная функция часто удобна: оба операнда рассматриваются более равноправно при преобразованиях. Но сначала нужно понять смысл операции, а уже потом выбирать техническую форму.

### Почему вывод возвращает поток

В записи `std::cout << first` слева находится поток, поэтому естественная форма — свободная функция с первым параметром `std::ostream&`. Поток нельзя принимать по значению: это существующий объект вывода, с которым мы должны работать.

Возвращение того же потока по ссылке позволяет продолжить цепочку: результат `std::cout << first` снова является потоком, к которому можно применить `<< second`. Без этого цепочка привычного вида не складывалась бы.

Параметр точки — `const Point&`, потому что вывод должен только наблюдать объект. Если для печати потребовалась бы изменяемая точка, мы не смогли бы естественно печатать константные объекты.

### Операторы должны соблюдать ожидаемый смысл

Язык позволяет задать необычное поведение, но пользователь типа ожидает, что `+` создаёт сумму, `+=` меняет левый операнд, `==` проверяет равенство, а вывод не уничтожает объект. Нарушение таких ожиданий усложняет каждую строку программы.

Нельзя изменить приоритет или число операндов знакомого оператора. Также нельзя создать совершенно новый оператор вроде `**` для степени. По крайней мере один операнд перегружаемой операции должен иметь подходящий пользовательский тип: переопределить сложение двух встроенных `int` нельзя.

### Две формы инкремента различаются результатом

Префиксный `++value` обычно сначала изменяет объект и возвращает ссылку на новое состояние. Постфиксный `value++` обычно сохраняет старое значение, меняет объект и возвращает старую копию. Для различения сигнатур постфиксная форма получает фиктивный параметр `int`.

Этот параметр не означает, что пользователь должен написать `value++5`. Он служит языку для различения двух функций. В реализации постфиксной формы удобно использовать уже написанную префиксную: так меньше дублирования.

### Как безопасно читать объект из потока

При вводе составного объекта нельзя бездумно менять поле за полем. Представьте дробь: числитель прочитался, а знаменатель оказался нулём или вообще не прочитался. Если сразу изменить исходный объект, он может остаться частично обновлённым или нарушить свой инвариант.

Надёжная схема: прочитать данные во временные переменные, проверить успешность разбора и допустимость значений, затем одним логическим шагом изменить объект. При неудаче следует установить состояние ошибки потока, а объект сохранить согласно принятому договору. Ниже эта схема показана в техническом разборе.

### Зачем нужны const-версии operator[]

Если объект изменяемый, индексирование может вернуть `T&`, позволяя изменить элемент. Если объект константный, обычно требуется `const T&`, позволяющая только чтение. Это две перегрузки по константности объекта.

Сама перегрузка `operator[]` не добавляет проверку границ автоматически. Автор типа должен решить, проверяет ли он индекс, какое поведение обещает при ошибке и соответствует ли это ожиданиям пользователя. В стандартном векторе для проверяемого обращения есть отдельный метод `at()`.

### Сравнение в C++20

Для простого типа со значимой последовательностью полей можно попросить компилятор сгенерировать сравнение через `= default`. В примере равенство означает равенство обеих координат. Оператор `<=>` позволяет описать трёхстороннее сравнение и поддержать связанные операторы порядка.

Однако наличие полей ещё не доказывает, что их лексикографический порядок соответствует смыслу задачи. У точек на плоскости нет единственного естественного «меньше» для всех применений. Поэтому генерация сравнения — инструмент реализации уже выбранного договора, а не замена проектирования.

### Переходим к подробным правилам и примерам

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 7.1. Основные правила

Перегруженный оператор — функция с особым синтаксисом вызова. Хотя бы один операнд перегружаемого оператора должен иметь классный или перечислимый тип; нельзя изменить работу `int + int`, создать новый оператор или поменять приоритет/число операндов. Нельзя перегрузить `::`, `.`, `.*`, `?:` и `sizeof`.

Метод `T::operator+(...)` имеет неявный левый операнд `*this`; свободная функция `operator+(T, U)` принимает оба операнда явно. Для симметричных бинарных операций свободная функция часто удобнее, потому что допускает преобразования обоих операндов.

## 7.2. Каноническая арифметика: += и +

```cpp
struct Vec2 {
    int x{}, y{};
    Vec2& operator+=(const Vec2& rhs) {
        x += rhs.x; y += rhs.y;
        return *this;
    }
    friend Vec2 operator+(Vec2 lhs, const Vec2& rhs) {
        lhs += rhs;
        return lhs;
    }
};
```

`a += b` меняет `a` и возвращает ссылку на него. `a + b` не меняет аргументы и возвращает новый объект по значению. Реализация `+` через `+=` избегает дублирования логики. Для `-`, `*`, `/` действуют аналогичные соображения, но математическая семантика должна соответствовать типу.

## 7.3. Префиксный и постфиксный ++/--

```cpp
class Counter {
    int n_{};
public:
    Counter& operator++() { ++n_; return *this; } // ++x
    Counter operator++(int) {                     // x++
        Counter old = *this;
        ++*this;
        return old;
    }
};
```

Параметр `int` в постфиксном операторе — **фиктивный маркер** для различения сигнатур. Префиксный обычно возвращает `T&` на изменённый объект, постфиксный — `T` со старым значением. Аналогично `--`.

## 7.4. Сравнение и `<=>` в C++20

```cpp
#include <compare>
struct Point {
    int x{}, y{};
    auto operator<=>(const Point&) const = default;
};
```

Компилятор генерирует лексикографическое трёхстороннее сравнение членов в порядке объявления; из него могут быть переписаны `<`, `<=`, `>`, `>=`, а `==` может быть неявно объявлен для подходящего **defaulted** `<=>`. Если написать **собственный**, не defaulted `<=>`, `==` автоматически из него не появляется.

| Категория | Когда подходит | Особенность |
|---|---|---|
| `std::strong_ordering` | целые, строгая эквивалентность | `equal` означает эквивалентность с возможностью подстановки |
| `std::weak_ordering` | эквивалентные, но различимые значения | `equivalent` не обязательно идентичность |
| `std::partial_ordering` | например, `double` с NaN | возможен `unordered` |

`auto operator<=>(...) const = default` может оказаться **удалённым**, если члены не поддерживают нужные сравнения. Сравнение `double` может дать `unordered` при NaN.

## 7.5. Ввод/вывод как свободные функции

```cpp
class Complex {
    double re_{}, im_{};
public:
    Complex(double re, double im) : re_(re), im_(im) {}
    friend std::ostream& operator<<(std::ostream& os, const Complex& c) {
        return os << c.re_ << ' ' << c.im_;
    }
    friend std::istream& operator>>(std::istream& is, Complex& c) {
        return is >> c.re_ >> c.im_;
    }
};
```

Левый операнд `std::cout << obj` — `std::ostream`, поэтому для обычного синтаксиса перегрузка должна быть свободной функцией (её можно объявить `friend`). Возвращайте **ссылку на поток**, чтобы работали цепочки `cout << a << b`. Ввод принимает изменяемый объект. Для сложного формата сначала считывайте во временные переменные, затем обновляйте объект только при успешном разборе.

## 7.6. operator[]: const и non-const

```cpp
class Array2 {
    int a_[2]{1,2};
public:
    int& operator[](std::size_t i) { return a_[i]; }
    const int& operator[](std::size_t i) const { return a_[i]; }
};
```

Неконстантный `operator[]` возвращает `T&`, чтобы работало `a[0] = 5`. Константный возвращает `const T&` и запрещает изменение через константный объект. В отличие от `std::vector::at`, `operator[]` часто **не проверяет границы**. Можно добавить проверку и бросать `std::out_of_range`.

## 7.7. operator() — функторы

Круглые скобки после объекта могут означать вызов его `operator()`. Например, объект сравнения может хранить порог и при каждом вызове отвечать, превышает ли число этот порог. В отличие от простой свободной функции, такой вызываемый объект удобно объединяет действие с собственным состоянием.

Лямбда тоже создаёт объект специального типа с операцией вызова. Захваченные значения становятся частью состояния этого объекта. Поэтому функторы и лямбды связаны общей идеей: поведение можно передавать как значение, но его время жизни и ссылки внутри него всё равно требуют обычной проверки.

```cpp
struct Adder {
    int offset;
    int operator()(int x) const { return x + offset; }
};
Adder add5{5};
int result = add5(10); // 15
```

Функтор — объект с оператором вызова. В отличие от простой функции он хранит состояние. Лямбда компилируется в объект особого безымянного типа с `operator()`.

## 7.8. operator-> и proxy-объекты

Стрелка позволяет писать `pointer->method()` вместо `(*pointer).method()` для обычного указателя. Пользовательский тип может предоставить собственный `operator->`, чтобы поддержать похожую форму доступа. Наиболее понятный пример — умный указатель, который владеет объектом, а при обращении передаёт доступ к нему.

Если оператор возвращает ещё один объект с собственным `operator->`, применение может продолжаться до получения обычного указателя. Такой промежуточный объект называют прокси. Красивый синтаксис не отменяет проверки жизни и наличия конечного объекта: пустой умный указатель нельзя безопасно разыменовать только потому, что доступ выглядит как обычная стрелка.

```cpp
struct Item { int value = 7; };
struct Handle {
    Item* p;
    Item* operator->() const { return p; }
};
Item item;
Handle h{&item};
int x = h->value; // 7
```

Если `operator->` возвращает указатель, выполняется доступ к члену. Если возвращает объект класса с собственным `operator->`, механизм применяется **рекурсивно**, пока не будет получен указатель. На этом основаны умные указатели и некоторые proxy-типы. `operator->` должен быть методом класса.

## 7.9. Операторы преобразования

Конструктор может описывать преобразование в наш тип, а функция вида `operator bool() const` — преобразование из нашего типа в другой. У такой функции не пишут отдельный возвращаемый тип перед именем: целевой тип уже указан в имени оператора.

Частый случай — проверка наличия значения. Для владельца объекта естественно написать `if (owner)`, имея в виду «объект есть». `explicit operator bool()` позволяет поддержать нужные контекстные проверки и одновременно ограничить многие непреднамеренные неявные преобразования. Без ограничений пользовательский объект мог бы участвовать в арифметике через цепочку неожиданных преобразований.

```cpp
class Flag {
    bool value_;
public:
    explicit Flag(bool v) : value_(v) {}
    explicit operator bool() const { return value_; }
};
Flag f{true};
if (f) { /* contextual conversion to bool */ }
// bool b = f; // ошибка: explicit
bool b = static_cast<bool>(f); // OK
```

Оператор преобразования записывается `operator T() const` **без возвращаемого типа перед `operator`**. `explicit operator bool` допускается в контекстах логической проверки (`if`, `while`, `!`), но запрещает многие неявные конверсии.

## 7.10. Пользовательские литералы и канонические формы

Суффикс у литерала может выражать единицу измерения или другой предметный смысл. Например, пользовательский литерал способен превратить число в объект длительности, а не оставить его безымянным количеством. Это помогает типам различать понятия, которые на уровне чисел выглядели одинаково.

Функция пользовательского литерала имеет специальное имя с `operator""`. Пользовательские суффиксы обычно начинаются с подчёркивания; имена без него зарезервированы для стандартизации. Сам по себе красивый суффикс не проверяет всю физическую модель: автор типа всё равно должен определить допустимые значения и операции.

```cpp
struct Meters { long double value; };
constexpr Meters operator""_m(long double x) { return {x}; }
Meters distance = 2.5_m;
```

Пользовательский суффикс обычно должен начинаться с `_`, а объявление `operator""_m` располагают в подходящем пространстве имён. Литерал `2.5_m` вызывает соответствующую функцию. Перегружайте операторы только когда семантика **очевидна**: например, `+` для векторов, `[]` для индексируемого контейнера, `<<` для вывода. Не делайте `operator+` удаляющим файл или `operator==` изменяющим объект.

## 7.11. Практика: класс с инвариантом, композицией и операторами

```cpp
#include <cassert>
#include <iostream>
#include <stdexcept>
#include <string>
#include <utility>
#include <vector>
class Student {
    std::string name_;
    std::vector<int> grades_;   // композиция; vector владеет памятью
public:
    explicit Student(std::string name) : name_(std::move(name)) {
        if (name_.empty()) throw std::invalid_argument("empty name");
    }
    Student& operator+=(int grade) {
        if (grade < 2 || grade > 5) throw std::out_of_range("grade");
        grades_.push_back(grade);
        return *this;
    }
    double average() const {
        if (grades_.empty()) return 0.0;
        double sum = 0;
        for (int grade : grades_) sum += grade;
        return sum / grades_.size();
    }
    friend std::ostream& operator<<(std::ostream& out, const Student& s) {
        return out << s.name_ << ": " << s.average();
    }
};
int main() {
    Student a{"Anna"};
    (a += 5) += 3;
    Student b = a;             // независимая копия vector и string
    b += 5;
    assert(a.average() == 4.0);
    std::cout << a << '\n';    // Anna: 4
    try { a += 1; }
    catch (const std::out_of_range&) { std::cout << "invalid grade\n"; }
    assert(a.average() == 4.0); // неверная оценка не изменила объект
}
```

Здесь действует Rule of Zero. Закрытые поля защищают инвариант: имя непустое, каждая оценка от 2 до 5. Возвращение `Student&` позволяет цепочки операций, `average() const` доступен для константного объекта, `friend` даёт потоковой функции доступ к полям. После перемещения стандартные поля остаются допустимыми, но имя источника может стать пустым: если нужен такой же инвариант и для перемещённого объекта, контракт класса и move-операции надо продумать отдельно.

## 7.12. Как выбрать метод или свободную функцию

Оператор как метод имеет неявный левый операнд. У свободной функции оба операнда — явные параметры. Это особенно заметно, если вы допускаете преобразование числа в свой тип.

```cpp
// 10_operators.cpp
#include <cassert>
#include <iostream>
class Amount {
    int value_{};
public:
    Amount(int value) : value_(value) {} // намеренно допускаем преобразование
    Amount& operator+=(const Amount& other) {
        value_ += other.value_; // учебные значения не переполняют int
        return *this;
    }
    friend Amount operator+(Amount left, const Amount& right) {
        left += right;
        return left;
    }
    int value() const { return value_; }
};
int main() {
    Amount a{5};
    Amount b = a + 2;
    Amount c = 2 + a;
    assert(a.value() == 5);
    std::cout << b.value() << ' ' << c.value() << '\n';
}
```

**Вывод:** `7 7`. Свободная функция, найденная для операции с `Amount`, допускает преобразование `int` в `Amount` в обоих положениях. Метод `Amount::operator+` не сделал бы выражение `2 + a` симметричным автоматически: слева находится `int`, у которого нет такого метода. При `explicit Amount(int)` неявные преобразования были бы запрещены — это отдельное проектное решение.

### Что происходит внутри operator+

1. Параметр `left` — отдельный объект; для lvalue-аргумента он обычно копируется.
2. `left += right` изменяет эту копию.
3. `return left` возвращает самостоятельный результат. Это параметр функции, поэтому NRVO к нему не применяется; возможны правила неявного перемещения.
4. Исходный `a` остаётся прежним.

Не возвращайте `Amount&` на параметр `left`: его время жизни закончится при выходе из функции. Возврат значения здесь является частью правильного контракта.

## 7.13. Потоковый ввод: сначала разобрать, потом изменить объект

Простой `is >> a.x_ >> a.y_` может частично изменить объект: первый компонент прочитан, второй не удалось. Если нужен контракт «при неверном вводе объект прежний», сначала читайте во временные переменные.

```cpp
// 11_streams.cpp
#include <cassert>
#include <iostream>
#include <sstream>
class Pair {
    int x_{}, y_{};
public:
    Pair(int x, int y) : x_(x), y_(y) {}
    friend std::istream& operator>>(std::istream& in, Pair& p) {
        int x{}, y{};
        if (in >> x >> y) {
            p.x_ = x;
            p.y_ = y;
        }
        return in;
    }
    friend std::ostream& operator<<(std::ostream& out, const Pair& p) {
        return out << p.x_ << ' ' << p.y_;
    }
    int first() const { return x_; }
    int second() const { return y_; }
};
int main() {
    Pair p{1, 2};
    std::istringstream bad{"9 wrong"};
    bad >> p;
    assert(!bad && p.first() == 1 && p.second() == 2);
    std::cout << p << '\n';
    std::istringstream good{"9 8"};
    good >> p;
    std::cout << p << '\n';
}
```

**Вывод:** `1 2`, затем `9 8`. Объект сохраняется при неуспехе; сам поток при этом уже мог прочитать часть входа и переходит в состояние ошибки. Сохранение объекта не означает «откат входных символов».

Операторы не должны печатать подсказки вроде «введите x» в произвольный поток: это смешивает интерфейс пользователя с преобразованием данных. Подсказки при необходимости пишет вызывающий код.

## 7.14. Контракт оператора и const-корректность

| Операция | Ожидаемое изменение | Типичный результат |
|---|---|---|
| `a += b` | Изменяет a | `T&` |
| `a + b` | Исходные операнды сохраняются | `T` |
| `++a` | Изменяет a | `T&` |
| `a++` | Изменяет a, сохраняет старое значение для результата | `T` |
| `a[i]` для изменяемого контейнера | Даёт доступ к элементу | `Element&` |
| `a[i]` для const-контейнера | Даёт только чтение | `const Element&` или подходящее значение |
| `a == b` | Сравнивает | `bool` |

Это общепринятые контракты, а не требование, что любой перегруженный оператор обязан иметь именно такой результат. Язык позволяет написать неожиданную семантику, но на контрольной и в нормальном интерфейсе нужно сохранять привычный смысл.

Если `operator[]` возвращает `int` по значению, обычная запись `array[0] = 5` не будет менять элемент и для такого скалярного результата вообще некорректна. Если const-перегрузка возвращает изменяемую ссылку на внутренний элемент, она открывает изменение через константный контейнер и нарушает ожидаемый контракт.

**Проверка оператора:** изменяет ли он нужный объект; сохраняет ли инвариант; не возвращает ли висячую ссылку; корректно ли работает с `const`; можно ли выстроить цепочку; не возникнет ли переполнение на допустимых входах.

# Лекция 8. Наследование

## Когда разные объекты должны поддерживать одно действие

Мы уже умеем описывать отдельный тип. Теперь представьте набор фигур: у окружности есть радиус, у прямоугольника — ширина и высота, но у обеих можно запросить площадь. Хотелось бы написать функцию, которая умеет показывать площадь любой фигуры и не проверяет вручную, какой перед ней вид.

```cpp
#include <iostream>
#include <memory>
#include <numbers>
#include <stdexcept>
#include <vector>

class Shape {
public:
    virtual double area() const = 0;
    virtual ~Shape() = default;
};

class Circle final : public Shape {
    double radius_;

public:
    explicit Circle(double radius) : radius_(radius) {
        if (!(radius > 0.0)) {
            throw std::invalid_argument("Radius must be positive");
        }
    }

    double area() const override {
        return std::numbers::pi * radius_ * radius_;
    }
};

class Rectangle final : public Shape {
    double width_;
    double height_;

public:
    Rectangle(double width, double height)
        : width_(width), height_(height) {
        if (!(width > 0.0) || !(height > 0.0)) {
            throw std::invalid_argument("Sides must be positive");
        }
    }

    double area() const override {
        return width_ * height_;
    }
};

void show_area(const Shape& shape) {
    std::cout << shape.area() << '\n';
}

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(2.0));
    shapes.push_back(std::make_unique<Rectangle>(3.0, 4.0));

    for (const auto& shape : shapes) {
        show_area(*shape);
    }
}
```

Программа выводит приблизительно `12.5664`, а на следующей строке `12`. Мы передаём обе фигуры одной функции `show_area`, хотя площадь вычисляется разными формулами. Это пример динамического полиморфизма: единый интерфейс допускает разные реализации поведения.

### Что именно наследуется

Запись `class Circle : public Shape` означает открытое наследование. Внутри объекта `Circle` есть базовый подобъект `Shape`, а тип `Circle` поддерживает договор базового типа. Указатель или ссылку на окружность можно использовать там, где ожидается указатель или ссылка на фигуру.

Наследование имеет смысл, если объект производного типа действительно можно использовать в роли базового с соблюдением его обещаний. Если класс автомобиля содержит двигатель, автомобиль не становится разновидностью двигателя. Такое отношение естественнее выражать полем: это композиция.

### Почему area объявлена virtual

`virtual` сообщает, что при соответствующем вызове через базовый интерфейс нужно выбрать реализацию по фактическому типу объекта. `= 0` делает функцию чисто виртуальной. Класс `Shape` становится абстрактным: создать самостоятельный объект `Shape` нельзя, потому что общего алгоритма площади у него нет.

В `Circle` слово `override` просит компилятор проверить, что метод действительно переопределяет виртуальную функцию базы. Если случайно забыть `const` или изменить тип параметра, проверка поможет поймать несоответствие. Без неё похожее имя могло бы создать другую функцию, а не нужное переопределение.

`final` у класса запрещает дальнейшее наследование от него. Это выражает решение автора интерфейса; слово не требуется для самого полиморфного вызова.

### Статический и динамический тип

Внутри `show_area` выражение `shape` имеет статический тип `const Shape&`. Именно он известен из текста объявления и определяет доступный интерфейс. Но объект, к которому привязана ссылка, может быть `Circle` или `Rectangle`. Это его динамический тип в рассматриваемой иерархии.

Поскольку `area` виртуальна, выбор переопределения учитывает динамический тип. Если бы функция была невиртуальной, выбор не превращался бы в такой поиск по фактическому объекту. Наличие наследования само по себе не делает все методы виртуальными.

При этом аргументы по умолчанию выбираются по статически видимому объявлению, а не по динамическому типу. Поэтому сочетание виртуального выбора функции с разными значениями по умолчанию в базе и наследнике особенно легко неправильно прочитать.

### Зачем нужны unique_ptr и виртуальный деструктор

`std::unique_ptr<Shape>` владеет одной фигурой и освобождает её автоматически. `std::make_unique<Circle>(2.0)` создаёт окружность и сразу помещает владение в умный указатель. Затем владелец перемещается в вектор. Сам вектор владеет элементами, элементы владеют фигурами.

Когда вектор разрушается, разрушаются владельцы. Освобождение через базовый тип должно корректно уничтожить весь производный объект. Для обычного удаления через базовый указатель в такой иерархии базовый деструктор должен быть виртуальным. Тогда сначала выполняется разрушение производной части, затем базовой.

Это логически связано с интерфейсом: если разрешено управлять жизнью разных объектов через базовый тип, интерфейс должен поддерживать корректное завершение их жизни.

### Почему нельзя хранить такие объекты просто как значения базы

Если базовый класс конкретный и скопировать в него производный объект по значению, в новом объекте останется только базовая часть. Это срезка. Потерянные поля и поведение не восстановятся от того, что исходный объект когда-то был производным.

В нашем примере `Shape` абстрактен, поэтому `std::vector<Shape>` не подходит уже по этой причине. Но даже для неабстрактной базы хранение производных объектов как базовых значений не сохраняло бы их динамическую индивидуальность. Поэтому для открытой полиморфной иерархии часто используют владельцев указателей на базу.

### Переопределение, перегрузка и сокрытие — три разных механизма

Перегрузка выбирает между функциями по параметрам и другим правилам в месте вызова. Переопределение предоставляет реализацию виртуальной функции в производном классе. Сокрытие имён влияет на то, какие объявления вообще найдутся при поиске имени.

Например, появление `print(double)` в производном классе может скрыть базовый `print(int)`, даже если параметры разные. Объявление `using Base::print;` позволяет ввести базовые перегрузки в рассматриваемый набор. Это не превращает невиртуальную функцию в виртуальную и не создаёт переопределение само по себе.

### Что происходит во время конструирования

Объект производного типа строится по частям: сначала базовые подобъекты, затем поля, затем выполняется тело конструктора производного класса. Во время конструктора базы производная часть ещё не готова к использованию. Поэтому виртуальный вызов в конструкторе базы не направляется в переопределение ещё не построенного потомка.

При разрушении происходит обратный процесс. Виртуальность учитывает текущий этап жизни, а не предположение, что самый производный объект вечно доступен полностью. По этой причине вызовы виртуальных функций в конструкторах и деструкторах требуют особой осторожности.

### Ромб наследования и общая база

Представьте, что `Student` и `Employee` оба наследуют `Person`, а `Assistant` наследует и `Student`, и `Employee`. При обычном наследовании в помощнике окажутся две базовые части `Person`: одна через студента, другая через сотрудника. Обращение к единственному «человеку» становится неоднозначным.

Виртуальное наследование позволяет разделить один общий базовый подобъект между этими путями. За инициализацию такой виртуальной базы отвечает самый производный класс. Оно решает конкретную задачу структуры подобъектов и не связано напрямую с виртуальными методами, несмотря на общее ключевое слово `virtual`.

Перед применением множественного наследования стоит проверить, нужна ли эта модель. Иногда удобнее иметь один объект человека и отдельные компоненты его ролей. Выбор определяется отношениями предметной области и требованиями интерфейса.

### Переходим к подробным правилам и примерам

Теперь разберём механизмы этой лекции по отдельности. Связывайте каждое правило с уже рассмотренной программой: какое действие оно разрешает, какое состояние меняет и какую ошибку помогает обнаружить.


## 8.1. Наследование = отношение is-a

```cpp
class Animal {
protected:
    std::string name_;
public:
    explicit Animal(std::string n) : name_(std::move(n)) {}
    void info() const { std::cout << name_; }
};
class Dog : public Animal {
public:
    Dog(std::string n) : Animal(std::move(n)) {}
    void bark() const { std::cout << "woof"; }
};
```

`Dog` — разновидность `Animal`, поэтому при `public`-наследовании `Dog&` может использоваться как `Animal&`. Это **подстановочность**: производный тип должен выполнять контракт базового. Если машина *имеет* двигатель, правильнее `class Car { Engine engine_; };`, а не `Car : Engine`.

Класс `Animal` содержит `name_` и метод `info() const`. Класс `Dog` публично наследует `Animal` и добавляет `bark() const`: собака является разновидностью животного.

## 8.2. Модификаторы наследования

Слова `public`, `protected` и `private` возле имени базы описывают доступность унаследованного интерфейса и связанных преобразований. При открытом наследовании доступная открытая часть базы остаётся открытой частью производного интерфейса. При закрытом наследовании отношение используется как деталь реализации и не даёт обычному внешнему коду свободно трактовать наследника как базу.

Это нужно отличать от закрытых полей самой базы. Производный класс не получает произвольного прямого доступа к `private`-полям базы при любом модификаторе наследования. Он должен пользоваться разрешёнными средствами базового класса. `protected` предоставляет особый доступ наследникам, но не делает поле открытым для всего внешнего кода.

| Доступ члена в Base | `public Base` | `protected Base` | `private Base` |
|---|---|---|---|
| `public` | public | protected | private |
| `protected` | protected | protected | private |
| `private` | напрямую недоступен | напрямую недоступен | напрямую недоступен |

**Важно:** `private`-члены базы **существуют** внутри базового подобъекта наследника, но недоступны напрямую из кода наследника. При `class Derived : Base` наследование по умолчанию `private`; при `struct Derived : Base` — `public`.

## 8.3. Порядок конструирования и разрушения

```cpp
struct Base { Base(){std::cout<<"B ";} ~Base(){std::cout<<"~B ";} };
struct Member { Member(){std::cout<<"M ";} ~Member(){std::cout<<"~M ";} };
struct Derived : Base {
    Member m;
    Derived(){std::cout<<"D ";}
    ~Derived(){std::cout<<"~D ";}
};
// Для { Derived d; }:
// B M D ~D ~M ~B
```

База полностью конструируется до членов и тела конструктора наследника. При разрушении сначала выполняется тело деструктора наследника, затем уничтожаются его поля, затем базы. Порядок членов — **по объявлению**, порядок прямых баз — **по списку наследования**.

## 8.4. Наследование конструкторов

Конструкторы не наследуются автоматически как обычный набор методов. Объявление `using Base::Base;` позволяет использовать соответствующие формы создания базы при создании производного объекта. Но оно не снимает с производного класса ответственности за собственные поля: они тоже должны получить корректное начальное состояние.

Если производному объекту нужны дополнительные обязательные данные, собственного конструктора часто не избежать. Наследование конструкторов — средство уменьшения повторяющегося кода, а не обещание, что любой способ создания базы автоматически подходит новому типу.

```cpp
struct Base {
    explicit Base(int) {}
    Base(int, double) {}
};
struct Derived : Base {
    using Base::Base; // наследовать доступные конструкторы
    int extra = 5;
};
Derived d(1); // Base(int), extra == 5
```

`using Base::Base` делает конструкторы базы доступными для конструирования производного класса, но **не наследует** copy/move-конструкторы как обычные конструкторы и не заменяет инициализацию полей наследника. Если полю не задан default member initializer, оно может остаться неинициализированным.

## 8.5. Сокрытие имён (name hiding)

```cpp
struct Base {
    void f(int) { std::cout << "int"; }
    void f(double) { std::cout << "double"; }
};
struct Derived : Base {
    void f(int) { std::cout << "derived int"; }
};
Derived d;
d.f(3.14);       // "derived int": Base::f(double) скрыт!
d.Base::f(3.14); // "double"
```

Любое объявление `f` в наследнике может скрыть набор одноимённых перегрузок базы. Чтобы добавить перегрузку и сохранить базовые, используйте `using Base::f;` внутри класса. **Сокрытие имени** — не то же самое, что **переопределение виртуальной функции**.

## 8.6. Срезка объектов (object slicing)

```cpp
struct Base { int x = 1; virtual ~Base() = default; };
struct Derived : Base { int y = 2; };
Derived d;
Base b = d;      // копируется только Base-подобъект
Base& r = d;     // срезки нет
Base* p = &d;    // срезки нет
```

Объект `Derived d` содержит базовый подобъект `Base` и собственные поля `Derived`. При `Base b = d` создаётся отдельный объект `Base`: копируется базовая часть, а поля производной части в `b` отсутствуют.

Срезка возникает при **копировании производного объекта по значению в базовый тип**, в том числе при передаче `void f(Base)` и хранении `std::vector<Base>`. Виртуальность методов не отменяет срезку: после копирования `b` — самостоятельный объект `Base`. Чтобы сохранить полиморфное поведение, передавайте `Base&`, `Base*` или храните `std::unique_ptr<Base>` (при корректном виртуальном деструкторе).

## 8.7. Приватное наследование vs композиция

`class Stack : private std::vector<int>` означает «реализован через» с использованием базового подобъекта, но **не публичное is-a**. `class Stack { std::vector<int> data_; }` выражает **has-a**. Композиция обычно предпочтительна: меньше связанность, проще менять реализацию и управлять инвариантами. Приватное наследование может иметь смысл для доступа к `protected`, специальных возможностей переопределения или оптимизации пустого базового класса, но не является универсальной заменой композиции.

## 8.8. final и принцип подстановки

```cpp
struct Base {
    virtual ~Base() = default;
    virtual void run() final {}
    virtual void save() {}
};
struct Derived final : Base {
    void save() override {}
    // void run() override {} // ошибка: final
};
// struct More : Derived {}; // ошибка: класс final
```

`final` на классе запрещает дальнейшее наследование; на виртуальном методе — дальнейшее переопределение. `override` проверяет, что метод действительно переопределяет виртуальный метод базы. **Принцип Лисков (LSP):** объект наследника должен использоваться вместо базы без нарушения обещанного поведения. Не всякое внешне похожее отношение является корректным наследованием.

## 8.9. Множественное наследование

```cpp
struct Printer { void status() {} };
struct Scanner { void status() {} };
struct Copier : Printer, Scanner {};
Copier c;
// c.status();          // неоднозначно
c.Printer::status();   // явно выбираем базу
```

При множественном наследовании объект содержит подобъекты нескольких прямых баз. Адрес `Printer*` и `Scanner*`, полученный из `Copier*`, **может различаться**: корректное преобразование указателя на базу учитывает смещение подобъекта. `reinterpret_cast` не заменяет корректное приведение к базе.

## 8.10. Проблема ромба

В обычном ромбе `Printer` и `Scanner` наследуют `Device`, а `Copier` наследует оба класса. В `Copier` находятся два подобъекта `Device`, по одному через каждую ветвь. Виртуальное наследование `Device` обеими ветвями позволяет иметь один общий подобъект.

```cpp
struct Device { int id = 0; };
struct Printer : Device {};
struct Scanner : Device {};
struct Copier : Printer, Scanner {};
Copier c;
// c.id = 1; // неоднозначно: ДВА Device-подобъекта
c.Printer::id = 1;
c.Scanner::id = 2;
```

Без виртуального наследования `Copier` содержит **две отдельные копии** `Device`, каждая со своим `id`. Квалификация имени выбирает одну ветку, но не устраняет дублирование состояния.

## 8.11. Виртуальное наследование

```cpp
struct Device { explicit Device(int id) : id(id) {} int id; };
struct Printer : virtual Device { Printer() : Device(1) {} };
struct Scanner : virtual Device { Scanner() : Device(2) {} };
struct Copier : Printer, Scanner {
    Copier() : Device(42), Printer(), Scanner() {}
};
Copier c;
// c.id == 42: общий Device-подобъект ровно один
```

| Схема наследования | Число подобъектов `Device` в `Copier` |
|---|---|
| `Printer : Device`, `Scanner : Device` | Два отдельных подобъекта |
| `Printer : virtual Device`, `Scanner : virtual Device` | Один общий подобъект |

**Ключевой нюанс:** виртуальную базу инициализирует **наиболее производный класс** (`Copier`), а инициализаторы `Device(...)` в промежуточных конструкторах игнорируются, когда эти классы являются подобъектами `Copier`. Виртуальные базы конструируются до невиртуальных баз; детали расположения служебных указателей/таблиц (`vbptr`, `vptr`) — **детали ABI**, а не обязательная модель памяти стандарта C++.

## 8.12. Примеси, интерфейсы и альтернативы

Одинаковая внешняя возможность не обязательно требует общей иерархии объектов. Если все конкретные типы известны при компиляции, шаблонная функция может работать с любым типом, поддерживающим нужные выражения. В C++20 concepts позволяют яснее описать требования к такому типу. Здесь выбор реализации происходит другим способом, чем виртуальный вызов через базовую ссылку.

Если набор вариантов заранее закрыт, иногда удобен `std::variant`: он хранит одно значение из перечисленного набора типов. Если нужно разделить самостоятельные обязанности, помогает композиция. Примесь, в свою очередь, добавляет некоторую общую возможность через наследование. Эти подходы полезно различать по вопросу: какие типы должны быть известны заранее и кто отвечает за общее состояние?

На контрольной прежде всего используйте механизм, который требуется условием. Но в объяснении проектного решения важно показать, почему именно эта модель отношений подходит задаче.

**Mixin** добавляет типу небольшую возможность через наследование (например, CRTP-шаблон). **Интерфейс** в C++ часто задаётся абстрактным классом с чисто виртуальными методами:

```cpp
struct Drawable {
    virtual void draw() const = 0;
    virtual ~Drawable() = default;
};
struct Circle : Drawable {
    void draw() const override { std::cout << "circle"; }
};
```

Чисто виртуальный метод (`= 0`) делает класс абстрактным, если в наиболее производном классе остаётся непереопределённым. В интерфейсах нужен **виртуальный деструктор**, если объекты могут удаляться через указатель на базу. Альтернативы наследованию: композиция, шаблоны, концепты C++20, `std::variant` и свободные функции. **Важное разграничение:** `virtual`-методы и динамический полиморфизм подробно развиваются в следующих темах курса; здесь они введены ровно настолько, насколько нужны для понимания наследования, срезки и интерфейсов.

## 8.13. Практика: виртуальная функция и аргумент по умолчанию

![Выбор метода через базовый тип](assets/dispatch.svg)

```cpp
#include <iostream>
struct Base {
    virtual void print(int n = 1) const { std::cout << "B" << n; }
    virtual ~Base() = default;
};
struct Derived : Base {
    void print(int n = 2) const override { std::cout << "D" << n; }
};
int main() {
    Derived d;
    const Base& b = d;
    b.print();         // D1: тело по динамическому типу, аргумент по статическому
    d.print();         // D2
    d.Base::print();   // B1: явная квалификация подавляет виртуальный вызов
}
```

**Вывод:** `D1D2B1`. `override` требует совпадения нужных характеристик функции: отсутствие `const` у метода наследника здесь приведёт к ошибке компиляции. Обычный конструктор не бывает виртуальным; деструктор может быть виртуальным.

## 8.14. Самопроверка по ООП и особенностям C++

1. Почему `T x = other;` вызывает конструктор, а `x = other;` — присваивание?
2. Почему `T(T&& other) : field(other.field) {}` может копировать поле? Исправление: `field(std::move(other.field))`; имя `other` — lvalue.
3. Что произойдёт при `delete basePtr`, если он указывает на `Derived`, а деструктор базы невиртуален? Для обычного удаления такого объекта — UB.
4. Почему `private` не означает «поля базы отсутствуют в наследнике»? Они входят в базовый подобъект, но прямой доступ ограничен.
5. Чем `virtual Base` отличается от `virtual void f()`? Первое управляет общим базовым подобъектом, второе — выбором реализации при вызове.
6. Почему нельзя вернуть ссылку на локальный результат `operator+`? Объект разрушится при выходе, ссылка станет висячей; возвращайте значение.

Дополнительная практика с виртуальными вызовами расширяет вводный материал лекции 8; это не утверждение о точном содержании контрольной.

## 8.15. Статический и динамический тип: два разных вопроса

У выражения с базовой ссылкой статический тип определяется объявлением ссылки. Динамический тип связан с фактически существующим наиболее производным объектом. Ссылка на базу не создаёт новый базовый объект.

```cpp
// 12_dispatch.cpp
#include <iostream>
struct Base {
    virtual ~Base() = default;
    void plain() const { std::cout << "B"; }
    virtual void dynamic() const { std::cout << "B"; }
};
struct Derived : Base {
    void plain() const { std::cout << "D"; }
    void dynamic() const override { std::cout << "D"; }
};
int main() {
    Derived d;
    const Base& base = d;
    base.plain();
    base.dynamic();
    d.plain();
    d.Base::dynamic();
    std::cout << '\n';
}
```

**Вывод:** `BDDB`.

| Вызов | Причина результата |
|---|---|
| `base.plain()` | Невиртуальный метод выбран через статический тип Base |
| `base.dynamic()` | Виртуальный вызов использует Derived::dynamic |
| `d.plain()` | Поиск имени в Derived находит Derived::plain |
| `d.Base::dynamic()` | Явная квалификация подавляет виртуальный вызов |

Указатели и ссылки не «превращают объект обратно в базу». Они ограничивают доступный интерфейс по статическому типу, но виртуальная диспетчеризация может сохранить поведение производного класса.

## 8.16. Перегрузка, сокрытие и переопределение: сравнение

**Перегрузка** предлагает несколько функций с одним именем и разными параметрами. **Сокрытие** влияет на то, какие имена вообще видны при поиске в наследнике. **Переопределение** задаёт новую реализацию виртуальной функции базы.

| Запись | Что означает |
|---|---|
| `void f(int); void f(double);` в одном классе | Перегрузка |
| `Derived::f(int)` при Base::f(double) | Сокрытие имени базы |
| `void f() const override` при virtual Base::f() const | Переопределение |
| `using Base::f;` | Введение базовых перегрузок в набор поиска |

```cpp
struct Base {
    virtual void show() const {}
};
struct Derived : Base {
    // void show() override {} // ошибка: потерян const, нужного override нет
    void show() const override {}
};
```

Без `override` случайно отличающаяся сигнатура иногда компилируется как другой метод, и ошибка обнаруживается только по поведению. `override` превращает намерение автора в проверяемое требование.

Уровень доступа сам по себе не определяет возможность переопределения: виртуальный метод базы может быть `private` и иметь переопределение в наследнике. Но явный вызов закрытого метода по имени по-прежнему ограничен правилами доступа. Выбор виртуальной реализации и проверка доступа — разные механизмы.

## 8.17. Конструкторы и деструкторы: виртуальность ограничена текущим этапом

Во время выполнения конструктора базы производная часть ещё не готова. Виртуальный вызов из этого конструктора не должен обращаться к ещё не созданному состоянию наследника. При разрушении аналогично нельзя рассчитывать на уже уничтоженную производную часть.

```cpp
// 13_ctor_virtual.cpp
#include <iostream>
struct Base {
    Base() { f(); }
    virtual ~Base() { f(); }
    virtual void f() const { std::cout << "B"; }
};
struct Derived : Base {
    Derived() { f(); }
    ~Derived() override { f(); }
    void f() const override { std::cout << "D"; }
};
int main() {
    { Derived d; }
    std::cout << '\n';
}
```

**Вывод:** `BDDB`. Конструктор Base вызывает Base::f; тело конструктора Derived — Derived::f; тело деструктора Derived — Derived::f; тело деструктора Base — Base::f.

Не используйте вызов чисто виртуальной функции из конструктора или деструктора как способ потребовать работу наследника. Для обычной виртуальной функции в примере достаточно помнить, что выбор связан с текущим конструируемым или разрушаемым классом.

### Виртуальный деструктор и удаление

```cpp
std::unique_ptr<Base> object = std::make_unique<Derived>();
```

При обычном удалении производного объекта через `Base*` базе нужен подходящий виртуальный деструктор. Виртуальность других методов автоматически не делает деструктор виртуальным. Деструктор `Derived` виртуален, если переопределяет уже виртуальный деструктор базы; `override` помогает явно это показать.

## 8.18. Абстрактный интерфейс: законченный пример

```cpp
// 14_interface.cpp
#include <iostream>
#include <memory>
#include <vector>
struct Shape {
    virtual double area() const = 0;
    virtual ~Shape() = default;
};
class Rectangle final : public Shape {
    double w_, h_;
public:
    Rectangle(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
};
class Square final : public Shape {
    double side_;
public:
    explicit Square(double side) : side_(side) {}
    double area() const override { return side_ * side_; }
};
int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Rectangle>(2.0, 3.0));
    shapes.push_back(std::make_unique<Square>(4.0));
    for (const auto& shape : shapes) std::cout << shape->area() << ' ';
    std::cout << '\n';
}
```

**Вывод:** `6 16` с пробелом перед переводом строки. Для примера предполагаются положительные конечные размеры; проверку инвариантов можно добавить по образцу лекции 5.

`Shape` абстрактен из-за `area() = 0`: создать самостоятельный `Shape` нельзя. Вектор хранит владеющие указатели, поэтому объекты разных производных типов сохраняются без срезки. `unique_ptr` освобождает память, виртуальный деструктор обеспечивает корректное разрушение через базовый интерфейс.

Почему `Square` здесь не наследует `Rectangle`? Интерфейс `Shape` обещает только вычисление площади. Если бы `Rectangle` обещал независимо менять ширину и высоту, квадрат не смог бы соблюдать этот контракт, сохраняя равенство сторон. Подстановка определяется поведением интерфейса, а не только геометрическим названием.

## 8.19. Ромб и преобразование к базовому типу

При обычном ромбе неоднозначным бывает не только обращение `copier.id`, но и преобразование `Copier*` в `Device*`: неясно, какой из двух базовых подобъектов нужен. Можно сначала выбрать ветвь `Printer*` или `Scanner*`, но это не объединит два состояния.

В виртуальном ромбе обе ветви разделяют общий виртуальный подобъект `Device`. Его конструктор выбирает наиболее производный класс `Copier`. При создании самостоятельного `Printer` наиболее производным будет уже `Printer`, поэтому его инициализатор `Device` используется.

Не заучивайте конкретные смещения и обязательное наличие `vbptr` как требование стандарта: это детали реализации. Стандарт задаёт отношения подобъектов и корректное поведение преобразований, а компилятор выбирает представление.

**Алгоритм разбора наследования:** выпишите базовые подобъекты; определите уровень доступа; найдите имя и перегрузку по статическому типу; проверьте виртуальность; установите текущий динамический тип с учётом ctor/dtor; отдельно проверьте срезку и способ уничтожения.

**Контрольные вопросы:** почему `using Base::f` не делает функцию виртуальной; почему `virtual` не отменяет срезку; почему наличие `private`-поля базы не означает его отсутствия в объекте наследника; почему композиция часто удобнее наследования для переиспользования реализации?

## 9.2. Пять видов ответа на вопрос «что выведет код?»

1. **Компилируется, результат определён:** можно назвать точный вывод.
2. **Ошибка компиляции:** нет исполняемого файла; объясните причину (например, `private`, ambiguous overload, narrowing).
3. **Ошибка компоновки:** объявление есть, определения нет, либо конфликт определений.
4. **UB:** стандарт не определяет поведение; нельзя обещать конкретный вывод.
5. **Unspecified / implementation-defined:** программа может иметь несколько разрешённых вариантов или зависеть от реализации; не путайте с UB.

## 9.3. Алгоритм решения задачи по коду

1. Проверить синтаксис, типы, доступ и перегрузки: иначе ошибка компиляции.
2. Проверить наличие определений: возможна ошибка компоновки.
3. Проверить время жизни, границы и остальные причины UB. При UB точного вывода нет.
4. Если поведение определено, разобрать вызовы, порядок действий и вычислить вывод.

**Перед ответом проверяйте:** (1) тип каждого выражения; (2) категорию значения; (3) `const` и доступ; (4) перегрузку; (5) время жизни; (6) копирование или перемещение; (7) порядок конструирования и уничтожения; (8) выход за границы/неинициализированные значения; (9) особенности C++20.

# Тренировочная контрольная с решениями

> Сначала решите без просмотра ответов. Для фрагментов подразумеваются нужные стандартные заголовки и `std::` там, где это очевидно; если не указано иначе, каждый пример рассматривается отдельно.

## Задача 1. Целочисленное деление

```cpp
int a = 7, b = 2;
std::cout << a / b << ' ' << a % b << ' ' << a / 2.0;
```

**Ответ:** `3 1 3.5`. Первые две операции целочисленные; в третьей `a` преобразуется к `double`.

### Почему получается именно так

Начнём с типов: `a` и `b` объявлены как `int`. Поэтому `a / b` выполняет целочисленное деление и даёт целую часть частного: `3`. Остаток `a % b` равен `1`, потому что `7 = 3 * 2 + 1`. В последнем выражении литерал `2.0` имеет тип `double`, поэтому целое значение `a` преобразуется, и деление сохраняет дробную часть. Три результата печатаются по очереди с пробелами между ними.

## Задача 2. Префикс и постфикс

```cpp
int x = 4;
int y = x++;
int z = ++x;
std::cout << x << ' ' << y << ' ' << z;
```

**Ответ:** `6 4 6`. Постфикс сохраняет старое значение 4 и делает `x=5`; префикс делает `x=6` и возвращает 6.

### Почему получается именно так

Выпишем состояния после каждой команды. Сначала существует только `x` со значением `4`. В `int y = x++;` результат выражения — прежнее значение `x`, поэтому `y` получает `4`, а сам `x` становится `5`. Следующая отдельная команда `int z = ++x;` сначала увеличивает `x` до `6`, затем использует это значение для создания `z`. В момент вывода `x` и `z` равны `6`, а `y` хранит свою независимую копию прежнего значения. Здесь изменения находятся в разных командах, поэтому проблемы неупорядоченных изменений нет.

## Задача 3. Массив и указатель

```cpp
int a[]{3, 6, 9};
int* p = a;
std::cout << *(p + 1) << ' ' << (a + 3 - p);
```

**Ответ:** `6 3`. `a+3` — допустимый one-past-end указатель; разность считается в элементах.

### Почему получается именно так

При создании `p` массив `a` преобразуется в указатель на первый элемент. Выражение `p + 1` указывает на второй элемент, то есть на число `6`. Звёздочка обращается к этому элементу и даёт его значение. Указатель `a + 3` расположен сразу за тремя элементами массива. Его можно получить, но нельзя разыменовать. Вычитание двух соответствующих указателей этого массива измеряет расстояние в элементах: от первого элемента до позиции за третьим расстояние равно трём.

## Задача 4. const

```cpp
int x = 1, y = 2;
const int* p = &x;
p = &y;
// *p = 3;
```

**Ответ:** без закомментированной строки компилируется. `p` перенаправляется; `*p=3` — ошибка компиляции из-за `const`.

### Почему получается именно так

Сначала `p` хранит адрес `x`. После `p = &y` меняется значение самого указателя: он начинает указывать на `y`. Значения `x` и `y` не меняются. Запрет относится к изменению целого через `p`, потому что тип доступного объекта записан как `const int`. Если убрать комментарий перед `*p = 3`, компилятор отклонит обращение. Само по себе это не делает исходный `y` константным: отдельная команда `y = 3` по-прежнему допустима.

## Задача 5. Время жизни

```cpp
int* make() {
    int x = 10;
    return &x;
}
int main() { std::cout << *make(); }
```

**Ответ:** обращение через висячий указатель, **UB**; нельзя утверждать, что будет напечатано `10`.

### Почему получается именно так

Во время вызова `make` создаётся локальный объект `x`. Выражение `&x` получает его адрес, и этот адрес возвращается. Затем выполнение выходит из функции, и жизнь `x` заканчивается. Возвращаемый указатель не переносит объект наружу и не продлевает его жизнь. Поэтому разыменование в `main` уже обращается к несуществующему объекту. Исправить задачу с числом можно возвратом `int` по значению: вернуть `x`, а не его адрес.

## Задача 6. Перегрузка

```cpp
void f(int) { std::cout << "I"; }
void f(double) { std::cout << "D"; }
int main() { f(1); f(1.0); f('a'); }
```

**Ответ:** `IDI`. `char` обычно продвигается к `int` (integral promotion), что лучше conversion к `double`.

### Почему получается именно так

Каждый вызов разрешается отдельно. Литерал `1` имеет тип `int`, поэтому первая перегрузка даёт точное совпадение. Литерал `1.0` имеет тип `double`, поэтому во втором вызове выигрывает вторая. В третьем вызове символьный литерал имеет тип `char`; на обычных платформах его продвижение к `int` лучше преобразования к `double`, и печатается `I`. Это выбор по типам и рангам преобразований, а не по тому, что символ внешне похож на букву. Утверждение о продвижении именно в `int` предполагает, что `int` представляет все значения `char`, как в используемых обычных реализациях.

## Задача 7. Ссылка против копии

```cpp
void a(int x) { x += 2; }
void b(int& x) { x += 3; }
int main() { int n=1; a(n); b(n); std::cout << n; }
```

**Ответ:** `4`. `a` меняет копию, `b` — исходный `n`.

### Почему получается именно так

При вызове `a(n)` создаётся отдельный параметр `x`, изначально равный `1`. Он становится `3`, но затем функция завершается и параметр перестаёт существовать. Исходный `n` всё это время равен `1`. В `b(n)` параметр является ссылкой на `n`, поэтому `x += 3` меняет сам исходный объект. После второго вызова `n` равен `4`, и именно его печатает программа.

## Задача 8. Порядок полей

```cpp
struct S {
    int x = 2;
    int y = x + 3;
    S() : y(100), x(5) {}
};
int main() { S s; std::cout << s.x << ' ' << s.y; }
```

**Ответ:** `5 100`. Поля инициализируются в порядке **объявления**, но явный инициализатор `y(100)` перекрывает default member initializer `y = x+3`.

### Почему получается именно так

Сначала определим порядок полей по тексту класса: `x`, затем `y`. Порядок `y(100), x(5)` в списке конструктора этого не меняет; компилятор может предупредить о вводящей в заблуждение записи. Для `x` есть явный инициализатор `x(5)`, поэтому значение по умолчанию `2` не используется. Для `y` есть явный инициализатор `y(100)`, поэтому выражение `x + 3` тоже не используется. В итоге получается не `5 8`, а `5 100`.

## Задача 9. Деструкторы

```cpp
struct A { ~A(){std::cout << "A";} };
struct B { ~B(){std::cout << "B";} };
int main() { A a; B b; }
```

**Ответ:** `BA`. Локальные объекты уничтожаются в обратном порядке конструирования.

### Почему получается именно так

Оба объекта созданы в одном блоке `main`: сначала `a`, затем `b`. При достижении конца блока разрушение идёт обратно. Деструктор `b` выводит `B`, после него деструктор `a` выводит `A`. В коде не печатаются ни пробелы, ни перевод строки, поэтому результат записывается слитно. Если добавить внутренний блок с третьим объектом, он будет разрушен уже на выходе из своего блока, не дожидаясь конца `main`.

## Задача 10. Копирование и владение

```cpp
struct Bad {
    int* p = new int(5);
    ~Bad() { delete p; }
};
int main() { Bad a; Bad b = a; }
```

**Ответ:** копирование `Bad b=a` по умолчанию копирует адрес; при разрушении обоих объектов возникает **double delete / UB**. Исправление: `std::unique_ptr<int>` с запретом копирования, `std::vector<int>` или глубокое копирование с Rule of Five.

### Почему получается именно так

Для `a` выделяется один динамический `int`, и его адрес сохраняется в поле `p`. При создании `b` не выполняется повторно обычная начальная инициализация поля через `new int(5)`; работает копирующий конструктор, который для указателя копирует его значение. Поэтому оба поля указывают на одну область. Сначала разрушается `b` и освобождает её, затем деструктор `a` пытается освободить уже освобождённое. Это ошибка владения, даже если оба объекта ни разу не меняли число. Правильная реализация должна заранее определить, копируется ли содержимое независимо или копирование владельца запрещено.

## Задача 11. Перегрузка `++`

```cpp
struct C {
    int x{};
    C& operator++() { ++x; return *this; }
    C operator++(int) { C old=*this; ++*this; return old; }
};
int main() { C c{2}; C a=c++; C b=++c; std::cout << a.x << ' ' << b.x << ' ' << c.x; }
```

**Ответ:** `2 4 4`. После `c++`: `a=2`, `c=3`; после `++c`: `c=4`, `b` копирует 4.

### Почему получается именно так

Начальное состояние `c.x` равно `2`. Постфиксный оператор создаёт `old` как копию текущего объекта, поэтому `old.x` равно `2`. Затем `++*this` вызывает префиксную форму и увеличивает `c.x` до `3`. Возвращённый старый объект используется для создания `a`. Во второй строке префиксная форма сразу увеличивает `c.x` до `4` и возвращает ссылку на `c`. Но объявление `C b = ++c` создаёт самостоятельный объект по этому значению, поэтому `b.x` становится `4`.

## Задача 12. Сокрытие имён

```cpp
struct Base {
    void f(int) { std::cout << "I"; }
    void f(double) { std::cout << "D"; }
};
struct Derived : Base {
    void f(int) { std::cout << "X"; }
};
int main() { Derived d; d.f(2.5); }
```

**Ответ:** `X`. Имя `f` в наследнике скрывает обе перегрузки базы; `double` преобразуется в `int`. Добавление `using Base::f;` сделает вывод `D`.

### Почему получается именно так

Сначала выполняется поиск имени `f` в производном типе. Он находит объявление в `Derived`, и базовые функции с тем же именем оказываются скрыты. Поэтому набор кандидатов не содержит `Base::f(double)`, хотя она дала бы точное соответствие аргументу. Оставшийся метод принимает `int`, а значение `2.5` преобразуется в `2`. Печатается `X`. После `using Base::f;` базовая перегрузка с `double` снова участвует и выигрывает у преобразования.

## Задача 13. Срезка

```cpp
struct B { virtual ~B() = default; virtual int f() const { return 1; } };
struct D : B { int f() const override { return 2; } };
int byValue(B b) { return b.f(); }
int byRef(const B& b) { return b.f(); }
int main() { D d; std::cout << byValue(d) << byRef(d); }
```

**Ответ:** `12`. В `byValue` происходит срезка до `B`, в `byRef` динамический тип объекта остаётся `D` и виртуальный вызов выбирает `D::f`.

### Почему получается именно так

Вызов `byValue(d)` создаёт самостоятельный параметр типа `B`. В нём хранится только скопированная базовая часть исходного объекта; его динамический тип — `B`. Поэтому виртуальная функция даёт `1`. Вызов `byRef(d)` не создаёт нового базового объекта: ссылка связывается с базовой частью всё ещё существующего `D`. Динамический тип сохраняется, и виртуальный вызов даёт `2`. Оба результата выводятся без разделителя.

## Задача 14. Ромб

```cpp
struct A { int x=1; };
struct B : A {};
struct C : A {};
struct D : B, C {};
int main() { D d; /* std::cout << d.x; */ }
```

**Ответ:** `d.x` неоднозначно — в `D` две копии `A`. Можно выбрать `d.B::x` или `d.C::x`; для единой общей базы используйте `struct B : virtual A` и `struct C : virtual A`.

### Почему получается именно так

Нужно мысленно нарисовать два пути: `D → B → A` и `D → C → A`. При обычном наследовании это два разных подобъекта `A`, у каждого собственное поле `x`. Даже если оба сейчас хранят одинаковое число `1`, обращение `d.x` не выбирает автоматически один из них. В показанной программе спорная строка закомментирована, поэтому сам фрагмент не обязан выдавать ошибку. Ошибка появляется при попытке выполнить неоднозначное обращение.

## Задача 15. `std::move` и категории

```cpp
void f(const std::string&) { std::cout << "L"; }
void f(std::string&&) { std::cout << "R"; }
int main() {
    std::string s = "abc";
    f(s);
    f(std::move(s));
}
```

**Ответ:** `LR`. Именованное `s` — lvalue; `std::move(s)` — xvalue. Сам вызов `f(std::move(s))` ничего не перемещает: выбранная перегрузка лишь принимает ссылку.

### Почему получается именно так

В первом вызове выражение `s` является lvalue и не подходит для связывания обычного `std::string&&`. Доступная ссылка на константу подходит, поэтому печатается `L`. Во втором вызове `std::move(s)` является xvalue и позволяет выбрать rvalue-ссылку, поэтому печатается `R`. Тело второй перегрузки только выводит символ: в нём нет создания новой строки из параметра и нет операции передачи ресурсов. Следовательно, из самого этого примера нельзя сделать вывод, что содержимое `s` было перемещено.

## Задача 16. `explicit`

```cpp
struct T { explicit T(int) {} };
void f(T) {}
int main() {
    T a{3};
    // T b = 3;
    // f(3);
    f(T{3});
}
```

**Ответ:** `T a{3}` и `f(T{3})` корректны; `T b = 3` и `f(3)` — ошибки из-за запрета неявного преобразования.

### Почему получается именно так

Конструктор типа существует, и создать `T` из числа явно разрешено. Поэтому `T a{3}` корректно. В `T b = 3` требуется форма инициализации, которая не использует этот explicit-конструктор как неявное преобразование из числа. Аналогично, `f(3)` потребовало бы неявно получить параметр типа `T`. В `f(T{3})` мы сначала явно создаём подходящий объект, поэтому ограничение не нарушено.

## Задача 17. `operator<=>`

```cpp
struct P {
    int x, y;
    auto operator<=>(const P&) const = default;
};
int main() { P a{1,9}, b{2,0}; std::cout << (a < b); }
```

**Ответ:** `1`. Сравнение лексикографическое: сначала `x`, а `1 < 2`, поэтому `y` не определяет результат.

### Почему получается именно так

Сгенерированное сравнение идёт по полям в порядке объявления. Сначала сравниваются `a.x == 1` и `b.x == 2`. Уже на этом шаге видно, что первый объект меньше, поэтому значения `9` и `0` во втором поле не перевешивают решение. Это похоже на сравнение слов по первому различающемуся символу. Результат `a < b` — логическое значение `true`, а стандартный вывод без `std::boolalpha` показывает его как `1`.

## Задача 18. Виртуальная база

```cpp
struct A { int x; explicit A(int n) : x(n) {} };
struct B : virtual A { B() : A(1) {} };
struct C : virtual A { C() : A(2) {} };
struct D : B, C { D() : A(7), B(), C() {} };
int main() { D d; std::cout << d.x; }
```

**Ответ:** `7`. В наиболее производном объекте `D` виртуальную базу `A` инициализирует `D`, а не `B` или `C`.

### Почему получается именно так

Слова `virtual A` у обоих промежуточных классов задают один общий подобъект `A` внутри `D`. Поэтому нельзя последовательно выполнить обе конкурирующие инициализации `A(1)` и `A(2)` как создание двух отдельных баз. Когда создаётся `D`, за виртуальную базу отвечает именно его конструктор, и используется `A(7)`. Если создавать отдельный объект `B`, самым производным классом будет уже `B`, и тогда его `A(1)` будет иметь значение.

## Задача 19. Написать класс без ручного new/delete

**Условие:** реализовать класс `Scores`, который хранит оценки, добавляет оценку, возвращает среднее, запрещает оценки вне диапазона 0–100.

```cpp
#include <vector>
#include <stdexcept>
class Scores {
    std::vector<int> values_;
public:
    void add(int x) {
        if (x < 0 || x > 100) throw std::out_of_range("score");
        values_.push_back(x);
    }
    double average() const {
        if (values_.empty()) return 0.0;
        long long sum = 0;
        for (int x : values_) sum += x;
        return static_cast<double>(sum) / values_.size();
    }
};
```

**Разбор:** `private` защищает инвариант; `add` проверяет данные; `average() const` не изменяет объект; `std::vector` автоматически управляет памятью; `static_cast<double>` не даёт целочисленному делению испортить среднее. При чрезвычайно большом числе оценок даже `long long` теоретически может переполниться — для заданных ограничений это нужно учитывать.

### Почему получается именно так

Разделим условие на ответственность. Хранение последовательности и освобождение её памяти делегированы вектору. Проверка диапазона принадлежит `add`: она выполняется до изменения вектора, поэтому недопустимая оценка не попадает внутрь. Получение среднего не должно менять набор оценок, что выражено `const` у метода.

Для пустого набора здесь выбран договор «среднее равно 0.0». Это решение интерфейса, а не математическое доказательство существования среднего пустой последовательности. Можно было выбрать исключение или результат, явно обозначающий отсутствие значения. Важно определить это заранее. При непустом наборе преобразование суммы к `double` выполняется до деления, чтобы не потерять дробную часть.

## Задача 20. Написать класс с каноническими операторами

**Условие:** реализовать двумерный целочисленный вектор с `+=`, `+`, `==`, `<<`.

```cpp
#include <iostream>
struct Vector2 {
    int x{}, y{};
    Vector2& operator+=(const Vector2& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;
    }
    friend Vector2 operator+(Vector2 lhs, const Vector2& rhs) {
        lhs += rhs;
        return lhs;
    }
    bool operator==(const Vector2&) const = default;
    friend std::ostream& operator<<(std::ostream& os, const Vector2& v) {
        return os << '(' << v.x << ',' << v.y << ')';
    }
};
```

**Разбор:** `+=` меняет объект; `+` использует копию `lhs`; `==` C++20 сравнивает поля; потоковый оператор свободный и возвращает `ostream&`. Для `int` арифметика может переполниться — это отдельное ограничение типа.

### Почему получается именно так

Сначала реализуется операция изменения `+=`: она прибавляет координаты и возвращает текущий объект. Затем `+` получает левый операнд по значению, изменяет эту самостоятельную копию через `+=` и возвращает её как новый результат. Так сумма не меняет исходные векторы и не дублирует формулу сложения.

Сгенерированное равенство требует совпадения обоих полей. Вывод получает вектор по константной ссылке и возвращает тот же поток, поэтому его можно включать в цепочки `std::cout << first << second`. Поля в этом `struct` открыты, что соответствует простой группе координат без дополнительного инварианта. Если бы координаты имели обязательные ограничения, понадобился бы другой интерфейс изменения.
